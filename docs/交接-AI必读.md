## 1. 产品是什么（一句话）

**把变好的声音直接送进微信和游戏的本地实时变声器。** 不上云、全程本机。

和「本地语音工作站」的区别：它们交付一个音频文件，这个项目**交付一句已经发出去的话**。

三条主路径：

1. **开麦说话**（实时变声）：麦克风 → RVC → 虚拟声卡 → 微信/游戏/Discord 的"麦克风"。
2. **打字让它说**（TTS）：文字 → 用你选的音色合成 → 一键发进微信（含歌声垫底）。
3. **训练变声**（自建音色）：一段素材 → 自动切片质检 → 挑干净片段 → 训练成你的音色。

三端共用同一个本地后端：**桌面端**（Electron，主力）· **手机浏览器遥控页**（零安装，推荐）· **移动端 Expo**（半弃用，见 §6.4）。

### 2.1 后端怎么长出来的（两条规矩，别绕开）

- **能力 = 插件 = 一个 `plugin.json`**。`server.py` 的 `_mount_all()` 只做一件事：读清单 → `mount_plan()` → `load_router()`。**没有 `plugin.json` 的能力等于不存在**（前端不会显示、路由不会挂）。
- **关掉的能力是真不 import** —— 不只是前端不显示。目的是"不拉 torch/CUDA 上下文、不吃显存"。所以**不要在模块顶层 import 重依赖**，否则关掉也照样吃资源。
- ⚠️ 新增一个 `APIRouter` 会同时踩**两条文档新鲜度断言**：README 的 router 计数 + 目录树清单（`test_docs_freshness.py`）。改完直接 grep README 这两处。

### 2.2 前端路由怎么来的（最容易搞错）

- `pages/` 下有 **23 个目录，但只有一部分是路由**。`App.tsx:153` 的 `routePlan` 是**读插件清单算出来的**，不是手写 `<Route>`。
- ⇒ **加页面 ≠ 改 `App.tsx`**。正确顺序：`plugin.json` 的 `routes` 字段 → `pages/<名字>/index.tsx` → 清单校验测试。
- 关掉插件，它的页面自动消失 —— 这是设计，不是 bug。

## 3. 怎么跑 / 怎么验

```bash
# 后端（用项目根的 .venv，Python 3.11）
"D:/变声/.venv/Scripts/python.exe" m2_server/server.py

# 前端开发
cd web && npm run dev          # vite
cd web && npm run electron:dev # 桌面壳（vite + electron 并行）

# 只让前端在【安装版】里生效（一条命令，不碰主进程）
cd web && npm run ship         # 构建 → 同步进安装目录 → 逐字节自检

# 门禁（提交前，钩子会自动跑）
"D:/变声/.venv/Scripts/python.exe" tools/check.py --fast

# 复刻 CI 干净环境（推之前才需要，约 9.5 分钟）
"D:/变声/.venv/Scripts/python.exe" tools/check.py --ci-fidelity
```

**门禁 11 个步骤**（`tools/check.py` 的 `STEPS`）：`licenses` `gate` `ownership` `requires` `electron` `ps1lint` `petlayout` `nodetest` `ruff` `pytest` `web`。

`--fast` 只跑 8 项 —— **跳过 `ps1lint` / `nodetest` / `web`（前端）**，且 `pytest` 用的是 `FAST_TESTS` 子集。
⇒ **`--fast` 绿 ≠ 前端绿 ≠ 全量绿**，见 §6.3。`--fast` 实测约 5 分钟（pytest 占 ~294s）。

**跑测试的纪律**（血泪换来的）：

- **一次只跑一个全量**。并发跑两份会抢内存 → 进程被 OOM 打死 → 表现为「FAIL + 耗时远短于基线」，不是用例失败。
- 全量基线看**耗时**：显著短于基线 ⇒ 先怀疑进程被杀，别怀疑代码。
- 精确计数用 `--junitxml`（覆盖率表会吃掉汇总行，且它是**唯一留下失败 traceback 的地方**）。

### 5.3 判定方法本身的坑（**这个比技术坑更贵**）

- ⛔ **`grep` 零命中 ≠ 功能没做**。2026-10-14 用 `grep persona` 判定"人格包没做"（碰巧对了），但同一份表里 **AudioSeal 和"多语言"都判错了** —— 能力落在完全不同的模块名下。
  **正确核实顺序**：`plugin.json` 的 `routers` → 路由文件 → 权重/依赖是否落盘。三步都查完才敢说"没做"。
- ⛔ **`tail` 的沉默不算证据**。2026-10-04 我 `tail -60` 没看到某请求就断言"根本没发出去"，实际 12 条全 200（在前面 185~607 行）。**说"某请求从未发生"之前必须全量 grep**。
- ⛔ **「报告说做完了」≠「做完了」**。核对 `git show --name-only <sha>`；指标声称要能用一条命令复现。
- ⛔ **「单文件绿、多文件红」第一嫌疑是异步写入活过了 teardown**（daemon 线程 / `sleep(20)` 后重写 / 训练线程）。
- ⛔ **「本机绿 ≠ CI 绿」**。三根轴：依赖未声明（Pillow/comtypes 曾从未声明）、平台差异、编码。推前跑 `--ci-fidelity`。

## 7. 红线（改之前必须知道）

### 7.1 三条铁律（`AGENTS.md` 原文，违反即事故）

1. **改动即提交**：一次逻辑改动 = 一个 conventional commit。
2. **改动即补测**：交付前测试全过。
3. **踩坑必记**：可复现、会再犯的坑写进 `docs/` 三份之一（症状/根因/对策/证据，标 ✅本机实测 / 📚社区声称 / ❓未验证）。

### 7.2 桌面端两种形态，生效路径完全不同（最常误判）

| 形态 | 改 `m2_server/*.py` | 改 `web/electron/*.cjs` | 改 `pet.html` |
|---|---|---|---|
| **源码模式**（`npm run electron`） | 重启即生效 | 重启即生效 | 重启即生效 |
| **安装版**（`变声工坊.exe`） | ❌ **重启不生效**，要 `sync_backend.ps1 -TargetRoot $dst` | ❌ **必须重打 asar**（或定向重打 ~1 分钟） | ⚠️ 手动拷一份即热替 + **asar 里那份也要更** |

- 改前端只想在安装版生效：`cd web && npm run ship` → **完全退出应用**（不是关窗口，桌宠常驻）再打开。
- **别用 `md5sum` 手工比对**：Git Bash 对含反斜杠的 Windows 路径会加 `\` 前缀，一侧相对一侧绝对时**全假红**、两侧绝对时**全假绿**（更危险）。用 `cmp -s` 或 `tools/verify_backend_sync.py`。
- 判断某份构建含不含某改动：**直接 grep 指纹**（asar 内是原文），别猜。

### 7.3 沙箱限制（WorkBuddy 环境）

- 禁：`wsl` / `docker` / `reg` / `sc` / COM / `Add-Type`；**Electron GUI 起不来**（只桩冒烟）。
- 可：微信 Qt 的 UIA（能读）；长命令用 `run_in_background=true`；调本机端口加 `--noproxy '*'`。
- 释放空间只用 `tools/hard_delete.py`；**批量删除 / pytest / vite build / `release.ps1` 前必加 `CODEBUDDY_SAFE_DELETE_ENABLED=0`**（否则 rmtree 被 bulk guard 拦 → 只剩 0 字节空壳）。
- 「绝不在沙箱装 Py 包」是**曾经的**纪律；本机 `.venv` 装过 RapidOCR（15MB，可选兜底）。装之前先问。

### 7.4 五个最容易踩的具体坑

1. **全局热键别用裸 `Alt+X`** —— 菜单栏会抢（`autoHideMenuBar` 只是隐藏不是不存在），微信"按住说话"也占 Alt。一律 `Ctrl+Alt+X`。
2. **推理期间别让空闲计时器杀掉 llama-server** —— 已修（`24a13bb`），但改动 `reply_advisor` 生命周期时要想起来。
3. **改配置对象前先确认消费方是"每次读"还是"导入时读了一次"** —— 模块级常量是早绑定，改配置源对它**无效且不报错**。
4. **`test_docs_freshness` 会红两次** —— 新 router 要同步 README 的计数 + 目录树。
5. **判断「视觉能不能做」先分清两种任务** —— 读数（每个元素是什么）用专用小模型/几何裁切，快且准；理解（整屏讲什么）用视觉大模型。**拿大模型做逐元素读数，慢 200 倍还带幻觉。**

## 9. 这份文档怎么维护

**什么时候改它**（只有这三种情况）：

1. **勾掉一项** —— §6 的某条做完了，移到 §4 并打勾（带 commit 或落点）。
2. **加一条"此路不通"** —— §5 新增一行，必须带**证据 + 日期**。没有证据的"我觉得不行"不要写进来。
3. **数字过期** —— 改完先跑一遍命令再改，别凭记忆。

**不要把它写成**：设计文档（去 `docs/` 专题）、变更日志（`git log` 就是）、待办池（§6 只放"有明确下一步"的）。

**写法要求**：

- 每条**必须能落到一个文件、一个路由或一个命令**。写不出落点的，说明它还没做完，或者你还不够了解它。
- 数字**必须带实测日期**。跨天引用旧结论前先复算 —— 本项目已经因为"沿用三天前的结论"错过一次（`pitch=-12` 被当成模型能力上限）。
- 状态只用四种：✅ 完成 / ⚠️ 部分 / ❌ 未做 / ⏸ 停用。**不要用"基本完成""差不多"**。
