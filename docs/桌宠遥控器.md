# 桌宠 = 常驻遥控器（2026-09-29）

> 需求原话：「把桌宠从装饰改成常驻遥控器：显示变声开关、当前音色和延迟，并支持按住说话变声发送」。
> 本文记的是**为什么这样落地**（含被否掉的方案），以及改完之后**怎么让它生效**。

---

## 一、落地形态（一句话）

桌宠面板的**头部那一行**从「品牌标 + 标题 + 状态药丸」换成**状态条**：变声开关（药丸，可点）+
当前音色 + 实测推理耗时；功能页从 2 个变 3 个，新增**「按住说话」**页（一颗 46px 的按住按钮）。

```
┌──────────────────────────────────────┐
│ ● RVC 变声中   袋鼠骑士   82ms       │  ← 状态条（原 #phead 那一行，零新增高度）
├──────────────────────────────────────┤
│ [ 说话 ] [ 按住说话 ] [ 音效 ]        │  ← #tabRow（本来就存在，多一页不占像素）
├──────────────────────────────────────┤
│  （当前页：说话页 / 按住页 / 音效页）  │
├──────────────────────────────────────┤
│ 合成并发送            试听            │  ← 动作行（「按住」页里收起）
├──────────────────────────────────────┤
│ ✓ 已发到微信（3.2s）                  │  ← 状态行（共用）
│ [刚刚·3.2s] [3 分钟前·5.1s]           │  ← 最近发送（共用，气泡在屏时让位）
└──────────────────────────────────────┘
```

## 二、为什么「不新增一行」是硬约束

面板纵向预算是**死的**，而且刚刚好卡满：

| 事实 | 数值 | 证据 |
|---|---|---|
| 面板上限 | `max-height: 300px` | `pet.html` 的 `#panel` |
| ok-dark 自然高 | **289px** | `node tools/pet-panel-preview.cjs --measure --scene ok-dark` |
| 剩余 | **11px** | 289 → 300 |

而 `.compact` 让位规则（气泡在屏时收起 `#tabRow` + `#recent`）**删不得**：
2026-09-29 实测把它删掉后，`offline / live / qwen / think` **四个场景全红**（面板内容溢出被切）。
所以「再加一行状态条」不是选项，只有两条路：**占已有行**，或**让位**。选了前者 —— 头部那一行
的信息价值最低（标题「变声工坊」在这个 220px 的透明窗里是重复信息；品牌标 svg 无任何 JS 引用），
拿它换状态条，**净新增高度 = 0**（这也是这个设计成立的唯一理由）。

宽度预算同样是硬的：184px（204 - 面板左右各 10px padding）。实测最挤的形态（live-dark）：

| 元素 | 宽 | 说明 |
|---|---|---|
| 药丸「RVC 变声中」 | 77.4 | 引擎名**不能删**（2026-09-26 专门修过的用户诉求，`test-pet-renderer-script` 守着） |
| 音色「袋鼠骑士」 | 52 | 唯一允许被压缩的一个（`flex: 0 1 auto`） |
| 耗时「82ms」 | 35.6 | `flex: 0 0 auto`，因为它可能是 3 位数（100ms+） |
| 间距 | 2×4 | `#phead { gap: 4px }` |
| **合计** | **~173 / 184** | 剩 11px 是**留给延迟位数**的：不预留，机器一慢音色名就先变省略号 |

为了腾宽度，这一行里去掉了两个装饰件：品牌标 `#plogo`（aria-hidden 的 svg，无引用）与标题
`#ptitle`。**引擎名、音色、耗时三者都不让** —— 它们要么是用户诉求，要么是本次要显示的数据。

## 三、状态条上的三个数各自来自哪（别串源）

| chip | 数据源 | 口径 / 坑 |
|---|---|---|
| 药丸 `#pill` | `tick()` 的 `runningEngine`（`/api/rvc/live/status` + `/api/cascade/status`） | 由**实际在跑谁**推导，不是「用户选了谁」（§3.27 的既有铁律）。文案限 3 个汉字内，引擎名放 tooltip |
| 音色 `#rmVoice` | `voiceSel`（面板下拉），下拉是「主界面选中」时用 **`/api/voices` 的 `selected`** 反查真名 | `selected` 是本次新加的字段；没有它只能显示一句没用的「主界面选中」 |
| 耗时 `#rmLat` | **`/api/rvc/live/status` 的 `infer_ms`**（后端 tail `logs/<exp>/realtime_gui.log` 的「推理耗时」） | ⚠️ 是**单块推理耗时**，不是端到端延迟；只在 `live_running` 时显示 |

**耗时为什么读日志而不是新起一个测量进程**：RVC 实时链路本来就在打这个数（本机
`realtime_gui.log` 4279 行里全是「推理耗时：0.08秒」）。读它零成本、不占音频设备、不必进 RVC venv。
读法与 `_live_stream_ready` 同款：只 seek 尾部 8KB，不扫整个大日志。

**为什么停了就不显示**：日志里那 80ms 会一直在。照直报出来，用户会以为变声还在跑 ——
这是「读日志」这条路最容易掉进去的坑，所以口径是**只在 `live_running` 时报**。

## 四、按住说话：链路与状态机

### 链路（不需要开实时变声、不碰虚拟声卡）

```
按住 → pointerdown → IPC pet:mic-down(音色id) → 主进程 POST /api/capture/mic/start
     后端 mic_capture 抓**真实麦克风**（不是默认录音设备！）
松手 → pointerup   → IPC pet:mic-up          → 主进程 POST /api/capture/mic/stop
     后端 stop 顺手 rvc_convert 换声 → 主进程复用既有 sendWechatWav 发进微信
```

- **为什么抓「真实麦克风」而不是默认录音设备**：实时变声开着时默认录音设备已被切到
  `CABLE Output`，按默认去录会录到**已经变好的声音**，再换一次声就是双重变声。
- **为什么不切虚拟声卡**：切声卡的物理代价 3~6 秒，按住几秒说话根本来不及。
- **为什么不用「按住微信的录音键」**：微信那边是「**单击**开始持续录音 → 点 ↑ 绿钮结束发送」
  （`wechat_voice.py` 记着 2026-09-10 的真机实测：保持按住不松反而起不了浮层），
  软件模拟的 Alt 也不触发它。这个手势在微信侧**不成立**，桌宠按钮是它唯一能落地的地方。

### 状态机在主进程，渲染侧只镜像（`pet-actions.cjs` / `pet.html`）

松手有三种意外，都必须有归属 —— 这就是状态机不能在渲染进程的原因（面板在鼠标移开 500ms 后
就会自己收，渲染进程持不住「已经按下了」这件事）：

| 意外 | 处理 |
|---|---|
| 松手**早于** start 的响应 | `micHold.wantStop` 记意愿，start 回来立刻收尾（不丢这句话） |
| 手指/鼠标**滑出按钮** | `setPointerCapture` + `pointercancel/lostpointercapture` 也算松手 |
| **按住不放** | 主进程 59s 上限自动收尾（与后端 `mic_capture.MAX_HOLD_SECONDS` 对齐） |

另外两条集成级不变量（都有用例守着）：

- **按住期间不把窗口设成鼠标穿透**：光标一滑出面板，`overInteractive()` 返回 false →
  `setIgnoreMouse(true)` → 整个透明窗变点击穿透，`pointerup` 可能就送不到页面了，录音只能等 59s 上限。
- **按住期间面板不自动收起**：面板一 `display:none`，按钮、指针捕获、秒数全没，而录音还在继续。

### 失败要出声

装的是**旧版主进程**时，preload 里根本没有 `micDown`（改 `*.cjs` 必须重打 asar，而 `pet.html`
是热替换的）—— 这种情况会在状态行明说「需要新版桌面端：主进程还是旧的」，而不是静静失败
（静默失败时用户会以为是自己没按住，而这他解决不了）。

### 发送前预检：把「微信没开」提前到按下之前（2026-09-29）

这条链路的顺序是「录 0..59 秒 → 换声十几秒 → 才轮到发送」，而「微信没开」是**按下之前**
就能知道的事。等松手后才知道，代价是白白对着麦克风说完一句、再等十几秒换声。
所以按住页最上面加了一行状态（`#holdPre`），进页、每 5s（仅当停在页上）、
刚发完一次这三种时机去拉 `GET /api/wechat/precheck`（**只读**，不动声卡、不碰微信）。

四种结论说四句不同的话（全部来自后端一个字段，前端不自己推）：

| 后端字段 | 行上说什么 | 色调 |
|---|---|---|
| `block_reason` 非空 | `⚠ ` + 分因首句（微信没在运行 / 收托盘 / 停在登录页是三件事）——**这次注定失败** | bad |
| `wechat_running: false` 且没硬失败 | 「微信没在运行 · 这次会先拉起它（要等十几秒）」（auto/1 模式会自己拉起，不是失败） | warn |
| `restart_needed: true` | 「这次会重启微信 · 约十几秒」，原因进 tooltip | warn |
| 都正常 | 「微信已打开 · 直接切麦克风」 | ok |

三个别踩的点：

1. **判据不在前端算**。`block_reason` 是后端 `_send_preflight()`（send_text 那条分因预检）
   的原文转述。自己拿 `wechat_running` 推的话会漏掉“进程在、但窗口收在托盘/停在登录页”
   —— 那三种情况进程都是活的，而发送全都必败。
2. **只告警、不拦人**。不给按钮加 `disabled`：预检数据可能过期（用户刚把微信打开），
   拿旧数据拦人会把「我刚开了微信」变成「按不了了」，比不告警更糟。
3. **先探测再用**。后端没起、预检 404（后端比桌宠旧）、响应缺字段（前后端版本不一致）
   各自有各自的文案 —— 尤其**缺字段时绝不能猜成「微信没开」**，那会把用户指去查微信。
4. **行上显示的是「分因首句」**（到第一个 `（`/`：` 为止），所以后端的报错文案
   **首句必须是问题本身**。这条有真实代价：托盘那条原本是「微信在运行（pid: 22）但没有任何
   可见窗口——多半被关进了托盘」，截出来就成了一句红色警报「⚠ 微信在运行」= 「一切正常」。
   已改写为先说问题（「微信没有任何可见窗口（pid: …）——它还在运行、多半被关进了托盘」），
   并在 `test_wechat_restart.py::test_find_wechat_hwnd_tray_only_says_open_chat_window` 里
   钉住 `msg.startswith(...)`。**改这几句报错文案时先想一眼它在 204px 的一行里长什么样。**

它同时在两个地方报：按住页的那行状态，以及 `GET /api/wechat/precheck` —— 手机上那份
遥控页早就在用同一个端点（见 `docs/手机遥控页.md`）。

## 九、纵向预算门禁（2026-09-29 新增：会自动报警）

上面第 32 行那句「面板纵向预算是**死的**」以前只是**文档里的建议** —— 靠人每次动手前想起来
去跑 `--measure`。现在是**门禁**：新控件把底部挤掉，提交那一刻就被拦下，并指名是谁吃掉的。

### 怎么跑

```bash
# 提交前那一刻会跑的（pre-commit 的 petlayout 步，~1.2s）
node tools/test-pet-panel-layout.cjs --fast

# 只要静态部分（不需要浏览器，CI 无 playwright 时也能跑）
node tools/test-pet-panel-layout.cjs --static

# 13 个命名场景全量（含「文字没被裁」的量测）
VM_PET_LAYOUT_ALL=1 node tools/test-pet-panel-layout.cjs

# ★ 重算基线（会先打印一份「这次吃了多少」的成本表）
VM_PET_BUDGET_UPDATE=1 node tools/test-pet-panel-layout.cjs
```

被拦下时输出长这样（`VM_PET_HTML` 指向临时变体做的变异测试，见下）：

```
FAIL sweep:hold:bubble0：余量 77px → 69px
     吃掉余量的： pane/newWidget（+8px）、holdPane 79→87px（+8）
```

### 它拦什么、不拦什么

- **拦**：任何让某个（功能页 × 气泡态）的**余量变小**的改动 —— 哪怕今天还没溢出。
  以及「新功能页/新控件没有登记预算」和「基线里的控件已经从 pet.html 里消失」。
- **不拦**：余量**变多**（那是好事）、`+0px` 的变化、1px 以内的亚像素取整。
- **允许存在但会警告**：基线里已记着的**负数余量**（现在是 `speak:bubble1 -18`、`fx:bubble1 -5` ——
  气泡在屏 + 状态行两行时说话页/音效页被切）。它们是既有产品取舍，门禁不许它们**变差**，
  但也不假装不存在；要不要牺牲哪一行是产品决定，不是门禁该替人做的。

### 余量的定义（这里最容易写错）

**不是** `clientHeight - scrollHeight` —— 面板是 `height:auto + max-height:300px`，内容不超时
两者**恒等**，所以那个值永远是 0，只在被切时才是负数（它是「切了多少」）。

```
余量 = capacity - need
  need     = panel.scrollHeight                       # 内容需要多高
  capacity = 实测：临时把 style.height 顶到 1000px，读 clientHeight 后立刻恢复
```

`capacity` 为什么**实测**而不算公式：公式等于把 flex 的实际行为抄一份，改一处 CSS 就静默漂。
不变量是「**余量只能变多，不能变少**」。判据还带**自检**（拿 4 组假量测证明三种情况都判红、
两种不判红）—— 判据没有自检时，写错一个 `<` 就是永久静默放行，本仓吃过这个亏（§8.59）。

### 覆盖面靠 DOM 枚举，不靠手写清单

预算扫描在**一次页面加载**里遍历所有功能页页签（从 `#tabRow button[data-tab]` 读，不写死）×
{无气泡, 大头气泡 82px}。控件清单同理自动枚举（`#panel` 内所有 `button/input` + 状态条三个 chip）。
于是**加第四页就自动被扫到**，不需要谁记得去加场景 —— 而手写清单必漏：本轮之前

### 基线文件

`tools/pet-panel-layout-budget.json`（18 个 key：6 个扫描项 + 12 个命名场景状态）**跟着代码提交** ——
它就是「预算」的凭据。改了面板**而且确认这次增长非加不可**，才用 `VM_PET_BUDGET_UPDATE=1` 重算；
重算前先看它打印的成本表，别把「拦不住」当成「不用看」。

当前余量（px，越小越紧）：

```
离屏/窄场景最紧：  fxpick 2   offline 2   ok 9   speak:bubble0 9
中间：            fx:bubble0 24  guide 26  hold:bubble1 47
「按住说话」页：     hold:bubble0 77  holdrec 93
已知溢出：         fx:bubble1 -5   speak:bubble1 -18
```

最紧的**健康**状态只剩 **2px** —— 所以今后新增量基本都会被拦住，这正是这次改造的目的。

### 变异测试（门禁真正被验收的地方）

用 `VM_PET_HTML` 指向临时变体，**不动仓库文件**：

| 变异 | 结果 |
|---|---|
| `#holdPane` 加一个 **8px** 的 div（还没溢出，只吃余量） | ❌ 拦住：`sweep:hold:bubble0：余量 77px → 69px` + 指名 `pane/newWidget（+8px）` |
| 同一位置换成 **40px**（真把底部挤掉） | ❌ 拦住：同样指名 `pane/bigWidget（+40px）` |
| 页签名 `fx` 改成 `newwidget`（假装加第四个功能页）**且不加浏览器** | ❌ 拦住（`--static`）：`这些页/状态没有预算基线： sweep:newwidget:bubble0、sweep:newwidget:bubble1` |

连续两次扫描的场量/块高/余量**逐字相同**，基线的比对不会自己抖。

### 代价与边界

- 成本：静态部分 ~0ms；一次 headless Chromium 扫描 **0.9s**（全量 13 场景 4.5s）。
  找不到 chromium 时**不静默跳过**：量测部分会被明确标成 `[skip]` + 「别把这条 skip 当通过」，
  而静态部分（含「新页必须有基线」）照跑。
- 它**量的是高度，不是观感** —— 「按住多久算够」「换声十几秒里文案够不够清楚」这类
  只能靠真按出来的判断，仍走 `docs/桌宠-按住说话-真机验收.md`。
