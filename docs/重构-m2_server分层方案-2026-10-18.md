# m2_server 分层重构方案（2026-10-18 · 待执行）

> 结论先说：**不能直接 `git mv`**。这个包现在靠「脚本目录进 sys.path + 扁平导入」活着，
> 搬文件会同时打断 4 条链（见 §二）。正确顺序是**先做路径锚点与兼容层，再按批搬，最后收口**。
> 本文只写方案，未动任何代码。

## 一、现状数字（2026-10-18 实测）

| 指标 | 数值 |
|---|---|
| `m2_server/` 顶层 `.py` | **100 个**（`wc -l` 合计 40,845 行） |
| 其中 `APIRouter` 模块 | **39 个**（`*_api.py` 只有 25 个，剩下 14 个路由藏在业务名里：`rvc_live`、`wechat_voice`、`cascade`、`effects`、`audition_api`…） |

## 二、四条硬约束（不解决就不要动文件）

### 1. 扁平导入靠 sys.path，不靠包

```python
# m2_server/server.py 第 37 行起
import config as cfg
import plugin_loader
```

`python m2_server/server.py` 会把 `m2_server/` 放进 `sys.path[0]`，所有模块因此能用
**裸名字**互相引用：`import config`（43 处）、`runtime`（30 处）、`session_out`（19 处）、
`common`（19 处）。测试侧同理 —— `m2_server/tests/conftest.py:22` 手动
`sys.path.insert(0, .../m2_server)`。

**搬到 `routers/wechat_voice.py` 后 `import config` 仍然能解析**（因为 m2_server 还在 sys.path），
所以"搬"本身不炸；炸的是下面三条。

### 2. `plugin_loader` 用 `importlib.import_module(模块名)` 动态加载

```python
# m2_server/plugin_loader.py:83
mod = importlib.import_module(module_name)
```

`module_name` 来自 `plugin.json` 的 `"routers": ["audio_api"]` 与
`"hooks": [{"module": "market_images", ...}]`。**28 个 plugin.json、27 个路由名 + 若干 hook 名**
都得跟着改；漏一个就是启动时那行「路由模块 N/M 个已加载」里悄悄少一条。

### 3. 31 个模块用 `Path(__file__).parent` 定位兄弟文件

```
ab_chain.py:36        INFER_PY = Path(__file__).parent / "offline_vc_infer.py"
audition_api.py:62    SCORE_PY = Path(__file__).parent / "audition_score.py"
config.py:10          ROOT = Path(__file__).parent.parent        ← 项目根
cascade_stream.py:522 sys.path.insert(0, str(Path(__file__).parent))  ← 自立门户
```

搬进子目录后 `parent` 全错一层。其中 `config.ROOT` 是**全仓最关键的锚点**，必须先固定成
"向上找到项目根"，而不是数 `parent` 的层数。

### 4. README 与门禁按文件名钉住模块

`m2_server/tests/test_docs_freshness.py` 有两条互补断言：

- `_README_NAMED_MODULES`（36 个 `xxx.py`）必须**都在** `m2_server/` 下；
- 反向：从 `plugin_manifest` 取出的每个 router 模块名，**必须在 README 里出现过**。

搬家不同步这两处，测试直接红。

## 四、迁移机制：一个兼容层，别做 100 个 shim

新建 `m2_server/core/__init__.py` 时不写逻辑；过渡期只在 `m2_server/__init__.py`（或
`_compat.py`，由 server.py 与 conftest.py 双双 import）里做**别名注册**：

```python
# m2_server/_compat.py —— 只在过渡期存在
import sys
from m2_server.core import config, runtime, session_out, common
from m2_server.routers import wechat_voice, rvc_live
# …按批次补全…

_ALIASES = {
    "config": config, "runtime": runtime, "session_out": session_out,
    "common": common, "wechat_voice": wechat_voice, "rvc_live": rvc_live,
    # …
}
for _old, _mod in _ALIASES.items():
    sys.modules.setdefault(_old, _mod)   # setdefault：真模块优先
```

效果：

- 旧代码 `import config as cfg` 拿到的是同一个 module 对象（**不是副本**，状态共享）；
- `importlib.import_module("audio_api")` 照样命中，`plugin.json` 可以**暂不改**；
- 141 个测试文件**一个都不用改**就能跑。

代价：别名表要跟着批次补。**这是有意的**——用一张显式表换"每批都能跑测试"。

## 五、五阶段执行（每阶段独立可提交、可回滚）

### 阶段 0 · 先固定路径锚点（不改结构）

1. `config.py` 的 `ROOT` 改成"向上找含 `.git` 的目录"，不再 `parent.parent`；
2. 新增 `cfg.PKG_ROOT`（= `m2_server` 目录）；
3. 把 31 处 `Path(__file__).parent` 里**指向兄弟模块**的（`ab_chain`、`audition_api`、`cascade` 等）
   统一改成 `cfg.PKG_ROOT / "xxx.py"`，指向项目根的统一走 `cfg.ROOT`。

**验收**：`python tools/check.py --fast` 全绿 + `python m2_server/server.py` 起得来。

> 这一步单独做、单独提交。它是后面所有搬迁的前置条件，也是最容易被跳过的一步。

### 阶段 1 · 骨架 + 兼容层（仍然零移动）

建 `core/ routers/ services/{voice,audio,wechat,media,market,sfx,ai,ft}/ engines/` 的
`__init__.py`、`_compat.py`，并在 `server.py` / `tests/conftest.py` 顶部 import 它。

**验收**：测试数不变（`pytest --collect-only | tail -1` 与改造前比对）、server 启动日志
「路由模块 N/M 个已加载」的 N 与改造前一致。

### 阶段 2 · 按"叶子优先"搬（4 批）

| 批 | 内容 | 为什么这个顺序 |
|---|---|---|
| B1 | `conftest.py` 之外的**纯工具叶子**：`core/` 11 个 + `engines/` 4 个 | 别人只 import 它们，它们不 import 路由；搬完是最小闭环 |
| B2 | `services/` 全部 43 个 | 只被 router 调用；此时 routers 还在原地，不受影响 |
| B3 | `routers/` 39 个 | 最后搬，因为 `plugin.json` 与 README 门禁都盯着它们 |
| B4 | `test_wechat_voice.py` 挪进 `tests/`；`conftest.py` 留原地 | 收拾收集口径 |

每批收尾动作固定三步：

```bash
# ① 补 _compat 别名
# ② 跑全量
python tools/check.py --fast
# ③ 起服务冒烟（路由数必须与上一批一致）
python m2_server/server.py    # 看 "路由模块 N/M 个已加载"
```

### 阶段 3 · 改 source 的 import（可选，但推荐）

`import config as cfg` → `from m2_server.core import config as cfg`。
按目录批量做（ruff 的 `--select I` 不够，它不改裸名），用脚本 + 人工 spot check。
每改一个目录跑一次测试。**这一步做完 `_compat` 里对应的别名就可以删一条。**

### 阶段 4 · 收口

1. 删 `_compat.py`；
2. `tests/conftest.py` 去掉 `sys.path.insert`；
3. 启动方式统一为 `python -m m2_server.server`（`web/electron/backend.cjs` 与
   `m2_server/server.py` 的注释、`docs/分发与打包说明.md`、安装版的启动参数都要同步）；
4. `plugin.json` 的 `routers` / `hooks.module` 改成新模块路径；
5. `test_docs_freshness._README_NAMED_MODULES` 与 README 目录结构同步；
6. 更新 `AGENTS.md` 里涉及 `m2_server/*.py` 的路径（`wechat_*.py` 那段）。

> **第 3、4 步不能省**：`python m2_server/server.py` 与 `python -m m2_server.server`
> 在同一份代码上只能有一个是正确入口，两套并存就会重演"客户端跑的是旧路径"那类事故。

## 六、会红的门禁（7 处同步点，漏一个就是假绿）

| 位置 | 为什么红 |
|---|---|
| `m2_server/tests/test_docs_freshness.py` | `_README_NAMED_MODULES` 36 个文件名 + 反向 router 清单 |
| `README.md` 「目录结构」段 | 反向检查从 `plugin_manifest` 取 router 名来比对 |
| `m2_server/plugins/*/plugin.json`（28 份） | `routers` 与 `hooks.module` 是模块名 |
| `m2_server/plugin_loader.py` 的注册表 | 同上是字符串模块名 |
| `m2_server/tests/conftest.py` | `sys.path.insert(0, m2_server)` 在收口阶段要删 |
| `pyproject.toml` 的 `--cov=m2_server` | 包路径改了，覆盖率范围会静默变 |
| `docs/分发与打包说明.md` / `tools/sync_backend.ps1` | 同步的是整个 `m2_server/`，但要确认子目录一并镜像 |

## 七、明确不做（避免一次动太多）

1. **不顺手拆 god module**。`wechat_voice.py` 3078 行、`rvc_live.py` 1611 行的内部拆分
   是独立任务，跟"搬家"混在一起会让 diff 无法审。
2. **不改业务命名**（`m1_workshop` / `m2_server` 这些历史命名保留）。
3. **不动 `m2_server/tests/` 的内部组织**（141 个平铺测试单独议题）。

## 八、风险与回滚

| 风险 | 对策 |
|---|---|
| `__file__` 锚点漏改 → 运行时才炸（测试覆盖不到） | 阶段 0 先统一锚点；每批后手动跑 `python m2_server/server.py` 并点一遍首页/桌宠 |
| 兼容层漏一条 → 某路由静默不加载 | 每批比对启动日志的路由数 N；`test_docs_freshness` 的反向检查会兜底 |
| 打包/安装版仍按旧路径 | 阶段 4 强制只留 `python -m`；`tools/sync_backend.ps1` + `verify_backend_sync.py` 复核 |
| 搬迁期间有并行会话在改 `m2_server` | 每批开始前 `git status` 确认干净；单批只动一批文件，冲突面最小 |

回滚：每批一个 commit，`git revert <sha>` 即可整批回退（兼容层让它天然可回滚）。
