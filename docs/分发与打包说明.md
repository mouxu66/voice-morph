# 变声工坊 · 分发与打包说明

本机开发、打包、分发三件事的流程与坑位记录，别每次重新踩。

## 一、目录角色

| 路径 | 角色 |
|------|------|
| `web/electron/` | Electron 主进程 + 桌宠源码（`main.cjs` / `pet/` / `preload.cjs`）→ 编译进 `app.asar` |
| `web/src/` | React 前端源码 → 构建产物 `web/dist/` |
| `m2_server/` | Python 后端源码 |
| `tools/` | 环境体检 `doctor.py`、后端同步 `sync_backend.ps1` 等 |
| `tts_models/` | Qwen3-TTS 权重（4.9G，**不进包**） |
| `voice-morph-desktop/` | electron-builder 产物（可重建，已 gitignore） |
| `.asar_tmp/` | **旧** asar 解包工作区（含 2026-09-03 重构前的单体主进程，已废弃、已 gitignore；不要拿它重打包） |

## 二、改完代码怎么进包

**改了 Electron / 桌宠（`web/electron/` 下）**

现役 `app.asar` 由 electron-builder 从 `web/` 构建，**已经没有"解包 → 替换 → 重打"这条流程了**：
`repack_asar.cjs` / `extract_asar.cjs` / `probe_asar.cjs` / `verify_asar_repack.cjs` 已于 2026-09-13 删除
（它们内部硬编码 `D:/变声/...`，且会拿 `.asar_tmp/` 里 46KB 的旧单体主进程覆盖现役装配层，见 AGENTS.md）。

```bash
cd web && npm run electron:build    # = tsc -b && vite build && electron-builder --win
```

**本机开发时根本不用重新打包**：`resolveProjectRoot()` 会优先命中 `D:\变声\web\electron`
（回退 asar），直接 `cd web && npm run electron:dev` 就是最新源码。

**改了后端（`m2_server/` 或 `tools/`）**

```powershell
.\tools\sync_backend.ps1   # 仅"分发到别的机器"时需要；本机开发时后端启动会自动镜像（backend_autosync.py）
```

**改了 React 前端（`web/src/`）**

```bash
cd web && npx vite build --outDir dist_new --emptyOutDir   # 别用 npm run build
mv dist dist_old_bakN && mv dist_new dist
```

> 坑：`vite build` 会先清空 `dist/`，这一步在沙箱里会被安全删除包装（genie-trash）拦下报 403/超时。
> 绕法就是构建到新目录再 `mv` 换名；旧备份 `dist_old_bak*` 需手动删。

## 三、本机 vs 分发机：后端根解析

`main.cjs` 的 `resolveProjectRoot()` 按序找第一个存在 `m2_server/server.py` 的目录：

1. asar 同级（开发态 = 项目根）
2. **`D:\变声`** ← 本机优先：全量新代码 + 4.9G 模型
3. `resources/backend`（extraResources，只有裸代码）
4. app / userData 回退

- **在自己机器上**：命中 2，壳在打包目录、脑在 `D:\变声`，怎么用都是最新代码。
- **拷给别人**：对方没有 `D:\变声`，命中 3 —— 代码有、模型没有，需要对方自备。

Python 解释器同理：`{root}/.venv` → `D:\变声\.venv` → 系统 python。

## 四、分发给别人：接收方三步

1. 在项目目录建环境（Windows）：
   ```powershell
   python -m venv .venv
   .venv\Scripts\python.exe -m pip install -r requirements.txt
   ```
2. 备模型：把 `tts_models/`（Qwen3-TTS 权重）放到项目根；音色库放 `media/voicebank/`。
3. 打开应用。若后端起不来，弹窗点 **「运行环境体检」**，逐项看 ✓/✗ 并按提示修复（缺 VB-CABLE 只影响实时变声，缺 torch/CUDA 是真跑不动）。

后端日志：`shell.showItemInFolder(BACKEND_LOG)`，实际位于 `%APPDATA%/<app>/backend.log`。

## 五、已知坑

- `asar.extractFile` 路径必须用反斜杠（`electron\\pet\\pet.html`），正斜杠报 not found。
- 打包目录 `resources/backend/tts_models/` 是空目录壳，别以为模型已经在里面。
- 退出应用会自动还原系统麦克风（`audio_config.ps1 -action restore`），用 `before-quit` 兜底。

## 六、安装包里到底装了什么（2026-09-19 实测）

拆解 `VoiceMorph-Setup-0.2.3.exe`（101.5MB）：

| 组成 | 未压缩 | 说明 |
|---|---|---|
| `变声工坊.exe` | 178MB | Electron 运行时，**安装包的主体** |
| `locales/` + `icudtl.dat` + chromium dll | ~68MB | Electron 自带 |
| `resources/app.asar` | 6.74MB | 前端 `dist` + 主进程 `electron/` |
| `resources/backend/` | 16MB | 后端源码 + `web_dist` + `tools` |

> **别指望靠"少放源码"瘦身**：把 `resources/backend/` 整个删掉，安装包也只小 10MB 量级。
> 真正几个 GB 的是 `tts_models/`(4.9G)、`models/`(958M)、RVC 整合包 —— 那些本来就不在包里。

### 6.1 三条已修的事故（`m2_server/tests/test_desktop_packaging.py` 守）

**① `dependencies` 整棵树被重复打进 asar（曾占 37.4MB）**

electron-builder 会把 `package.json` 的 `dependencies` **整棵树**拷进 `app.asar`，
而 `files` 里的正向白名单（`dist/**/*`、`electron/**/*`）**管不住它**；
而 vite 早已把前端代码打进 `dist/`。实测 app.asar 5305 个条目里 5236 个是 `node_modules`
（lucide-react 19MB / react-dom 7MB / @fontsource 6.2MB…），而主进程 `web/electron/**/*.cjs`
对第三方包的 require 数是 **0**（只有 `fs`/`path`/`child_process`/`electron`）。

- 对策：`build.files` 里加一条 **`"!node_modules/**/*"`**。
- 实测：app.asar 47.1MB → 6.74MB（5305 → 71 条目）；安装包 101.5MB → 93.4MB。
- ⚠️ **这条排除是一刀切的，改动前先读 `web/package.json` 顶部的 `"//"` 注释**：
  它成立的前提是主进程不 require 任何第三方包。以后主进程真要引包，
  必须把排除改成白名单，否则安装版运行期 `MODULE_NOT_FOUND`。
- ❌ 别改成"把前端库挪进 `devDependencies`"：效果一样，但会让
  `tools/audit_licenses.py` 判定"载荷里的字体已不是声明依赖"——
  `@fontsource/*` 的 woff2 **真的随 `dist/` 发出去**，挪走等于漏掉 OFL 署名义务。

  > 依赖写在哪个分区是 **npm 语义**，什么进发行物是 **打包器的事** —— 两者不该混为一谈。

**② `!**/data/**` 把一份生产文件挡在包外（静默退化）**

`extraResources` 里 m2_server 那条 filter 带 `"!**/data/**"`，而 `m2_server/data/rvc_texts.txt`（4KB）
是**生产文件** —— `config.load_rvc_texts()` 读它当 RVC 训练语料模板。
它有内置 20 句兜底，所以**安装版不会报错**，只是把语料从 100+ 句场景句悄悄退回 20 句通用句。
用户只会觉得"训出来不太像"，永远查不到是打包漏了个文件。

**③ `tools/` 那条 `extraResources` 一条 filter 都没有**

后果：`tools/desktop-control/out/`（87 张调试截图 / 95MB，2026-09-19 入库）、`__pycache__`、
`.pytest_cache`、`.bak-*` 备份全部会进包。已补 filter，口径与
`tools/verify_backend_sync.py` 的 `_IGNORE_RULES` **对齐** —— 那边是唯一权威，改一处要同步另一处。

### 6.2 改打包配置后怎么自测

```bash
cd web && npm run build && npx electron-builder --dir --config electron-builder.nosign.cjs
# 产物在 web/release2/win-unpacked/，然后跑打包门禁（产物存在时会自动逐项对照真实文件）：
.venv/Scripts/python.exe -m pytest m2_server/tests/test_desktop_packaging.py -v --no-cov
```

只想看安装包体积、不想覆盖 `release2/` 里的现役产物时，加 `-c.directories.output=<临时目录>`。

### 6.3 一个会骗人的坑：`tsconfig.tsbuildinfo` 会掩盖类型错误

`npm run build` 是 `tsc -b && vite build`，而 `tsc -b` 是**增量**的。
本地 `web/tsconfig.tsbuildinfo` 一旦是最新的，`tsc -b` 会直接跳过检查 →
**类型错误一直存在着却从不报错**，直到某次改依赖把 program 失效。
2026-09-19 就是这样暴露出一条 `openGuideLink` 的返回类型错误（声明 `Promise<boolean>`，
实返回 `{ok,url}` 对象 → 对象恒为真值 → 调用方的失败提示永远不会触发）。

- 改完依赖跑一次 `npm run build`，**别只看 `vite build` 过没过**；
- 要确认干净结果就 `rm web/tsconfig.tsbuildinfo` 再 build。
