## 1. SVC 的"跨音域"失效机制

### 1.1 核心结论：**训练集音域覆盖 = 模型可控音域的硬边界**

**RVC 作者本人的明确表态**（这是最直接的一手证据）：

> 提问者（#957）："我训练的模型训练集质量高无底噪音频时长 73min … 推理正常说话的内容没问题，推理歌声时正常音域时也没问题，**唯独高音歌声唱不上去** … 由于我的训练集都是正常说话的语调，并没有唱歌时会出现的那种高音，这可能是问题所在吗？"
>
> `ms903x1`（CONTRIBUTOR）回复：**"数据集里没有高音的话，推理高音歌曲就会哑掉。"**
>
> `RVC-Boss`（项目作者 / MEMBER）确认：**"嗯，训练集内需要带高音数据。"**
>
> — [Issue #957 · 推理带有高音歌声的问题](https://github.com/RVC-Project/Retrieval-based-Voice-Conversion-WebUI/issues/957) `[社区]`

**同一 issue 里另一位用户对"变调增强"的实测反馈（关键）**：

> `leospark`（2023-11-25）："@RVC-Boss 但是往往数据集内音高数据有限，尤其是 10min 数据，那该如何解决？**通过做数据增强 pitch_shift 有效吗（我尝试了，音色会变）**"
>
> — 同上 issue `[社区]` —— 注意：**该提问未获作者答复**，属于"社区经验、无官方背书"。

### 1.2 失效的具体表现形态（三种，症状不同）

| 症状 | 触发条件 | 来源 |
|---|---|---|
| **哑音 / 嘶哑 / 破音**（局部，音节级） | 音高超出训练集覆盖 | [#957](https://github.com/RVC-Project/Retrieval-based-Voice-Conversion-WebUI/issues/957)、[#2541](https://github.com/RVC-Project/Retrieval-based-Voice-Conversion-WebUI/issues/2541) `[社区]` |
| **"全哑火"**（整段） | 底模问题，或 F0 预测器上限被顶到 | [#2266](https://github.com/RVC-Project/Retrieval-based-Voice-Conversion-WebUI/issues/2266) `[社区]` |
| **hoarseness（沙哑噪声）随时间扩散** | 源/目标音域跨度过大；**且降回原调后嘶哑仍在** | SPA-SVC 论文 `[论文]` |

**★ 第 3 条是本次调研最有价值的一条**，它精确描述了用户遇到的现象：

> "in cross-domain SVC scenarios, where there is a significant disparity in pitch between the source and target voice domains, the models tend to generate audios with **hoarseness**"
>
> "using SVC models to only increase the pitch of the source vocals without changing the timbre **leads to hoarse audio, with hoarse portions persisting even when the pitch is lowered back to the original**. Additionally, **as the magnitude of pitch shifting increases, the range of hoarse artifacts expands, sometimes rendering the entire audio segment almost indistinguishable.** When returning the pitch shifted hoarse voice to original pitch, hoarseness still remains."
>
> — [SPA-SVC, arXiv:2406.05692](https://arxiv.org/abs/2406.05692)（Interspeech 2024，北邮）`[论文]`

⇒ `[推测]` 这解释了用户的观察链：**降八度把 F0 拉回训练集覆盖区 → 嘶哑减少 → 但音域跟着塌了**。用户看到的"泄漏减少"里，可能**有一部分其实是"音高凑进参考音音域"带来的假象，而非音色真的迁移成功**——这与本技能库已记录的 LTAS 陷阱（LTAS 奖励音高、不奖励音色）是同一个坑。

### 1.3 音色泄漏（timbre leakage）的 RVC 官方定义与旋钮

RVC 官方中文 FAQ **Q11 原文**：

> "如果底模和推理源的音质高于训练集的音质，他们可以带高推理结果的音质，但代价可能是**音色往底模/推理源的音色靠，这种现象叫做'音色泄露'**；
> **index rate 用来削减/解决音色泄露问题。调到 1，则理论上不存在推理源的音色泄露问题**，但音质更倾向于训练集。如果训练集音质比推理源低，则 index rate 调高可能降低音质。调到 0，则不具备利用检索混合来保护训练集音色的效果；
> 如果训练集优质时长多，可调高 total_epoch，此时模型本身不太会引用推理源和底模的音色，很少存在'音色泄露'问题…"
>
> — [RVC FAQ（中文 wiki）](https://github.com/RVC-Project/Retrieval-based-Voice-Conversion-WebUI/wiki/%E5%B8%B8%E8%A7%81%E9%97%AE%E9%A2%98%E8%A7%A3%E7%AD%94) `[工具文档]`

**源码验证**（本机拉取 `infer/vc/pipeline.py` 与 `train/dataset/extract_f0.py` 逐行核对）：索引检索就是特征插值，`index_rate=1` 即 100% 用训练集特征：

```python
# infer/vc/pipeline.py
npy = ...  # 检索到的训练集特征
feats = torch.from_numpy(npy).unsqueeze(0).to(self.device) * index_rate + (1 - index_rate) * feats
```

— [RVC `infer/vc/pipeline.py`](https://github.com/RVC-Project/Retrieval-based-Voice-Conversion-WebUI/blob/main/infer/vc/pipeline.py) `[工具文档]`

⇒ `[推测]` **但你需要的不是"无泄漏"，而是"换成目标音色"。** `index_rate→1` 只能保证"不出现推理源的音色"，不能保证"出现目标音色"——当目标说话人素材里根本没有高音，检索库里**没有高音特征可供检索**，此时 index_rate 拉满会退化成"把高音硬拽到训练集里最接近的低音特征"，即音域塌陷 + 怪音。**这是"提高 index_rate 治泄漏"在跨音域场景下失效的原理。**（此推断基于源码机制，未找到直接实测论文。）

### 1.4 RVC 的 F0 硬上限：1100 Hz（源码）/ 800 Hz（Applio）

**本机源码核对**（`infer/vc/pipeline.py` L74-77、`train/dataset/extract_f0.py` L62-65，两处一致）：

```python
f0_min = 50
f0_max = 1100
f0_mel_min = 1127 * np.log(1 + f0_min / 700)
f0_mel_max = 1127 * np.log(1 + f0_max / 700)
```

⇒ 训练与推理的 F0 都在这条 mel 标尺上量化。**但代码里没有 clamp**，所以与其说是"截断"，不如说是**超出 1100 Hz 的取值落进了量化表的边缘、精度塌陷**。`[工具文档]` + `[推测]`

社区实测指向上限确实会咬人：

> `hpx502766238`（2024-08-27，在萨顶顶《左手指月》上）："今天重新测了一下好像又可以了，应该还是 **f0 预测器的限制问题**，在 Applio 预测代码 (rvc/infer/pipeline.py) 里有个 **f0_max 默认是 800 还是 1000 来着，改成 1600 好像又行了**，虽然效果不算特别好，至少不会全哑了。"
>
> — [Issue #2266 · 一到高音就哑火](https://github.com/RVC-Project/Retrieval-based-Voice-Conversion-WebUI/issues/2266) `[社区]`

⚠️ **注意方向**：1100 Hz 约等于 C6（≈1046 Hz）再往上一点。**绝大多数流行歌的高音根本够不到这个天花板**（女高音 high C 是 C6=1046Hz，已经贴边）。所以：`[推测]` **用户的失效极可能不是 F0 提取上限，而是 §1.1 的训练集音域覆盖不足。** 先查训练集 F0 分布，别急着改 f0_max。

### 1.5 端到端 vs 声学模型：跨音域的失效点不止一处

Community 版 RVC 用 `rmvpe` 时，F0 提取与生成是两套东西；`rmvpe` 本身在高音上也会出错：

> [Issue #920 · rmvpe 高音容易跑调，两个八度反复横跳，用 parselmouth 就没事](https://github.com/RVC-Project/Retrieval-based-Voice-Conversion-WebUI/issues/920) `[社区]`
> （作者 `RVC-Boss` 在 issue 中回复"我们实验一下"，此后 issue 保持 open，未见结论）`[社区]`

⇒ `[推测]` **换 F0 提取器（rmvpe/fcpe/pm）能改的是"音高轨迹抓得准不准"，改不了"模型能不能发出这个音高"。**这两件事在社区讨论里经常被混为一谈。

## 2. ★ 音域扩展（pitch range extension）的可行手段

### 2.0 先给结论

| 手段 | 能否扩展"可控音域" | 代价 | 证据强度 |
|---|---|---|---|
| (a) 训练集变调增强（朴素 pitch-shift） | **部分能**，但 RVC 原生**未实装** | 音色变（共振峰被一起搬走） | 论文支持思路，RVC 无实现 |
| (b) formant-preserving pitch shift（WORLD/rubberband） | 能，且保住音色 | 需自己搭流程 | 工具文档明确 |
| (c) 推理时 formant shift 参数 | **RVC 无；DDSP-SVC 有** | — | 源码级确认 |
| (d) 零样本 SVC（Seed-VC 等） | **不依赖目标训练音域**，是该问题的天然解 | 音色像不像另说 | 工具文档 + 本机实测 |
| (e) 补录/换参考音/换模型 | 最直接 | 需要素材 | 社区共识 |

### 2.1 训练集变调增强（pitch augmentation / pitch-shifted copies）

#### 2.1.1 ★ 关键发现：**RVC 官方仓库里没有这个功能**

**本机源码核查结论**：

- `train/preprocess.py`、`train/data_utils.py`、`train/dataset/extract_f0.py`、`infer/vc/pipeline.py` —— **`formant` 命中数全部为 0**。
- `train/data_utils.py` 里对 `pitch`/`pitchf` 只做**切片与 padding**，**没有任何 keyshift / semitones / augment 逻辑**。
- 因此：**RVC 官方版不存在"训练集变调增强"开关。** `[工具文档]`

⚠️ **常见误传**：网上说的"RVC 训练时把数据升/降调再训一遍"**在官方 RVC 里没有对应的代码路径**（v1/v2 都没有）。如果要做，只能在**预处理前自己离线生成变调副本**（把 `dataset_raw` 里每个 wav 额外导出 ±N 半音的副本，再一起喂进去）。

#### 2.1.2 ★★ DDSP-SVC 有原生实现，且给出了具体数值 —— 这是最可复用的工程参考

**DDSP-SVC**（`yxlllc/DDSP-SVC`，RVC 的同生态竞品，2.7k star）**原生实现了 pitch augmentation**：

```python
# preprocess.py  L174-181
if use_pitch_aug:
    keyshift = random.uniform(-5, 5)
else:
    keyshift = 0

aug_mel_t = mel_extractor.extract(audio_t * (10 ** log10_vol_shift), sample_rate, keyshift=keyshift)
aug_mel = aug_mel_t.squeeze().to('cpu').numpy()
aug_vol = volume_extractor.extract(audio * (10 ** log10_vol_shift))
```

— [DDSP-SVC `preprocess.py`](https://github.com/yxlllc/DDSP-SVC/blob/6.3/preprocess.py) `[工具文档]`

**三条可直接照抄的工程决策**：

1. **shift 量 = `random.uniform(-5, 5)` 半音**，**每轮随机采样**（不是固定几份副本）。`[工具文档]`
2. **只对 mel 做变调，f0 用比例缩放对齐**（`data_loaders.py`）：
   ```python
   f0_frames = 2 ** (aug_shift / 12) * f0[start_frame : start_frame + units_frame_len]
   aug_shift = torch.from_numpy(np.array([[aug_shift]])).float()
   ```
   ⇒ **`aug_shift` 作为条件输入喂给模型**，让模型知道"这条样本被移调了多少"。
3. **验证集不做增强**（`use_pitch_aug=False`），保证评估口径干净。
4. 增强后额外存一份 `aug_mel` / `aug_vol`（与原版并存），`pitch_aug_dict.npy` 记录每个文件的 keyshift。

→ **"份数"这个问法在 DDSP-SVC 的范式下不成立**：它不是"生成 ±N 的固定副本"，而是**每个 epoch 随机一个 shift**。`[工具文档]`

#### 2.1.3 论文支持：cross-domain 场景下"朴素增强不够，要循环一致性"

**SPA-SVC**（[arXiv:2406.05692](https://arxiv.org/abs/2406.05692)，Interspeech 2024）明确指出：

> "Although existing SVC models **can introduce small-scale pitch random perturbations during training**, they often generate **hoarse artifacts in cross-domain SVC scenarios, particularly as the vocal range span increases**."

即在 **DDSP-SVC 的 `(-5, 5)` 基础上**，跨域仍然坏。SPA-SVC 的做法：

- **把 shift 量拉到 `random.uniform(6, 18)` 半音**（随机整数），远大于常规扰动；
- **cycle pitch shifting**：先升 → 重建 → 再从重建音频里提特征、降回原调 → 第二次重建 → 用 **SSIM loss** 比较两次重建的 mel 与原 mel：

  `L_cyc = 1 - SSIM(x, x̂)`，总损失 `L_total = L_cyc + L_diff`
- **数据**：M4Singer，训练集 Alto-1 554 段 / Bass-3 967 段；推理时用 **Soprano-3 / Tenor-1 作为未见说话人**，pitch shift key 取 **4 或 12**。
- **结果**：MOS-B 上 SPA-SVC 比 DDSP-SVC-Diff **高约 8.9%**；MOS-S（仅移调音频）**高约 0.17**。`[论文]`

**反效果（正是用户问的那条）**：

> `[社区]` `leospark`："通过做数据增强 pitch_shift 有效吗（**我尝试了，音色会变**）" — [#957](https://github.com/RVC-Project/Retrieval-based-Voice-Conversion-WebUI/issues/957)

`[推测]` **"音色会变"的机理**：朴素的 `pitch_shift`（含 librosa 默认实现）**把共振峰和 F0 一起搬**——升 5 半音，共振峰也升 5 半音，于是模型学到"这个人的音色 = 一个共振峰偏高的人"，把增强当成了**音色变异**而非**音高变异**。这正是 §2.2 要解决的问题。

#### 2.1.4 相关但不同：SingAug（SVS 侧的数据增强）

[SingAug, arXiv:2203.17001](https://arxiv.org/abs/2203.17001)（Interspeech 2022）系统研究 SVS 的数据增强，包括 **pitch augmentation + mix-up augmentation + cycle-consistent training**，在两组公开歌声库上显著提升主客观指标。`[论文]`
（SPA-SVC 引用它并说明自己的区别：SingAug 是"minor-range"增强，SPA-SVC 把范围拉到 6–18 半音并加循环一致性。）`[论文]`

### 2.2 Formant-preserving pitch shift

#### 2.2.1 原理与"直接改采样率"的区别

**librosa 的实现就是"变速 + 重采样"**（本机读 `librosa/effects.py` 源码确认）：

```python
rate = 2.0 ** (-float(n_steps) / bins_per_octave)
# Stretch in time, then resample
y_shift = core.resample(...)
```

— [librosa `effects.py` `pitch_shift`](https://github.com/librosa/librosa/blob/main/librosa/effects.py) `[工具文档]`

⇒ **`librosa.effects.pitch_shift` = 相位声码器时间拉伸 + 重采样，F0 与共振峰同步移动，不做任何 formant 保持。**"直接改采样率"（resample 后按原速播放）同理，两者都会让"花栗鼠/低沉"效应出现。`[工具文档]`

#### 2.2.2 支持 formant 保持的工具

| 工具 | 关键选项 | 原文 | 类型 |
|---|---|---|---|
| **Rubber Band** | `-F, --formant` | "**Enable formant preservation when pitch shifting.** This option attempts to keep the formant envelope unchanged when changing the pitch, **retaining the original timbre of vocals** and instruments in a recognisable way." | `[工具文档]` |
| **WORLD / pyworld** | `CheapTrick` 谱包络 + `Synthesizer` | WORLD 把语音分解为 **F0 / spectral envelope（含共振峰）/ aperiodicity** 三路，改 F0 而不动谱包络即"保共振峰变调" | `[工具文档]` |
| **Rubber Band**（引擎差异） | `-2/--fast` (R2) / `-3/--fine` (R3) | "R3… **almost always produces better results** than the R2 engine, but with significantly higher CPU load."；`-c/--crisp` 仅对 R2 生效 | `[工具文档]` |

— [Rubber Band usage.txt](https://www.breakfastquay.com/rubberband/usage.txt) `[工具文档]`

**TD-PSOLA / PSOLA 系**：`未找到` 直接可引的官方文档页（本次检索未获可靠来源）。`[推测]` PSOLA 系列属于"时域基音同步叠加"，天然在时域操作、共振峰随包络被动保持，但**在音高偏移大时（>5–6 半音）共振峰随时间变化的平滑性会崩**，这与其在语音变调中的经典适用范围一致。**此条未找到本次可引证的来源，请勿当作已核实结论。**

#### 2.2.3 RVC 生态里怎么做

**RVC 官方推理管线中没有 formant shift 参数**（源码级确认：`infer/vc/pipeline.py` 的 `formant` 命中数为 0；WebUI 参数为 `f0up_key` / `index_rate` / `filter_radius` / `resample_sr` / `rms_mix_rate` / `protect`）。`[工具文档]`

⇒ **要在 RVC 生态里做 formant-preserving，只能在 RVC 之外包一层**：
`[推测]`（流程推断，各步工具有文档支持，但"这样组合能解决跨音域"未找到实测来源）
```
人声干声 → Rubber Band -F -p -5（保共振峰降 5 半音）
        → RVC 转换（此时 F0 落在训练集音域内，模型能发出来）
        → Rubber Band -F -p +5（保共振峰升回去）
```
**风险**：两次 resample 会累积失真；且**升回去之后 F0 又超出模型音域，RVC 生成时的谐波结构本身就是"低音结构"被强行拉伸**——`[推测]` 这只能缓解，不能根治。

**RVC 2.3.260718 新增了"性别因子／声线粗细"**（"尽量保持音高不变，只移动共振峰，范围 -2～+2"）—— `[社区]`（第三方实测文章，非官方文档）。**本次未在官方 Changelog 中检索到该参数**（已抓取 `docs/cn/Changelog_CN.md` 全文，无"性别"/"共振峰"字样），**故可信度存疑，建议以本机界面实测为准。**

### 2.3 推理时 formant shift 参数

#### 2.3.1 RVC：**没有** `[工具文档]`

源码级确认（见 §2.2.3）。RVC 官方 WebUI/CLI 只有 `f0up_key`（移调半音数）这一个"高度"旋钮，**它不区分 F0 与共振峰**。

#### 2.3.2 ★ so-vits-svc：**也没有**，但有近亲参数 `--enhancer_adaptive_key` `[工具文档]`

本机拉取 `4.1-Stable` 的 `README_zh_CN.md`、`inference_main.py`、`inference/infer_tool.py`，**`formant` 命中数均为 0**。但 `inference_main.py` 里有一个**专为"更高音域"设计的参数**：

```
-eak, --enhancer_adaptive_key   使增强器适应更高的音域(单位为半音数)|默认为0
```

同文件里另有与音域强相关的提示：

```
-a, --auto_predict_f0   语音转换自动预测音高，转换歌声时不要打开这个会严重跑调
-ft, --f0_filter_threshold   降低该值可减少跑调概率，但会增加哑音
-f0p, --f0_predictor   可选择 crepe,pm,dio,harvest,rmvpe,fcpe
```
— [so-vits-svc `inference_main.py` @4.1-Stable](https://github.com/svc-develop-team/so-vits-svc/blob/4.1-Stable/inference_main.py) `[工具文档]`

⇒ `[推测]` "增强器适应更高音域"是**声码器侧**的适配，说明 so-vits-svc 作者承认"高音域"是一个需要单独处理的问题，且**他们选择的解法是让声码器跟上，而不是移动共振峰**。

#### 2.3.3 ★★ DDSP-SVC：**有** `--formant_shift_key`，且与 pitch-aug 模型绑定 `[工具文档]`

**这是本次调研在"formant shift 参数"上唯一的直接命中。**

```
--formant_shift_key    formant changed (number of semitones) , only for pitch-augmented model | default: 0
```
— [DDSP-SVC `main_reflow.py`](https://github.com/yxlllc/DDSP-SVC/blob/6.3/main_reflow.py) `[工具文档]`

GUI 侧（`gui_reflow.py`）：
- 滑条标签 **"共振峰偏移"**，范围 `(-2, 2)`，精度 0.05，默认 0；
- 与 **"变调"** 滑条（范围 `(-24, 24)`，整数半音）**并列独立**；
- 传入模型时复用 **`aug_shift` 这个通道**：

```python
f0 = f0 * 2 ** (float(pitch_adjust) / 12)      #变调
# formant change
formant_shift_key = torch.from_numpy(np.array([[float(formant_shift_key)]])).float().to(self.device)
...
result = self.reflow_model.infer(..., aug_shift = formant_shift_key, ...)
```

— [DDSP-SVC `gui_reflow.py`](https://github.com/yxlllc/DDSP-SVC/blob/6.3/gui_reflow.py) `[工具文档]`

**★ 这条设计极其重要，直接回答了用户的问题：**

> **`formant_shift_key` 只在 `use_pitch_aug=True` 训出来的模型上有效** —— 因为模型在训练时见过"mel 被移调、aug_shift 记录了移调量"的配对，**推理时才能通过 `aug_shift` 反向控制共振峰**。

⇒ **共振峰可控性不是推理期的免费午餐，是训练期埋进去的能力。** 这解释了为什么 RVC 没有这个参数：**RVC 训练时没做 pitch aug，所以推理期无从控制共振峰。** `[推测]`（基于 DDSP-SVC 的接口设计反推，逻辑自洽，但未找到明确论述此因果的文档）

**效果如何？** DDSP-SVC 的 `cn_README.md` **未给出 `formant_shift_key` 的调参建议或效果数据**。`未找到` 该参数的实测效果对比。

### 2.4 零样本 SVC 在跨音域上是否更好？

#### 2.4.1 ★ 结构性优势：零样本不依赖"目标说话人有没有高音数据"

**这是原理性的，不是效果好坏问题。**

> `[论文]` Everyone-Can-Sing（[arXiv:2501.13870](https://arxiv.org/abs/2501.13870)，CMU/Princeton/Adobe）：
> "**speech and singing timbre of the same person can differ significantly; the input singing pitch range may vary widely from the short target speech**"
> 其解法：**只用一个 5 秒语音做参考**，"To handle potential pitch range mismatches between speech and singing, we offer a **pitch adjustment method that shifts the target music score into a range within one octave of the speech reference.**"

**⚠️ 注意这句里的消音**：Everyone-Can-Sing 处理跨音域的办法，**是把乐谱移调进参考语音的八度内** —— 也就是说，**当目标只有说话数据时，它也是靠"改变歌曲音高来适配"，而不是"让说话人的音色唱上去"。** `[论文]`

**消融实验里有一条非常关键的负面结果**（原文）：

> "Pitch adjustment aligns source and target pitch ranges, boosting similarity but sometimes reducing singing quality; for example, **lowering a song's pitch to match the normal speaking range can make it sound unnaturally low.**"
>
> 以及："When source and target genders differ, SVS quality remains mostly unaffected… However, for the two SVC models, **quality drops significantly** while similarity improves, likely due to **larger pitch shifts in cross-gender conversion**."
>
> — [Everyone-Can-Sing, Table II 消融](https://ar5iv.labs.arxiv.org/html/2501.13870) `[论文]`

⇒ **这几乎是用户现象的论文版复刻**：**"降调能提升相似度，但会降低音质、且听起来不自然地低。"** 与用户观察到的"降八度泄漏减少但音域变低"完全一致。`[论文]`

#### 2.4.2 零样本是否真的"更好"？—— 诚实的答案：**看维度**

| 维度 | 训练式 RVC | 零样本 SVC |
|---|---|---|
| 跨音域**可用性** | 取决于训练集音域（硬边界） | 不依赖目标训练音域（结构性优势） |
| 音色**相似度** | 通常更高（有目标数据） | 较低，受参考音时长/质量限制 |
| 跨域（说话→歌唱） | 差 | 论文明确说"commonly less effective with cross-domain speech targets" |

**同域（说话→说话）的客观对比**（Seed-VC 官方 EVAL，SECS = 说话人嵌入余弦，越高越好）：

| 模型 | SECS↑ |
|---|---|
| Ground Truth | 1.0000 |
| CosyVoice | 0.8440 |
| **Seed-VC（零样本）** | **0.8676** |

同表里 Seed-VC 与非零样本 So-VITS-4.0 的对比：Tokai Teio 0.8899 vs 0.8637；Milky Green **0.8072 vs 0.6850**；Matikane 0.8768 vs 0.8594。
⇒ **零样本 Seed-VC 在同域上已经反超 So-VITS-4.0**（作者自评："despite not being trained on the target speakers, Seed-VC is able to achieve significantly better results than the non-zero-shot models. **However, this may vary a lot depending on the SoVITS model quality.**"）
— [Seed-VC EVAL.md](https://github.com/Plachtaa/seed-vc/blob/main/EVAL.md) `[工具文档]`

**★ 关键限定：这张表全是"说话→说话"，不是"说话参考 → 歌唱"。** `未找到` 任何"零样本 SVC vs 训练式 RVC 在跨音域歌唱上"的公开对照评测。`[社区]` 本技能库记录的本机实测（SeedVC f0 s11：CAM++ vs 参考 0.524 / vs 源 0.204）是**同任务链上最接近的证据**，但那是非人声（卡通）目标，不能直接外推。

#### 2.4.3 Seed-VC 的歌唱专用分支与参数

Seed-VC README 明确区分了 VC 与 SVC 模型：

> "seed-uvit-whisper-base … **Singing Voice Conversion (SVC)** … 44100 Hz … **strong zero-shot performance, singing voice conversion**"

歌唱推理参数：

```
--f0-condition True        # set to True for singing voice conversion
--semi-tone-shift 0        # pitch shift in semitones for singing voice conversion
--auto-f0-adjust False     # set to True to auto adjust source pitch to target pitch level,
                           #   normally not used in singing voice conversion
--diffusion-steps 25       # recommended 30~50 for singing voice conversion
```
— [Seed-VC README](https://github.com/Plachtaa/seed-vc) `[工具文档]`

⇒ `[推测]` **`--f0-condition` 必须开**（否则 F0 不受控）；**`--auto-f0-adjust` 官方说"歌唱时通常不开"** —— 这与上文 Everyone-Can-Sing"降调伤音质"的结论方向一致：**自动对齐音高在歌唱场景会产生不自然的音域压缩。**

| 论文 | 结论 | 链接 |
|---|---|---|
| **Zero-Shot Sing VC (clustering-based phoneme repr.)** | "**datasets with fewer recordings per artist are more susceptible to timbre leakage**"；用 10,000+ 小时歌唱数据训练 | [arXiv:2409.08039](https://arxiv.org/abs/2409.08039) `[论文]` |

## 3. SVS（歌声合成）路线

### 3.1 ★ 核心结论：**SVS 天然不受"源音轨音域"限制，但受"训练数据音域"限制**

**这是 SVS 与 SVC 的本质差别**：SVC 的输入是一段**已经录好的演唱**，所以源音域是硬输入；SVS 的输入是**乐谱（音高 + 时长）+ 歌词**，音高是你**指定**的。

**RVC 作者自己承认了这个问题的本质**（#957 之后的追问）：

> `leospark`："@RVC-Boss 但是往往数据集内音高数据有限，尤其是 10min 数据，那该如何解决？"
> — [Issue #957](https://github.com/RVC-Project/Retrieval-based-Voice-Conversion-WebUI/issues/957) `[社区]`

⇒ **"数据内音高有限"在 SVC 范式下无解**（因为模型必须见过这个音高才能发出来）；**SVS 把这个约束从"源音轨"转移到了"声库"** —— 只要声库训练数据覆盖 C5，SVS 就能唱 C5，**与原唱唱不唱得上去无关**。`[推测]`（基于 SVS/SVC 任务定义，逻辑必然，但未找到明确对比论述的论文）

### 3.2 各 SVS 工具的门槛

#### 3.2.1 DiffSinger（OpenVPI 维护版）`[工具文档]`

- 基于 [DiffSinger: Singing Voice Synthesis via Shallow Diffusion Mechanism](https://arxiv.org/abs/2105.02446)（AAAI 2022，浙大）
- 输出 44.1 kHz（原版 24 kHz）；引入 variance model 控制 **pitch / energy / breathiness / tension / voicing**
- 构成：**acoustic model**（必需）+ **variance model**（可选，用 DS 文件或额外数据）

**数据要求（官方 BestPractices 原文）**：`[工具文档]`
- 训练 acoustic model **必需三列**：`name` / `ph_seq`（音素序列）/ `ph_dur`（音素时长，秒）→ **即需要人工对齐的音素级标注**
- 录音放 `wavs/`，WAV 或 FLAC，推荐 mono
- **F0 提取范围是硬边界，官方要求按数据集调整**：
  ```yaml
  f0_min: 65   # Minimum F0 to detect
  f0_max: 1100 # Maximum F0 to detect
  ```
  > "It is also recommended to change the F0 detection range for Harvest **in accordance with your dataset, as they are hard boundaries for this algorithm and the defaults might not suffice for most use cases.**"
- 推荐 RMVPE 做音高提取；推荐 Vocal Remover 做谐波/噪声分离
- 声码器微调"**highly recommended**"

**★ 官方文档里 `未找到` "最少需要多少小时/多少首歌"的具体数字。** `未找到`（已抓取 `README.md` / `GettingStarted.md` / `BestPractices.md` 全文检索 hour/minute/song/at least，无数据量门槛表述）。

### 3.3 "用说话数据训歌声合成"的研究

| 论文 | 年份 | 核心做法 | 链接 |
|---|---|---|---|
| **DurIAN-SC** | 2020 | **只用说话数据**生成目标说话人的高质量歌声；统一语音/歌声合成特征；**20 秒 enrollment speech** | [ISCA](https://www.isca-archive.org/interspeech_2020/zhang20k_interspeech.html) `[论文]` |
| **Everyone-Can-Sing** | 2025 | 零样本 SVS + SVC，**5 秒语音参考**；**singing + speech 混合训练 1:1**（LibriTTS-R + 6262h 歌唱数据）；跨音域用"把乐谱移进参考语音八度内" | [arXiv:2501.13870](https://arxiv.org/abs/2501.13870) `[论文]` |

**★ Everyone-Can-Sing 的混合训练消融（对用户最有用的一条）**：

| 训练策略 | Zero-shot SVS MOS | SIM-MOS |
|---|---|---|
| **Mix Train.**（歌唱:语音 = 1:1） | 4.01 ± 0.08 | 3.80 ± 0.13 |
| **Singing Train.**（只用歌唱） | 3.83 ± 0.21 | 3.46 ± 0.49 |

> 原文："The **mixed training strategy enhances both quality and similarity** across all models. In contrast, **training only on singing data leads to higher variance** in these scores, likely due to the limited data scale in zero-shot settings, which could cause instability."
> — [Everyone-Can-Sing §III-B2](https://ar5iv.labs.arxiv.org/html/2501.13870) `[论文]`

⇒ **说话数据不是负担，是有用的补充** —— 但前提是**模型架构显式支持跨域**（variance model / 分离的 performance attributes）。这**不能**外推成"RVC 加说话数据就能唱高音"。`[推测]`

### 3.4 SVS 路线的门槛总结

| 门槛 | 内容 | 来源 |
|---|---|---|
| **必须能标注** | DiffSinger 需要音素级 `ph_seq` + `ph_dur`（秒）对齐 | `[工具文档]` |
| **必须覆盖目标音域** | F0 检测范围是 hard boundary，"defaults might not suffice" —— 但官方**未明说**"必须本人唱得到" | `[工具文档]` + `[推测]` |
| **计算门槛** | NNSVS 推荐 10GB+ 显存；DiffSinger 需训练 acoustic + 可选 variance + 推荐微调 vocoder | `[工具文档]` |
| **数据量** | 官方**均未给出硬性小时数**；NNSVS 举例"30 首歌难以训出高质量模型" | `[工具文档]` |
| **★ 关键未知** | **"本人唱不到 C5，能否合成出 C5"** —— `未找到` 任何官方文档对这个问题给出明确答复 | `未找到` |

**⚠️ 对"用户本人唱不到那个音域"这一具体问题的诚实回答**：
`未找到` 直接文献。但 §3.2.1 的 F0 hard boundary 提示 + §3.1 的任务定义 ⇒ `[推测]` **SVS 的音域上限由"训练录音实际出现的 F0"决定，而"录音里出现的 F0"又受"本人能不能唱到"限制** —— 所以 **SVS 并不能凭空虚构出本人从未发出过的音高**，它只是把"源音轨音域"这个约束换成了"声库录音音域"。**要合成 C5，声库里就得有 C5 的录音。**
⇒ 但这**不等于**无解：**§2.1 的 pitch augmentation（尤其 SPA-SVC 式的 6–18 半音 + cycle consistency）在原理上就是把"没录过的音高"补进去的手段**，且 SVS 侧已有 SingAug 论文验证同类思路。`[推测]`

## 4. 现实对比：业界/社区给普通用户的实际建议

### 4.1 (a) 直接用原唱人声轨转换 —— 社区公认的缺点

| 缺点 | 原文证据 |
|---|---|
| **继承了原唱的演绎、口音、咬字、情绪** | "RVC 换的是音色，别的基本不管。**输出的节奏、口音、咬字和情绪都来自输入表演，不来自模型**" — [VoiceFinch RVC 教程](https://voicefinch.com/blog/rvc-voice-model) `[社区]` |
| **音色泄漏** | RVC 官方 FAQ Q11 定义（见 §1.3）；"听起来还像原唱 → 音色泄漏" — 同 VoiceFinch 教程故障表 `[社区]` |
| **音域不匹配导致破音** | "高音或低音破音 → **超出训练集的音域** → 补录对应音域，调整变调" — 同上 `[社区]` |
| **原唱混响/和声残留** | "推理源没处理干净，**可能是还残存有和音**" — [Issue #2266](https://github.com/RVC-Project/Retrieval-based-Voice-Conversion-WebUI/issues/2266) `[社区]` |

### 4.2 (b) 自己唱一遍再转换 —— 为什么社区推荐？

**核心逻辑**：**把"音域问题"从模型转移到"你能唱到哪"，再用变调解决。**

**最完整的一段社区原文**（繁体中文 RVC 指南，两个区块的配合）：

> **原音升降 Key (Source Shift)**：【破音救星】如果您在使用模型转换时发现声音变得很假、**高音唱不上去** (例如男生唱女生的歌)，您可以直接在这里将「原始音档」进行升降 Key (例如 -2 或 -4)。程式会在背景以无损音质将您的原音变调后，再送给 AI 处理，**这样转换出来的声音会大幅提升自然度！**
>
> **💡 魔法公式：男女转换必胜诀窍**
> 如果您用男生的声音去唱女生的歌 (男转女)，请先试着把 **变调 (Pitch) 设为 +12**。如果还是觉得怪，原因通常是**男生根本唱不上去**，此时强烈建议您**善用我们第一区块的「原音升降 Key」功能**，把您的原音降个 **-3 到 -6 个半音**，并且 **Pitch 依然维持 +12**。用修饰过的低音域人声喂给 RVC，**效果会神乎其技的自然！**
>
> — [Studio0808 · RVC 變聲技術](https://begin0808.github.io/studio0808_video/rvc_guide.html) `[社区]`

**⚠️ 注意这段话的两个前提**：① 它假设**人声是你自己录的**（"男生根本唱不上去"——只有自己唱才会遇到）；② 它推荐的是**"降源音 + 用 Pitch 升回来"的双旋钮组合**，而不是单纯把降调结果当成品。

**另一份社区教程把"输入质量"放在调参之上**：

> "比调参更管用的是输入质量：先把人声和伴奏分开，别用带混响的人声，**尽量让输入音域接近模型，不要靠极端的变调值硬拉。**"
> — [VoiceFinch RVC 教程](https://voicefinch.com/blog/rvc-voice-model) `[社区]`

⇒ **"让输入音域接近模型"这句话，正是用户"降八度"操作的动机，也正是本条建议的核心。** 但注意它说的是"接近"，不是"降一个八度"—— `[推测]` **降 12 半音属于"极端变调值"，社区建议的范围是 -2 到 -6。**

**⚠️ `未找到` 明确对比"用原唱轨 vs 自己唱一遍"的并列实测。** 上述建议都是**隐含的**（"魔法公式"只在"自己唱"的语境下才成立），没有哪篇教程直接写"A 方案比 B 方案好 N 分"。**这是本次调研的一个明确空白。**

### 4.3 (c) 先降调再转换、转换后再升回去 —— 副作用

| 副作用 | 证据 |
|---|---|
| **伴奏对不上** | "做翻唱时，如果人声升降的不是**整八度**，**伴奏也要升降同样的半音数，否则调就对不上**" — [VoiceFinch](https://voicefinch.com/blog/rvc-voice-model) `[社区]` |
| **降调伤音质 / 听起来不自然地低** | `[论文]` Everyone-Can-Sing："**lowering a song's pitch to match the normal speaking range can make it sound unnaturally low.**"（见 §2.4.1） |
| **嘶哑会残留**（降回去也还在） | `[论文]` SPA-SVC："**hoarse portions persisting even when the pitch is lowered back to the original**"（见 §1.2） |
| **共振峰错位** | `[工具文档]` 朴素的 librosa/重采样变调不保 formant（见 §2.2.1）；保 formant 需 Rubber Band `-F` 或 WORLD —— **`未找到`社区教程在 RVC 翻唱流程中实际使用 formant-preserving 工具的原文证据** |

**★ 用户现象的机制链条（本次调研的综合推断，`[推测]`，但每一环都有上面引用的来源支撑）**：
```
原唱高音超出目标模型训练音域
  → RVC 检索库里没有对应高音特征
  → 高音段被迫用低音特征近似 → 嘶哑/失真（§1.2）
  → 同时源音色（原唱）在高音段无处可替换 → 泄漏明显（§1.3）
降八度：
  → F0 回到训练集覆盖区 → 模型能"发得出来" → 嘶哑减少、泄漏减少 ✔
  → 但整首歌音域塌陷（§2.4.1 论文复刻），且 SPA-SVC 指出降回去后嘶哑仍在 ✘
```

### 4.4 (d) 直接合成（SVS / AI 翻唱工具）

- **`[社区]`** 有一类"AI 翻唱"商业/半成品工具走的是 SVS 或"零样本 SVC + 完整工程链"路线（如 Replay、ACE Studio）。[ACE Studio 官方博客](https://acestudio.ai/blog/ai-vocal-svs-comparison-rvc) 的标题即 "How to get vocals with AI: **SVS vs. RVC**"，但**该页正文本次抓取为空** `未找到` 实质内容。
- **`[社区]`** 社区教程把"Replay"这类工具描述为"**利用音色模型 + 原曲进行 AI 翻唱**" —— [AcoFork · 手把手教你 AI 翻唱](https://b.acofork.com/posts/rvc/) 里 **Replay 的输入仍然是"原歌曲"**，不是乐谱 ⇒ `[推测]` 这类工具本质仍是 SVC，**不能解决"原唱音域超限"的根本问题**。

### 4.5 ★ 综合建议（按对本机场景的适配度排序）

`[推测]`（下列排序是基于前述来源的工程推断，**未找到**任何来源给出同样的完整排序）

| 优先级 | 做法 | 依据 |
|---|---|---|
| **1** | **补录/补搜目标人的高音素材**（哪怕几句），重训 | `[社区]` RVC 作者直接结论（§1.1）；[#2541] "正常说话的声音很难覆盖全声域，这样在高音处可能破音或嘶哑" `[社区]` |
| **2** | **换零样本 SVC**（Seed-VC，开 `--f0-condition`），绕开"目标训练音域"限制 | §2.4.1 结构性优势 + 本技能库既有本机实测 `[工具文档]`+本机实测 |
| **3** | **用 SPA-SVC 式的训练集变调增强重训 RVC**（注意：RVC 无原生支持，需离线造变调副本；且**必须用保共振峰的变调**） | §2.1.2 DDSP-SVC 参数 + §2.1.3 SPA-SVC `[工具文档]`+`[论文]` |
| **4** | **降调幅度收敛到 -2 ~ -6 半音**（而不是 -12），配合 RVC 内部 Pitch 回补；伴奏同步变调 | §4.2 社区"魔法公式" `[社区]` |
| **5** | **走 SVS 路线**（DiffSinger + OpenUtau）—— 但需先解决"声库音域覆盖"，且要音素级标注 | §3 `[工具文档]` |

**⚠️ 对"降调"的一条独立提醒**：本技能库已记录 ✅本机实测——**LTAS 奖励音高、不奖励音色**（纯机械降 12 半音、音色一点没改，LTAS 就涨 0.078，与 shift 0→−12 的全部增益 0.097 同量级）。**用户"降八度后泄漏减少"的主观判断，务必用 CAM++/SECS 复核，不要只凭听感或 LTAS。**

## 附录 A：F0 上限对照表（用于判断"高音"到底有没有顶到天花板）

| 音名 | 频率 |
|---|---|
| C4（中央 C） | 261.6 Hz |
| C5（女高音常用高音） | 523.3 Hz |
| **C6（soprano high C）** | **1046.5 Hz** |
| RVC `f0_max` | **1100 Hz** |
| DiffSinger 默认 `f0_max` | **1100 Hz** |

⇒ `[推测]` **RVC 的 1100 Hz 上限约等于 C6**，对绝大多数流行翻唱**不是瓶颈**；用户的失效更可能来自**训练集音域覆盖**（§1.1）而非 F0 提取上限。**建议先量训练集的 F0 分布再决定要不要动 `f0_max`。**
