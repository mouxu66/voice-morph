## 二、🔴 本次修掉的真 bug

### 2.1 `rvc_common.py`：异常处理器自己抛 NameError（静默契约失效）

- **症状**：`_find_pids_by_cmdline` 的 docstring 写着「失败返回 `[]` 并记日志」，
  但 except 分支里的 `logger` **模块内从未定义**（只有一句没人用的 `import logging`）。
  一旦 PowerShell 枚举进程失败，异常处理器自己炸 → 抛 `NameError` 而不是返回 `[]`。
- **影响面**：`cascade.py` / `rvc_live.py` 靠它判断「级联/ASR/训练进程是否还活着」。
  PowerShell 被安全策略拦、或 `Get-CimInstance` 慢到超时，就会把 `NameError` 顶到 API 层。
  `_kill_pids` 里的 `logger.debug` 同理：kill 失败会中断后续进程的清理。
- **复现证据**（删掉 `logger` 模拟修复前）：
  `NameError: name 'logger' is not defined`
- **修复**：补 `logger = logging.getLogger(__name__)`；
- **补测**：新增 `m2_server/tests/test_rvc_common.py`（3 例）——枚举失败返回 `[]`、
  正常解析 PID、`taskkill` 单点失败不中断后续。

### 2.2 `pet_market.is_busy()` 漏算「排队中」→ 卸载放行 + 测试随机挂

- **症状**：`is_busy()` 只看 `_ACTIVE_STATUSES = {downloading, installing}`，
  而同文件的 `_NON_TERMINAL = {queued, downloading, installing}`。
  于是 `install()` 刚把任务置为 `queued`、worker 还没把它改成 `downloading` 的这个窗口里，
  系统自认为「空闲」。
- **两个真实后果**：
  1. `uninstall()` 的互斥判断用的就是这个 `is_busy()` → **排队中的皮肤能被卸载**，
     随后 worker 照常落盘，目录状态与前端显示不一致；
  2. `test_pet_market.py` 用 `while ... is_busy()` 轮询安装完成 → 会在安装开始前就退出，
     断言到 `queued` → **随机失败**（实测：单文件跑挂 1 例、全量跑挂另一个例、再跑又全绿，
     同一份代码三种结果）。
- **修复**：`is_busy()` 改用 `_NON_TERMINAL`（入队即算忙）。
- **补测**：`test_busy_counts_queued_task`——排队算忙 + 排队中卸载必须被拒；
  修完 `test_pet_market.py` 连跑 3 次全绿（此前约 1/2 概率挂）。

### 2.3 `test_play_worker.py`：`read_text()` 未指定编码 → 本机必挂

- **症状**：`json.loads(hist_file.read_text())` 走 locale 编码。Windows 中文环境默认 **GBK**，
  而生产代码写的是 UTF-8 中文 → `UnicodeDecodeError: 'gbk' codec can't decode byte 0xaf`。
- **这是全量测试唯一的红**：审查开始时的基线是 **470 passed / 1 failed**，
  也就是说 `docs/犯错指南.md` 里「全量 373 绿」「全绿」的结论已经过期。
- **修复**：显式 `read_text("utf-8")`。
- **同类扫描**：全仓只剩 2 处 `read_text()` 无 encoding，另一处（`test_market_images.py:62`）
  读的是纯 ASCII，暂不触发。

### 2.4 `server.py` SPA 路由：路径穿越防护比别处弱一档

- **症状**：`str(cand).startswith(str(_web_dist.resolve()))` —— 字符串前缀判断会放行
  **同前缀的兄弟目录**（如 `web_dist_backup/…`）。而 `media_api.py` 用的是规范的
  `p.is_relative_to(base)`。同一个仓库两套标准。
- **修复**：统一为 `cand.is_relative_to(web_root)`。

## 四、🟢 值得保持的做法

1. **失败降级成对设计**：微信发送「UIA 优先 + 像素兜底」，任一环异常都不中断发送；
   `rvc_common.find_pth` 兼容 `G_*.pth` 命名差异。
2. **异常路径都带注释**说明为什么可以吞（`# noqa: BLE001 —— 体检失败绝不阻断训练`），
   审查时不用猜意图。
3. **autosync 的自我保护**很克制：源目录为空时**不执行删除镜像**、检测到「运行形态即副本」就跳过、
   全程绝不反向覆盖。自动同步最容易酿成数据事故的几种情形都堵住了。
4. **测试用 monkeypatch 隔离真机**：`conftest.py` 置 `VM_WARMUP=0` 防测试拉起 GPU 进程，
   `test_wechat_record` 用 autouse fixture 屏蔽真实 UIA，避免测试污染真机会话。
5. **性能决策有实测数字**（TTS 冷启动 41.8s→2.9s、微信段抠掉 ~12s），不是拍脑袋。
6. **文档密度极高**：`犯错指南.md` 的「症状/根因/对策/证据 + ✅📚❓」格式非常适合长期维护，
   建议新坑继续往里补。

## 六、下一步：自动化（待你选型）

现状是「**所有质量动作都靠人记得跑**」。可选落点（按性价比排序）：

1. **一条命令的本地全量自检**（`tools/check.py` 或 `make check`）：
   `ruff` → `pytest m2_server` → `tsc -b` → 失败即非零退出。
   这是 CI 的地基，也是每次改动交付前的唯一动作。
2. **GitHub Actions**（`.github/workflows/ci.yml`）：push/PR 跑上面同一条命令。
   无 GPU 环境跑测试没问题（测试全部用 monkeypatch 隔离了模型/微信/ffmpeg）。
3. **git pre-commit / pre-push 钩子**：跑「落盘双验证 + 快速子集」，
   对应 `犯错指南 §3.1`（编辑工具报成功但没落盘）与铁律 1/2。
4. **`requirements-dev.txt` + 固定版本**：`ruff` 已在 `.venv` 但不在 `requirements.txt`，
   换机器复现不出检查环境。
5. **测试稳定性护栏**：把 `test_pet_market` 这类真实线程 + `sleep` 的用例改成
   「轮询目标状态而非固定 sleep」，并加 `pytest --count`-式重复跑（或 `pytest-randomly`）暴露顺序依赖。
