# 在线扒歌（yt-dlp 外部工具桥）

> 插件 id `sound.ytdlp` · 页面 `/ytdlp` · 代码 `m2_server/ytdlp_fetch.py` + `m2_server/ytdlp_api.py`
> **这一页写给"拉不动歌的人"**：先看「拉不动时按这个顺序查」，八成的问题在前三节。

---

## 0. 它是什么 / 不是什么

它是**取歌的第 3 条路**，与前两条并列（三条产物都落同一个会话目录、都退出即删）：

| # | 入口 | 场景 | 实现 |
|---|---|---|---|
| ① | 上传文件 | 歌已经在本地 | `cover_api` 上传 |
| ② | 粘直链 | 手上有**能直接下**的 URL | `url_fetch.py`（自己发 HTTP，逐跳校验） |
| ③ | **在线扒歌** | 手上只有**平台分享链接** | `ytdlp_fetch.py`（调外部 yt-dlp） |

**不是**：本项目不内置 yt-dlp、不代管它的更新、不解析任何平台接口。
仓库里**没有一行绕 DRM 的代码** —— 工具由用户自己装、自己升、自己承担使用边界。
所以它是个**可关的插件**（`plugin.json` 里 `extras.external[].kind = "app"`），
关掉它不影响 ①② 两条路。

为什么选 yt-dlp 而不是那些"解析接口"（2026-09-26 调研结论，别再走一遍）：

* 第三方 PHP 解析接口（`music.xxx.php?msg=`）—— 无维护者、平均几个月失效，
  而且绕的就是平台 DRM，写进源码是开源/比赛的硬伤。**否掉**。
* `NeteaseCloudMusicApi` 及其 fork —— 原版作者**主动删库停更**
  （README 只剩"保护版权，此仓库不再维护"）。**否掉**。
* **yt-dlp** —— 官方维护、发版极勤，`netease:*` / `qqmusic:*` 是一等公民 extractor，
  平台改版有整个社区一起修。**选它**。

## 1. 装 yt-dlp

本项目不代管这一步。三种方式任选：

```bash
pip install -U yt-dlp        # 装成模块，会进 PATH
winget install yt-dlp
# 或直接下 yt-dlp.exe 丢进任意目录
```

装完**让它能被找到**：放进 `PATH`，或设环境变量 `VM_YTDLP` 指到可执行文件的完整路径。

> 本机（✅2026-09-27 实测）：`yt-dlp 2026.03.17`，在
> `%LOCALAPPDATA%\Packages\PythonSoftwareFoundation.Python.3.13_...\Scripts\yt-dlp.exe`，
> 已能被自动发现，`VM_YTDLP` 不用设。

**平台一改版旧版本就会认不出链接**，所以偶尔 `yt-dlp -U`。这是选它的代价，也是它的优点来源。

> `-x --audio-format mp3` 的**转码依赖 ffmpeg**。本机已在 PATH（WinGet 装的 9.0 full build）。
> 缺了不会报错，只是产物会保持原容器（`.m4a` / `.webm` 等）—— 上游照样能吃，不影响翻唱。

## 2. 登录态（QQ 音乐、部分网易云曲目**必需**）

### 为什么需要

QQ 音乐几乎全曲库都要登录态才发音频流。实测报错原文是：

```
ERROR: [qqmusic] 0023jgxa0Ym5yo: This video is only available for registered users.
Use --cookies-from-browser or --cookies for the authentication
```

注意是 **registered users（注册用户）**，不是 VIP —— **免费账号通常就够**，
128kbps 也能拿去跑人声分离。所以"要登录"不等于"这首歌要付费"。

**默认是匿名请求**：不配下面任何一个环境变量，就发匿名请求。
读浏览器 cookie 库是侵入性操作，这个插件是"外部工具桥"，不该顺手摸用户的浏览器凭据。

### 做法 A（推荐）：导出 cookies.txt

1. 浏览器装一个能导出 Netscape 格式 cookies.txt 的扩展（搜 `Get cookies.txt LOCALLY`
   这类本地导出的，别用把 cookie 传上云的那种）；
2. **先登录**该音乐站点，再在站点页面上导出 `cookies.txt`；
3. 设环境变量指过去，**重启后端**：

```bash
VM_YTDLP_COOKIES=D:\somewhere\cookies.txt
```

配完后在「在线扒歌」页点**「重新检测」**，环境卡上会显示"登录态 cookies 文件" ——
不用靠"再拉一次看看"来验证。

### 做法 B（图省事）：让 yt-dlp 自己读浏览器

```bash
VM_YTDLP_COOKIES_BROWSER=edge      # 或 chrome / firefox
```

**但 Windows 上这条路经常不灵，原因是环境而不是代码**（✅2026-09-27 本机逐条复现）：

| 浏览器 | 报错 | 原因 |
|---|---|---|
| Chrome | `Failed to decrypt with DPAPI` | Chrome ≥ v127 启用 App-Bound Encryption（yt-dlp issue #10927） |
| Edge / Chrome | `Could not copy Chrome cookie database` | **浏览器还开着**，sqlite 库被独占锁（issue #7271） |

而且本机 Edge 的 `Local State` 里确认有 `app_bound_encrypted_key`
（✅ 实测读出来的，即已启用 ABE），所以**即使把 Edge 完全退出，也未必读得出来**。
结论：**做法 A 才是稳的**，B 只当"反正刚好能用"。

两个都配时**以文件为准**（文件是确定性的）。文件配了却不存在 → 直接报错，
不会静默退回匿名（静默忽略的后果是用户以为配好了，然后拿着"要登录"的报错反复试）。

## 3. 分享链接会被**规范化**（"粘进去没反应"的头号原因）

从 App 点「分享」得到的链接，经常**不是** yt-dlp 认的那个地址。
2026-09-27 用用户给的真实链接实测（QQ 音乐《唯一》）：

```
用户粘的   https://c6.y.qq.com/base/fcgi-bin/u?__=yY3vbmLH9kYO
  ↓ 302（在服务端跳，用户看不见）
跳到       https://i2.y.qq.com/n3/other/pages/playsong/index.html?songmid=0023jgxa0Ym5yo
  ↓ 再跳
最终       https://y.qq.com/n/ryqq_v2/songDetail/0023jgxa0Ym5yo
           ↑ yt-dlp 报 `Unsupported URL` —— 它只认旧的 /n/ryqq/songDetail/<mid>
```

所以"没反应"里有一大类**不是版权问题，是地址形式问题**。
`normalize()` 的做法：从链接里抠出稳定 ID（QQ 的 `songmid`、网易云的 `id`），
再用 ID **自己拼**官方规范地址。

| 你粘的 | 交给 yt-dlp 的 |
|---|---|
| `c6.y.qq.com/base/fcgi-bin/u?__=…` | `y.qq.com/n/ryqq/songDetail/<mid>` |
| `i.y.qq.com/v8/playsong.html?songmid=<mid>` | 同上 |
| `y.qq.com/n/ryqq_v2/songDetail/<mid>` | 同上 |
| `music.163.com/#/song?id=…` | `music.163.com/song?id=…` |
| `y.music.163.com/m/song?id=…` | 同上 |
| B站 / FMA / Jamendo 的链接 | **原样**（没有 ID 规则就不动它，改了反而可能改坏） |

界面在结果里会显示**实际解析到的地址**（只在与你输入不同时出现），
这样"这条链接为什么行/不行"一眼可见。

### 顺带扩了站点白名单

QQ 音乐的短链域是 `c1~c9.y.qq.com`，逐个列举没有出路。
所以白名单从"精确主机名"扩成了**精确 + 点号锚定的域名族**：

```python
host == "y.qq.com" or host.endswith(".y.qq.com")
```

点号锚定是这里**唯一的安全性质**：`.y.qq.com` **不**匹配
`y.qq.com.evil.example`（买个子域就能绕过的经典写法），也**不**匹配 `noty.qq.com`。
回归测试 `test_host_match_is_exact_not_prefix` 显式钉住这几种伪装。

### 安全边界（改这块之前先读）

* 短链解析是**唯一**会发 HTTP 的地方，且只在**入参 host 已过白名单**后才可能触发；
* 跳转目标**绝不会**被直接交给 yt-dlp —— 只用它抠 ID，再用 ID 拼自己构造的地址。
  否则白名单就等于让给了任意服务端重定向（在任意放行站点上找个开放重定向即可绕过）；
* 抠出来的 ID 字符集本身就是安全性质（排掉 `/` `.` `?` `#` `%`），
  那是本模块唯一手工拼字符串的地方。

## 4. 其它边界

* **随用随删**：产物由 `-P` / `-o` 钉死在 `<OUTPUTS_DIR>/.session`，
  退出即清。`_cleanup` 只删**本轮** `stem` 前缀，绝不删整个会话目录
  （那里面有用户刚下好、还没跑翻唱的歌）。
* **产物定位要按 stem 过滤**：会话目录里可能躺着上一次刚扒好的歌。
  扫全目录的话，"这次什么都没产出"会被上一次的残留伪装成成功 —— 用户拿到的是
  **上一首**，而且他多半发现不了。连着扒两首时必现。
* **单曲语义**：粘歌单 / 合集链接只会取第一首（`--no-playlist`）。
* **法律**："中文歌多 + 曲库全 + 免费 + 合法"是不可能三角，必须选一边放弃。
  本项目的取舍是：工具中立、用户自装、仓库干净，**使用边界由用户自己承担**。
  付费/会员曲目拿不到音频流是**正常结果，不是故障**。

### 取回可以停（2026-09-27 起）

改之前的样子：`subprocess.run(timeout=600)` —— 粘一条坏链接，界面只能干等
"取回中…"最长十分钟，用户唯一能做的是**关页面**，而后台 yt-dlp 还在跑；
而且 `run` 的超时只 kill **直接子进程**，yt-dlp 拉起的 ffmpeg 会变成孤儿
继续往会话目录里写。现在三条一起管住了：

| 出口 | 怎么触发 | 行为 |
|---|---|---|
| **取消** | 界面上的「取消」按 | 先叫后端取消（`POST /api/ytdlp/fetch/{job_id}/cancel`），再 abort 本地请求 |
| **关页面** | 用户直接关掉/刷新 | HTTP 连接断 → 后端把同一个作业取消掉，**不会**在后台把歌拉完 |
| **卡住** | 连续 90s 一行输出都没有 | 中止，报"判定卡住了"（与"超时"分开：两者要做的事不一样） |
| **超时** | 墙钟 600s | 兜底上限，报"N 秒没拉完" |

前两条都走同一条路：**按进程树杀**（Windows `taskkill /F /T`，POSIX `killpg`），
然后带重试地清掉本轮 `stem` 前缀的半截文件 —— 刚被杀的进程持有的句柄不是立刻
释放的，一次 `unlink` 常撞 `WinError 32`。

进度：`GET /api/ytdlp/fetch/{job_id}` 会返回 `{stage, percent}`（界面按秒轮询）。
`percent` 为 `null` 表示"还没读到进度行"，界面**不会**显示成 0% —— 那是
"一点没下"的意思，不是"还不知道"。

## 5. 会员曲兜底：从官方 MV 抽音轨（`VM_MV_FALLBACK`，**可选，默认关**）

### 它解决的问题

QQ 音乐有一部分曲子是**会员曲**，`vkey` 接口对它们返回 `purl` 空 +
`fnameHitCa`（`Ca` = Copyright authority，版权授权不通过）。实测证据
（2026-09-27，《唯一》= `0023jgxa0Ym5yo`）：

```
pay_play=1  pay_month=1  price_track=200  pay_status=0    ← 会员曲
匿名 vkey        → purl 空
配了真登录态 vkey → 仍 purl 空（Ca）
24 种 filename × platform 组合穷举 → 全部 purl 空
```

也就是说：**这不是"缺登录态"，是账号没有这首歌的授权**。配 cookies 也解决不了。
yt-dlp 在这条路上只能报 `No video formats found!`。

### 怎么绕过去的

用户给了关键线索：**QQ 音乐的 MV 网页一直是免费能看的**。顺着实测下来：

| | 歌曲音频接口 | MV 播放页 |
|---|---|---|
| 端点 | `vkey.CgiGetVkey` | 页面内部吐的 `.m3u8` / `.ts` |
| 匿名结果 | `purl` 空 / `fnameHitCa` | **200，直接出流** |
| 要登录态吗 | 要（会员曲还要 VIP） | **不要** |
| 文件本身 | 加密（mflac/mgg） | **明文 MPEG-TS** |

链路（`m2_server/mv_audio_fallback.py`）：

```
get_song_detail 拿关联 vid  →  浏览器打开 y.qq.com/n/ryqq/mv/<vid>
  →  截 .m3u8 索引 + 全部 .ts 分片  →  按序合并  →  ffmpeg -vn -acodec copy
```

实测《唯一》：27 片 / 36.38 MB / 720p / 271.2s，抽出 **192 kbps AAC 完整音轨**。

### ⚠️ 音质代价（必须让用户知道）

**MV 音轨 ≠ 唱片母带。**

* MV 抽出来是 **192 kbps AAC**；正版音源是 **FLAC 无损（~1000 kbps）**，差 5 倍。
* MV 音轨混了**影像的声音设计**（环境声、镜头切换的气口），可能带画面声。

**做粗料够用，做音源不够。** 所以兜底成功时接口会返回 `via: "mv_fallback"` +
`quality_note`，界面用琥珀色告警条显示 —— **不能让兜底产物看起来和正版音源一样**。

### 怎么开

```bash
# Windows PowerShell（临时，只在当前会话生效）
$env:VM_MV_FALLBACK = "1"

# 或写进后端启动环境（持久）
```

依赖三样，缺一样就用不了（`status` 接口会报出来）：

| 依赖 | 说明 |
|---|---|
| `node` | 驱动浏览器。找不到走 PATH |
| `playwright-core` | 默认猜 `<repo>/web/node_modules/playwright-core`；可用 `VM_PLAYWRIGHT_CORE` 指 |
| `ffmpeg` | 抽音轨。可用 `VM_FFMPEG` 指 |

查当前状态：

```bash
python m2_server/mv_audio_fallback.py status
```

### 三条刻意守住的边界

1. **默认关**。这是"绕平台会员授权"的取音路径，与 `VM_YTDLP_COOKIES` 同一口径：
   用户自己开、自己承担使用边界。
2. **只对 `y.qq.com` 生效**。别家没有等价的免费 MV 通路，误触发等于乱发请求。
3. **独立成模块，不进 `ytdlp_fetch`** —— 那个模块"没有一行绕 DRM 的代码"是
   刻意维持的性质（比赛/开源脱敏时这块天然干净）。

### 兜底的语义是"多做一次尝试"

* 只在 **yt-dlp 失败之后**跑。主路成功时不碰它（否则每首歌白抓一次 MV）。
* 自己失败**不盖掉 yt-dlp 的原话**。用户能行动的是"配登录态 / 换来源 / 升版本"，
  那些都在 yt-dlp 的归因里；兜底的失败原因（没关联 MV / 抓不全）对他没用。
* 任何意外都不外溢成 500。

### 改这块之前先读：四个实测踩过的坑

| 坑 | 现象 | 正确做法 |
|---|---|---|
| **分片 URL 完全相同** | 用 `Map<url, body>` 收 → 被覆盖成 1 片，合并出来只有 387KB | 必须用**数组按到达顺序**收 |
| **直链是一次性签名路径** | 每次刷新 m3u8 前缀都不同（`15541F1F…` / `0A9C88EC…` / `5B6B0D92…`） | **抓到就立刻下**，不能先存 URL 再排队 |
| **分片是惰性加载的** | 只播开头 → 只拿到开头几片，**静默**产出截断的歌 | 先读 m3u8 数 `#EXTINF` 行数当预期，不足即失败 |
| **MV 接口显式调用要鉴权** | `MV.getMVUrl` 返回 `860100005` / `860100001` | 别走 API，走**播放页**（页面内部那条路不校验） |

★ 第三条尤其要紧：**给用户一首被截断的歌，比明确告诉他"没抓全"糟得多** ——
他可能拿去跑完翻唱才发现少了尾部。所以 `_grab_mv` 用"片数"把关，
`fetch_from_mv` 再用"时长"把关（第二道，容忍 3s —— MV 的音频流本就比视频流略短）。

## 6. 拉不动时按这个顺序查

```bash
# ① 工具在不在、什么版本、登录态配了没（只读、不联网）
python m2_server/ytdlp_fetch.py probe

# ② 这条链接会被改成什么、属于哪个站点（不跑 yt-dlp、不落盘）
python m2_server/ytdlp_fetch.py resolve "https://c6.y.qq.com/base/fcgi-bin/u?__=xxxx"

# ③ 真跑一次，看点名的人话报错
python m2_server/ytdlp_fetch.py fetch "https://c6.y.qq.com/base/fcgi-bin/u?__=xxxx"

# ④ 会员曲兜底：开关状态 / 这首歌有没有关联 MV / 单跑一次兜底
python m2_server/mv_audio_fallback.py status
python m2_server/mv_audio_fallback.py vid 0023jgxa0Ym5yo
python m2_server/mv_audio_fallback.py fetch 0023jgxa0Ym5yo
```

对照表：

| 报错 | 下一步 |
|---|---|
| `暂不支持 <host>` | 站点不在白名单。用该站**分享出来的歌曲链接**，或走「翻唱」页的上传/粘直链 |
| `没找到 yt-dlp` | 见第 1 节 |
| `要给登录态才发音频流` | 见第 2 节（做法 A）。若是**会员曲**，配了也拿不到 —— 见第 5 节 |
| `yt-dlp 认不出这条链接` | 先 `yt-dlp -U`；还不行就是这种页面形式它还没支持 |
| `跑完了但没拿到音频文件` | ①未配登录态 ②付费/独家曲 ③平台改版，升级 yt-dlp。QQ 音乐的会员曲可开第 5 节的兜底 |
| `yt-dlp 超过 N 秒没拉完` | 网络慢或歌太大；重试即可 |
| `连续 90 秒没有任何输出，判定卡住` | 这条链接对应的取流挂了。换条链接，或走「翻唱」页的上传/粘直链 |
| `已取消取回（yt-dlp 已中止…）` | 用户按的取消，**不是故障**；界面只给一句确认，不弹红条 |
| `MV 兜底没开启` | 见第 5 节；用 `VM_MV_FALLBACK=1` 打开 |
| `这首歌在 QQ 音乐没有关联的官方 MV` | 这条兜底走不通，换一首或换来源 |
| `MV 分片没抓全（拿到 N/M 片）` | 网络慢或视频较长；稍后重试，一直不行就换来源 |
| `抽出来的音轨只有 Ns，MV 本身是 Ms` | 同上（这是第二道完整性把关） |
