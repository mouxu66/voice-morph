## P0 · 数据丢失：一键安装可静默覆盖已有音色权重（含自训产物）

- 提交：`a8b90f3`（安装编排）+ `d1a9b4c`（下载核心）
- 文件：`m2_server/market_install.py::_stage()`、`m2_server/market_api.py::market_install()`、
  `web/src/pages/VoiceMarket/VoiceMarketPage.tsx:395`
- 原因：`voice_id` 只做字符集校验（`^[A-Za-z0-9_\-]{1,64}$`），**不检查目标是否已存在**。
  `_stage()` 用 `shutil.copy2` 直接覆盖
  `RVC_ROOT/logs/<id>/<id>.pth`（自训实验目录）与 `RVC_ROOT/assets/weights/<id>.pth`。
  前端仓库文件面板允许手填 `idPreview` 作为 voice_id，而已装判断
  （`p.installed.includes(idPreview)`）只查 RVC logs/assets，**查不到 voicebank 里的自训音色**。
- 影响：填 `kangaroo` 安装任一市场音色，即**无备份、无确认地覆盖自训袋鼠权重**；
  同名重装不同版本/换源也会直接替换。属于不可逆数据丢失。

## P1 · 安全：下载域名白名单被 302 重定向绕过（SSRF + 任意内容落盘）

- 提交：`d1a9b4c`
- 文件：`m2_server/market_download.py::_download_to()`（`requests.get(..., allow_redirects=True)`）
- 原因：`_validate_url()` 只在 `start()` 里校验**初始 URL** 的 host；下载时允许跟随重定向，
  重定向后的目标 host 不再校验。白名单内任一 URL（含攻击者可控制的 HF/魔搭内容、
  或开放重定向端点）可 302 到 `127.0.0.1`、`169.254.169.254`、内网任意地址。
- 影响：`allow_loopback=False` 的护栏形同虚设；响应体会被当作权重写入
  `outputs/market/*.pth`，并可经安装流程拷贝进 RVC 目录。既是 SSRF 探测面，
  也是"不可信内容落盘"入口。

## P1 · 安全：无鉴权 + CORS 通配，任意网页可调用破坏性接口

- 提交：`c3ed853`（扩大删除面）、`a8b90f3`（新增安装端点）、既有配置
- 文件：`m2_server/config.py:65`（`VM_CORS_ORIGINS` 默认 `*`）、
  `m2_server/server.py:66-97`（未设 `VM_API_TOKEN` 时**完全不安装鉴权中间件**，且回环永远放行）
- 原因：默认部署下任何网页可用 `fetch` 命中本机 API；`allow_methods=["*"]` 使 DELETE 的
  预检也放行。
- 影响：`DELETE /api/voicebank/{id}` 可远程删音色——而 `c3ed853` 把删除回退面从 voicebank
  扩大到 `RVC_ROOT/logs/<id>`（训练产物、语料），破坏面显著变大；另有
  `POST /api/market/install`（触发下载 + 覆盖，见 P0）、`POST /tts`（打满显存）。

## P1 · 安全：第三方 `.pth` 反序列化缺显式约束，且无任何权重合法性校验

- 提交：`a8b90f3`（安装落位）、既有 `m2_server/offline_vc_infer.py:60`
- 原因：市场下载的权重经 `_stage()` 直接进 RVC 目录，由
  `torch.load(args.pth, map_location="cpu")` 加载，未显式声明 `weights_only`；
  下载层又不做 Content-Type / 魔数校验（404 HTML 页面也会当权重落盘），
  `sha256` 与 `expected_size` 均为可选。
- 影响：当前 torch 2.9.1 默认 `weights_only=True`，暂缓解 RCE，但（a）换到旧 torch 即成
  任意代码执行；（b）第三方 RVC ckpt 常含自定义 config 类，加载会直接
  `UnpicklingError` → 装了也用不了；（c）装到坏文件（HTML）时故障点后移到推理阶段，难排查。

## P1 · 逻辑：SHA256 校验与"镜像回退 / 续传"互斥，校验必失败

- 提交：`d1a9b4c`
- 文件：`m2_server/market_download.py::_run()`
- 原因：`hasher` 在下载前先把已有 `.part` 字节吞入；主源中途失败 → `part.unlink()` 从头重下，
  但 **hasher 未重置**，最终 digest = 旧字节 + 新字节。另一条：服务端不支持 Range（返回
  200 而非 206）时以 `"wb"` 重写文件，却仍沿用含旧 `.part` 内容的 hasher。
- 影响：任何带 `sha256` 的任务一旦触发回退或服务端不返回 206，就必然 `SHA256 不符` 失败。
  前端文件面板安装路径会传 `pickPth.sha256`（VoiceMarketPage.tsx:395），路径可达。

## P1 · 逻辑：同名任务"幂等"返回 done，会静默安装上一次的旧文件

- 提交：`d1a9b4c` + `a8b90f3`
- 文件：`market_download.py::start()`（`if dest.exists(): self._state = {"idle": True, ...}`）、
  `market_install.py::_download_wait()`（`if st.get("status") != "downloading": return`）
- 原因：`outputs/market/<id>.pth` 已存在时 start 直接返回完成态，安装流程跳过下载继续 stage。
- 影响：（1）换源 / 换版本重装同名音色 → 装回旧文件；（2）该分支把整个 state 重置为
  `{idle, done_file}`，**install 段丢失**，`/market/progress` 返回 `{"task": null}`，
  前端进度面板空白。

## P1 · 逻辑：`/market/cancel` 在"无进行中任务"时返回 200 而非 409

- 提交：`a8b90f3`（把 cancel 从 `get_manager().cancel()` 改为 `get_installer().cancel()`）
- 文件：`m2_server/market_install.py::InstallManager.cancel()`、`market_api.py::market_cancel()`
- 原因：install 段残留（如 `cancelled`/`interrupted`）时不抛错，会继续把 install 段改写成
  `cancelled` 并返回 200。
- 影响：接口契约与前端错误提示不一致（前端按异常提示"取消失败"），
  并被下面的测试失败直接暴露。

## P2 · 自动同步的镜像删除可能清空分发副本

- 提交：`693fa94`
- 文件：`m2_server/backend_autosync.py::sync_backend_copy()`
- 原因：镜像语义会 `unlink` 副本中源里不存在的文件；若 `web/dist` 构建失败/被清空
  （vite build 中断），同步会把 `resources/backend/web_dist` 一并清空；
  同步在 daemon 线程执行，与可能正在运行的副本进程无锁竞争。
- 影响：分发版前端白屏；副本被占用时复制失败只记 warning，副本可能长期处于半更新态。

## P2 · 下载大小上限可被绕过（流式写入无实时拦截）

- 提交：`d1a9b4c`
- 文件：`market_download.py::_download_to()` / `_run()`
- 原因：`_download_to` 的大小检查仅依赖 `Content-Length`（`if total and ...`，且算式
  `(total - offset) + offset` 等价于 `total`，属冗余写法）；无 Content-Length 的
  chunked 响应只能等 `_run` 里 `size > MAX_BYTES` 事后判断，届时 500MB+ 已落盘。
- 影响：异常/恶意大响应可把磁盘写满，且失败后清理滞后。

## P2 · 音频后处理响度回归风险

- 提交：`2dcbfd4`
- 文件：`m2_server/offline_vc_infer.py::postprocess_audio()`
- 原因：先按 RMS 锚定 -18 dBFS，再按峰值"只衰减"到 -1.5 dBFS；单个瞬态尖峰会把整段

- 影响：批次间响度不一致（有的很响、有的很轻）；既有测试只钉死"不削波"，未覆盖响度一致性。
