## 怎么用（人读和 AI 读是同一套）

1. **先匹配症状**：在 §一 的「症状」列找你手上那个现象 —— 表按撞见频率排，越靠前越常撞。
2. **再照「对策」做**：对策列直接给命令 / 常量 / 改法；结尾的 `§N.M` 是完整复盘的位置。
3. **要动代码前**：过一遍 §六 的清单。
4. **改完不生效**：先跑 §七 的诊断命令，再回头看 §3.1（没落盘）与 §3.2（双验证）。
5. **表里查不到**：去两份档案按 `§` 翻，或 `git log -S"关键词" -- docs/` 找历史结论。

### 3.1 编辑工具报"成功"，但代码没落盘 ✅ ← 本战役最贵的坑

Edit 返回 "Successfully edited"，文件里却还是旧逻辑。**代价**：后续 5~6 轮排查全建立在错误前提上
（依次错误归因为"窗口穿透样式""窗口被移走""声卡时序""时长限制"，逐个 A/B 排除）。

**破案手段**：给调用链打点，发现 `mouse_left` 之后没有配对的 UP ⇒ 立刻明白跑的是旧代码。

```python
import inspect, sys
sys.path.insert(0, 'm2_server')
import wechat_voice as wv
print(wv.__file__)                                    # 确认加载路径
print('单击 UP :', '单击' in inspect.getsource(wv._trigger_record))
print(inspect.getsource(wv._trigger_record)[-700:])    # 直接看运行时的源码
```

### 3.2 铁律：改完关键逻辑，立刻双验证

```bash
# ① 落盘验证：搜你新写的那句注释/常量，必须能搜到
grep -n "单击（DOWN+UP 短按）" m2_server/wechat_voice.py

# ② 运行时验证：确认 Python 实际加载的是这份文件、且函数体里有新代码
CODEBUDDY_SAFE_DELETE_ENABLED=0 .venv/Scripts/python.exe -c "

```

并且 `ls m2_server/wechat_voice.py wechat_voice.py` 确认**不存在同名模块** —— 同名文件在不同目录
会让 `import` 加载到错的那份（本项目 `m2_server` 各目录无 `__init__.py`，`tests/` 已踩过一次）。

### 3.3 "脚本说 ok 但实际没成功"——必须有人工/截图复核

`outcome=ok` 只代表**代码路径走完**，不代表微信真收到了。判 ok 的必要条件（缺一不可）：

1. `steps` 里出现"已点 ↑ 绿钮发送"这类终态；
2. 截图里聊天区**新出现一条语音气泡**，时长 ≈ 音频 + 1s；
3. `_find_green_send(r, retries=1)` 返回 `None`（浮层已消失 = 没有挂起录音）。

### 3.4 单元测试必须跟实现同步，别"改完不补测"

逻辑从"按住"改"单击"后，`test_wechat_record.py` 有 3 个用例挂了 —— **这是好事**，测试正确捕捉到了
行为变更。改测试时同步更新注释里的机制描述，别让测试变成"只描述旧行为的化石"。

### 3.5 测试/构建必须关掉 safe-delete shim

```bash
# python 侧（pytest）
CODEBUDDY_SAFE_DELETE_ENABLED=0 .venv/Scripts/python.exe -m pytest m2_server -q
# node 侧（前端构建）—— 摘 NODE_OPTIONS，且必须摘在子 shell 里
(unset NODE_OPTIONS; npm run ship)
```

不关会出现：pytest 随机挂几个（每次数量不同、单文件跑却全绿）、`vite build` 直接失败。
shim 把 `shutil.rmtree` / `fs.rmSync` 包成"移回收站" → 触发 bulk guard。两侧注入方式不同：
python 走 `PYTHONPATH`，node 走 `NODE_OPTIONS=--require=…`。

⚠️ **别写 `env -u NODE_OPTIONS npm run ship`**：本机 Git Bash 下它**静默失效**（退出码 0、无输出、
`dist` 纹丝没动）。清就清在子 shell 里（`docs/犯错档案-工程.md` §8.68）。

### 3.6 相对路径 vs 项目路径

`tools/tts_and_send.py --wav tts_xxx.wav` 传相对文件名时前端显示 `0.00s` —— 它按 cwd 找文件，
而产物在 `outputs/`。**修复**：统一走 `cfg.OUTPUTS_DIR` 解析（commit `5dd1fdf`）。同类：
`_do_send` 也用 `cfg.OUTPUTS_DIR` 拼路径，直接调它时必须传绝对路径或相对 `outputs/` 的正确相对名，
否则得到"找不到音频"的 500 而不是真实错误。
