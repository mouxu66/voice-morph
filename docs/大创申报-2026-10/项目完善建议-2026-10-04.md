## 二、🔴 缺口①：录音→四档 的链路没闭合（**这是最该先修的**）

### 2.1 问题（实测确认）

评测协议的核心定义是：**四档 = 同一段录音的前缀截取**（控制人/麦/房间不变）。
但现在的代码是：

```python
# m2_server/voicepreserve.py:435
def add_reference(pid: str, src: Path, duration_s: float) -> dict:
    ...
    dest = profile_dir(pid) / "refs" / f"{tag}.wav"   # 每次存一档
```

**调用方（前端）要先选档、再录一档** —— 也就是**录 4 次**（`usePreserve.ts:31` 注释也承认了
"录音目标档先选、再录"）。

★ **这与协议直接冲突**：协议要求"**一次录制，前缀切四档**"，
而现在的实现是"**录四次，每次一个档**"。两者的差别是致命的：

| | 协议要求（前缀截取） | 现状（分 4 次录） |
|---|---|---|
| 说话人 | 同一人 | 同一人 ✅ |
| 麦克风/房间 | 同一条件 | 可能同一 ✅ |
| **录音的"那一条 take"** | **同一条** | ❌ **4 条不同 take** |
| 结论可信度 | ✅ 可归因于"时长" | ❌ **混淆了"这次录得好不好"** |

**为什么必须修**：申报书里已经写明"**同一段录音的前缀截取**"，如果实际执行是录 4 次，
**等于自变量定义与执行不一致** —— 评审或论文审稿人一问就穿。
而且 `voicebank_eval.py` 的 `measure` 期望的是 `refs/<说话人>/<档>.wav` 四个文件
（`build_matrix` 里 `"ref": f"refs/{sp}/{tag}.wav"`），**恰好就是"切好的四档"** ——
说明**评测引擎的设计是对的，只是 preserve 侧少了一步"自动切档"**。

### 2.2 ✅ 已实现（本轮完成）

**后端 `m2_server/voicepreserve.py`**：新增 `add_reference_batch(pid, src, durations=None)`
- 先整体转一次 wav（复用 `_to_wav`）→ 读实际总时长 → 对每档 ffmpeg 切 `[0, N]`；
- **总时长不足最高档直接报错**（`error_stage="时长不足"`，并告知差多少秒），
  **不产生半套数据** —— 缺一档的矩阵在 `analyze` 里会变成"数据不足以判定"，
  而用户以为自己录完了，错因会指向统计而不是采集；
- 复用"同档替换"语义（重录一次 = 四档全替换，不产生 8 条 refs）；
- 源文件切完即删（不留冗余未切分录音）；
- 落一条 `add_reference_batch` 审计事件。

**API `m2_server/voicepreserve_api.py`**：新增
`POST /api/preserve/profiles/{pid}/references/batch`（单文件上传，无 `duration_s` 参数）。
路由声明在 `/references` **之前**，避免被 `{pid}/references` 先匹配。

**前端**：
- `web/src/api/client.ts::uploadPreserveReferenceBatch()`（内联 URL 字面量，
  满足 `tools/audit_endpoint_ownership.py` 的 AST 归属检查）；
- `usePreserve.ts::startFullRecording()`；
- `PreservePage.tsx`：录音卡片顶部新增**推荐路径**「一次录满，自动切出四档」
  （最高档从后端 `guide.durations` 现算，**不写死 60** —— 档位口径只有一份定义）。

**测试**：`test_voicepreserve.py` 新增 7 条（`TestBatchReferenceSlicing` 5 条 + API 2 条）：
一次录 65s 切出恰好四档且实际时长贴合标称 / 录 20s 报 `时长不足` 且不留半套 /
重录替换不追加 / 非法档案与空文件 / 审计事件 / HTTP 200 与 400 两条。

**验收**（可复跑）：
```bash
CODEBUDDY_SAFE_DELETE_ENABLED=0 .venv/Scripts/python.exe -m pytest \
  m2_server/tests/test_voicepreserve.py -k batch -q     # 7 passed
.venv/Scripts/python.exe tools/audit_endpoint_ownership.py   # 未定位函数 0 个
cd web && npx tsc -b && npx vitest run src/pages/Preserve      # 12 passed
```

> 原来的建议写法（保留作参考）：
> 加一个"一次录音 → 前缀切四档"的入口，不要改现有 `add_reference`（它有独立用途）：

```
新增： m2_server/voicepreserve.py::add_reference_batch(pid, src, durations=None)
  1. src 转 wav（复用现有 _to_wav）
  2. 读实际总时长 _wav_seconds
  3. 对每个 duration_s：ffmpeg 切 [0, duration_s] → refs/<tag>.wav，调 add_reference 落档
  4. 总时长 < 最大档（60s）→ 明确报错，不静默切短
  5. 落一条 events.jsonl（记录源文件 + 实际总时长，便于追溯）

前端 PreservePage：把"选档→录一档"改成
  「一次录到 ≥60s（脚本约 20 句 / 91s 容量）」→ 上传 → 后端自动切四档 → 显示四档时长核对表
```

**验收标准**（写死，别靠感觉）：
- 上传一段 65s 录音 → `refs/` 下**恰好 4 个** wav（3s/10s/30s/60s）；
- 四档的 `actual_s` 与标称值误差 ≤ 0.2s（`_wav_seconds` 已有）；
- 总时长不足 60s → **返回明确错误**，不产生半套数据；
- 测试：`test_voicepreserve.py` 补一条"一次上传切四档"的用例（含不足 60s 的失败路径）。
