## 二、SaMoye 这条线：论文已撤稿（★ 最该先知道的事）

- **arXiv:2407.07728 已被作者撤稿**：v5（2024-11-15）状态为 *withdrawn*，
  撤稿附言 `This paper needs major changes for resubmit`，作者 **Le Ma** 本人提交。
  v4 的 Comments 里也已写着 `This paper needs major changes for resubmit`。
  → 摘要页原话：*"We propose the first open-source high-quality zero-shot SVC model
  SaMoye that can convert singing to human and non-human timbre."* 这句**从未过审**。
  📚（<https://arxiv.org/abs/2407.07728>，本机实测页面状态）
- **它的「能转动物音色」正是我们想要的场景**（论文摘要明确写 *even under extreme
  conditions like converting singing to animals' timbre*，官方 demo 用猫/狗参考音）。
  但撤稿 + 我们实测 `sim_ref 0.19~0.31 / sim_src 0.27~0.33`（分离度 ≈ 0，见实验快照）
  两件事指向同一个结论：**这不是我们参数没调好，是该模型的宣称本身没被独立验证。**
  ✅ 本机实测 + 📚
- **模型自身的边界条件**：权重 `sovits_spk_1700h_0020.pt` 训练于
  **1815 小时纯歌声 / 6367 说话人** —— 全是**人类**歌手分布。
  拿它转「袋鼠」（非人、且参考音仅 3.08s / 134.7Hz 说话）属于论文里最极端的边界情形，
  官方那几条「狗唱歌」结果是 cherry-pick 的演示，不是可复现的平均水平。❓
- **许可证**：仓库内 `SaMoye-Model/LICENSE` = **MIT**，但版权头是
  `Copyright (c) 2023 PlayVoice` —— 即从 **whisper-vits-svc** 改来、保留了原作者的版权头。
  ✅ 本机实测（`samoye_svc_repo/SaMoye-Model/LICENSE`）
- **同世代生态状态**：`so-vits-svc` 官方仓库已 **archived / 停止维护**（Hugging Face 镜像页
  自述 "officially discontinued for maintenance and Archived"）；whisper-vits-svc 同为
  2023 世代老仓。这一代 VITS-SVC 的社区共识是「**有目标说话人训练数据才靠谱**」，
  零样本属勉强可用。📚

> **行动判断**：SaMoye 不值得继续投入。它的参考实现连作者自己都撤回了。

## 三、2026 年的可选项（比我们手上的新一档）

| 模型 | 时间 / 出处 | 许可证 | 为什么值得看 |
|---|---|---|---|
| **SoulX-Singer-SVC** | 2026-03-16 发布 SVC 分支；Soul-AILab | **Apache-2.0（含权重）** | 零样本、**免歌词/MIDI 转写**的 audio→audio，42,000h 对齐歌声（中/英/粤），跨语言；有官方 WebUI（`webui_svc.py`） |
| **HQ-SVC** | AAAI 2026；BUPT（arXiv 2511.08496） | 代码 <https://github.com/ShawnPi233/HQ-SVC> | 专打**低资源**：单张消费级 GPU + 小数据集即可训；论文自称在多数客观/主观指标上超过 SOTA，并把 **SaMoye 列为「需大数据集 + 大量对抗训练、资源昂贵」的对照** |
| **R2-SVC** | arXiv 2510.20677 | ❓ 未查 | 面向**真实世界鲁棒性**（带噪/混响源）的零样本 SVC —— 与我们「扒来的歌干声常有残留」的输入条件对口 |
| **Seed-VC**（现役） | Plachtaa/seed-vc | **GPL-3.0** ✅ 本机实测 | 2024-10-28 更新过 **44kHz 歌声微调模型**；我们已接在产品里，但受 §五 的许可约束 |
| **FreeSVC** | ICASSP 2025，freds0/free-svc | ❓ 未查 | 多语言零样本 SVC，可作对照 |

**技术路线上的关键差别（这才是真正值得我们抄的东西）**：
新一代（SoulX-Singer / HQ-SVC）是**在歌声上做条件建模**（显式 F0 contour / MIDI 条件、
melody-conditioned），而 SaMoye/whisper-vits-svc 这一代是**把歌声硬塞进
「说话人验证式的内容-音色解耦」**里。我们的实验快照第七节已经证明：
参考音只有 134.7Hz 说话、要唱 250~330Hz，是**分布外外推**，不是调参问题 ——
所以「换一条对歌声原生的路线」比「继续扫 shift」在原理上更对路。📚 + ✅ 本机实测

## 四、缺的那个指标：「夹嗓子」的学术名词是 vocal strain

实验快照第三节说「项目里没有任何能测夹嗓子的量」—— 网上有现成口径，而且**本机工具链已就位**。

### 4.1 本机现状（这一条省掉了引依赖的成本）

- `.venv/Lib/site-packages` 里**已经有** `praat_parselmouth 0.4.7`、`pystoi 0.4.1`、
  `librosa 0.10.2`、`torchaudio 2.9.1+cu128`。✅ 本机实测
- `tools/voice_qc.py` **已经在用 parselmouth** 算 F0 中位数（`_F0_SCRIPT`），
  且带「安装版后端可能没装 parselmouth → 回退 RVC venv 子进程」的兜底。
  → 补 HNR / CPP / jitter / shimmer 是**在既有质量工具上接一列**，不是新引一个库。
- `opensmile`（`pip install opensmile`，eGeMAPS v02，88 维）**未装**（✅ 实测 `site-packages` 无命中）。
  它一次调用就能出 `jitter / shimmer / HNR / H1-H2 / 谱倾斜`，是最省事的「一把抓」方案。

### 4.2 学术口径（该测哪几个量）

- **CPP（倒谱峰突出度）**：2025 年的临床嗓音综述把 CPP 列为整体嗓音质量的首选指标，
  并明确指出 **jitter/shimmer 对重度失调会失效**（恰恰是最需要指标的时候）。📚
- **H1–H2（第一、二谐波幅度差）**：语言学界公认的 **phonation type 判据**，
  是**声门开商 OQ 的声学代理** —— 「挤压」（pressed）→ OQ 变小 → **H1-H2 变低、谱倾斜变陡**。
  这是与「夹嗓子」对应最直接的一个量（Kreiman 等，JASA / JSLHR 系列）。📚
- **★ 一篇直接对口的新研究**：*Automatic Prediction of Vocal Strain Scores in Singing
  Voice Using Audio and Electroglottographic Modalities*（JSLHR，2026-09-22 上线，
  Yuanyuan Liu 等）—— 用音频 + EGG 做**歌唱嗓音 strain 分数**的机器学习预测。
  「vocal strain」就是我们口语里的「夹着嗓子 / 用力过猛」。
  📚（<https://pubs.asha.org/doi/10.1044/2026_JSLHR-25-01016>；正文 403，需机构权限，只能读到摘要页）
- **歌声专用的现成 MOS 模型：SingMOS / SingMOS-Pro**（ICASSP 2026，
  `torch.hub.load("South-Twilight/SingMOS:v1.1.2", "singmos_pro")`，16kHz 输入）。
  SingMOS-Pro 数据集 **7,981 条 / 41 个生成模型**，是 2025 年的歌声质量基准。
  它测**自然度**，不测挤压 —— 但正好能抓 **vocoder 伪影 / 电音感 / 闷** 这类「难听」。📚

### 4.3 ⚠️ 别把它当成下一个 CAM++

实验快照第三节的教训（CAM++ 对音高/发声方式失明）**会在这些 MOS 模型上重演**：
它们没被训练去区分「同一个人用力唱」vs「夹着嗓子唱」。正确用法是分层，而不是再找一个标量当终判：

```
对发声方式敏感（排序用）  → CPP、H1–H2、谱倾斜、jitter/shimmer   （praat_parselmouth，已装）
对伪影/失真敏感（兜底用）  → SingMOS-Pro 自然度 MOS              （torch.hub 一行加载）
对「这是谁」敏感（现役）   → CAM++ 余弦                          （已有，只用于排序）
终判                      → 人耳
```

## 五、★ 许可合规：Seed-VC 是 GPL-3.0，且两份外来仓库都没登记

- **`seed_vc_repo/LICENSE` = GNU GPL v3**（✅ 本机实测，读文件确认），
  与实验快照第八节担心的「GPL-3.0 分发合规」完全对应。
- **目前没构成分发**（这一点是好消息，我核实过）：
  `web/package.json` 的 `extraResources` 只含 `dist` / `../m2_server` / `../tools` /
  `requirements.txt` —— **不含 `seed_vc_repo/`、`seed_vc/`、`samoye_svc_repo/`**。
  且项目既有原则（`THIRD_PARTY_NOTICES.md`）正是「**仅以子进程调用、不随包分发、
  不静态链接 → 不构成衍生作品**」（ffmpeg 一栏就是按这条写的）。✅ 本机实测
- **★ 更正（同日晚，用户确认「直接上传 GitHub、完全开源」后复核）**：
  本文档初稿写的是「开源前若把 `seed_vc_repo/` 一起推上 GitHub，GPL-3.0 就跟着走」——
  **这个担心不成立**。实测：`.gitignore:113/114` 已忽略 `seed_vc/` 与 `seed_vc_repo/`，
  且 `git ls-files seed_vc_repo seed_vc` **返回 0 个文件**；仓库里已跟踪的
  `.pt/.pth/.ckpt/.onnx/.safetensors/.bin` 也是 **0 个**。✅ 本机实测
  → **GPL-3.0 引擎与其权重都不会进仓库，不构成分发。**
  同时 `.gitignore` 还忽略了 `tts_models/` `models/` `media/` `outputs/`（59/60/64/65 行）。
- **但换出来两个真缺口**：
  1. **开源用户拿不到引擎**：Seed-VC 那条链路（`m2_server/seed_vc.py` →
     `seed_vc_repo/inference_v2.py`）**在仓库里根本不存在**，而 `seed_vc.py` 的注释
     写的是「权重已缓存在 seed_vc_repo/checkpoints 与 HF 缓存，**无需重下**」——
     这是**按本机已就绪**写的。`tools/setup_env.ps1` 全文对模型只说了
     一句「模型权重（首次使用会自动下载或需手动放置）」（第 198 行）。
     → 新克隆的人开箱跑不起来，仓库缺**一键拉取**（含 Seed-VC 上游的获取方式
     与它自己的 GPL-3.0 提示）。
  2. **来源未登记**：`THIRD_PARTY_NOTICES.md` 里**全文件 grep `seed` 零命中** ——
     Seed-VC、SaMoye 都**没有登记**。`tools/audit_licenses.py` 的门禁盯的是
     **pip 依赖**（`FORBIDDEN` 名单）和**分发目录里的权重后缀**，
     **不覆盖「源码树里 vendored（且被 ignore）的外部仓库」**。✅ 本机实测
     虽然不构成分发，但**使用者要不要装、装哪个版本、受什么许可约束**，
     应当有一处写明。`docs/开源前待办清单-2026-09-12.md` 该补一条。

## 六、没查到 / 查不动的（诚实标注）

- **「SVC 开头 0–20s 固定崩」没有找到公开的已知问题条目**。相近的社区现象是
  so-vits-svc fork 的 issue #1220（2024-07）：*"When the singing transitions to reach
  the powerful passages of the chorus, the transitioned sound loses its power"* ——
  **局部段落的表现力损失**是这一代 VITS-SVC 的通病。❓ 未能证实与我们的开头崩同因。
  → 仍按实验快照第八节第 2 条办：**开头单独查，大概率在素材/条件构造侧**。
- **vocal strain 那篇 JSLHR 正文读不到**（403，需机构权限），只能确认它存在、
  题目与模态（audio + EGG）与作者。它的特征集/结论 **❓ 未验证**。
- **没有任何技术绕得过「参考音分布外」**：所有零样本 SVC 都对参考音的音高/时长/
  发声方式覆盖敏感。想「原调 + 好音色」，最终仍回到快照第八节第 4 条 ——
  **需要一段袋鼠在 250~330Hz 音区的素材**（4.5 分钟说话素材里不存在该音区的证据）。📚

## 七、据此的建议行动（按性价比排序）

1. **横向跑一次新路线**：同一 30–90s 同段源 + 同一参考音，跑 **SoulX-Singer-SVC**
   （Apache-2.0、免转写、有 WebUI），用 **CAM++ + 新补的 CPP/H1–H2** 同口径对比 SeedVC/SaMoye。
   这一步的信息量远大于再扫一遍 shift。
2. **给 `tools/voice_qc.py` 接上 CPP / HNR / H1–H2 / jitter / shimmer**（parselmouth 已在），
   让「夹嗓子」第一次变成可测量的排序量，并落进 `outputs/qc/*.json`。
3. **补登第三方仓库清单 + 补一键拉取**：把 Seed-VC（GPL-3.0）/ SaMoye（MIT，
   版权头仍是 PlayVoice）写进 `THIRD_PARTY_NOTICES.md`（注明**不随仓库分发、需用户自行获取**），

   （权重全在 `.gitignore` 里，零个入库 ✅）。
4. **开头崩单独立项**（与快照第八节一致）。
5. **（终局）录一段 250–330Hz 音区的袋鼠素材** —— 这是唯一能同时拿到「原调」和「好音色」的路。
