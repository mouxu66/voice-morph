## A 档 · 立即做（收益高、成本低）

> 状态：A1 ✅（`eeaaf91`）/ A2 ✅（`4b72755`）/ A3 ✅（`b0960e6`）/ A4 ✅ 均已落地。
> A1 补：权重双份改硬链接（同盘省一份 55–72MB，失败回退复制）。
> A4 明细见 `docs/A4-多链路对比落地说明.md`。

### A1 音色市场：卸载 + 来源标记

- 现状：`market_install.py` 安装时已记 `manifest_id`（溯源字段写进 downloads.json），
  但**没有任何卸载入口**——装完只能去音色库删，删完也不知道它是市场来的；
  `_stage()` 还会把权重写两份（`logs/<id>/` + `assets/weights/`，55–72MB × 2）。
- 建议：新增 `DELETE /api/market/uninstall`（清 logs + weights + `outputs/market` 缓存）；
  安装时落一个 `source.json` 标记来源，音色库卡片显示「市场 / 自训 / 导入」角标，
  市场卡片「已安装」按钮切换为「卸载」。
- 收益：市场从"能装不能管"变成闭环；配合 P0 覆盖修复后可安全反复试装。

### A2 装完自动生成一句试听

- 现状：实测 chaye741 / hudddd 等仓库**都没有演示音频**（只有 weights/indices），
  所以市场页「试听」长期不可用，用户必须装完才知道像不像。
- 建议：安装收尾阶段用固定一句中文合成 3–5 秒样本（复用 `/tts` 或离线变声链路），
  存 `outputs/market/<id>_preview.wav`，市场卡片与音色库共用播放器。
- 收益：直接消除"装了才知道翻车"，是市场转化率的瓶颈项。

### A3 训练前语料体检 + 一键剔除低分切片

- 现状：`clip_qc.py` 已接入 `pipeline_api.py:98` 与 `clips_api.py`，打分与 QC 徽章都在跑，
  但**训练入口没有消费这个分数**：`/ft` 页仍是全量训练，D 级垃圾切片照训。
- 建议：微调页加「语料体检报告」（各等级切片分布 + 预计得分），一键剔除 D/C 级后重训；
  顺带把 ROADMAP 的 P2-1「失败可诊断」落地（依赖 P1-1 打分，现成）。
- 收益：直接命中主线成功率——记忆里 kangaroo 的"鬼叫"根因就是 D 级切片进训。

### A4 多链路 A/B 对比（RVC / Seed-VC / Qwen3）+ 客观分

- 现状：`ab_api.py` 只有 `/ab/run`（两个**音色**、同一句文本对比），前端 `AbCompareCard`
  也只比音色。真正的决策痛点是"同一段输入走哪条链路更像"。
- 建议：扩成"同一输入 × 三条链路"并排试听，`experiments/` 里现成的
  CAM++ SECS + NatScore harness 直接输出客观分，与主观听感同屏。
- 收益：把长期靠人耳挑（袋鼠音色 A/B 试了 8 轮）变成可量化决策。

## B 档 · 顺手做

### B1 作品库：收藏 / 标签 / 批量导出

- 现状：`history_api.py` 只有列表与删除；TTS、离线变声、Seed-VC、有声书、市场试听
  的产物都进 history，但**无法组织**，翻旧产物只能靠时间和文件名。
- 建议：加收藏 + 自定义标签 + 按音色筛选 + 勾选批量打包 zip。
- 收益：低成本，把"用完即弃"的产物变成可复用资产（比赛演示素材也靠它攒）。

### B2 存储占用面板 + 一键清理

- 现状：`system_api.py` 只有 `/health` 与 `/diagnose`；而市场缓存、切片、
  历史产物、QC 缓存、RVC 双份权重各自膨胀，无统一视图。C 盘本就 96% 满。
- 建议：`GET /api/system/storage` 按目录统计占用，设置页展示 + 选择性清理
  （不含 voicebank 与 RVC logs）。
- 收益：防止磁盘被缓存悄悄吃满导致训练/推理失败。

## C 档 · 战略投入

### C1 移动端实时流式链路（MVP 核心，当前最大空白）

- 现状：`mobile/src/api.ts` 全是 REST（cascade/rvcLive/offlineVc/tts），
  `app/(tabs)/vc.tsx` 的交互是"手机录音 → 上传 → PC 转 → 回传播放"（文件级）；
  后端 `cascade_stream.py` 是 **PC 端子进程**（真麦 → VAD → ASR → TTS → 虚拟声卡），
  没有面向移动端的 WebSocket/分片推理端点。
- 建议：后端加 WS 音频流端点（分片 in/out + 会话状态），移动端改成分片推流播放，
  并打点端到端延迟（目标 <200ms）。
- 收益：这是产品与"又一个网页版变声器"的唯一分界线，也是 MVP 定义里的主干。

### C2 TTS 微调支持续训（增量加料）

- 现状：`finetune.py::_train_job()` 组装的训练命令只有 `--train_jsonl / --num_epochs /
  --speaker_name / --output_model_path / --anchor_ref`，**没有 init_model_path 或 resume**
  （而 `sft_12hz_qlora.py` 本身支持 `--init_model_path`）→ 每次加素材都从 base 重训。
- 建议：把 `--init_model_path` 透传，训练页加"基于已有音色继续训练"选项。
- 收益：袋鼠这类小样本音色可以边用边补料，省下反复全量训练的时间（本轮全量 5 分钟，
  但素材增长后成本线性上升）。
