# 真声直讲（真声直通 CABLE）设计

> 2026-10-04 立。**可行性已真机验证通过**（见文末「验证记录」）。
> 目标场景：老师用电脑播 PPT、用电脑麦克风讲课 —— **平时是本人真声**，
> 讲累了按一下热键，**AI 音色替他说一句**，学生那头听到的是**连续混音**。

## 一、为什么需要它（现状缺口）

现有三条链路都**不能**满足这个场景：

| 现有链路 | 做什么 | 为什么不行 |
|---|---|---|
| 实时变声 `sound.rvc-live` | 真麦 → RVC → CABLE | **真声被整个替换成变声音色**，没有"原样直通" |
| 级联 `cascade` | 真麦 → ASR → TTS → CABLE | 同样替换掉真声，且要等 1.5~2s |
| 热键 `Ctrl+Alt+1~5` | 播短语 → CABLE | 只播那一下；**单独用时听到的只有 AI 音**，真声不在里面 |

**全项目搜过 `passthrough` / `dry` / `wet` / `直通` / `原声` —— 真声直通一个实现都没有。**

所以缺的就是：**一条把麦克风原样灌进 CABLE 的常驻通路**，让"真声"和"热键 AI 音"
在 CABLE 里**叠加**，而不是互相替换。

## 二、链路

```
                                    ┌─ 直通流（常驻）：真麦 ──原样──┐
学生 ← QQ/微信 ← CABLE Output ← CABLE Input ← ───────────────────┴─ 混音
                                    └─ 插话流（按热键）：AI 音 ────┘
```

- QQ / 微信把**麦克风**设为 `CABLE Output (VB-Audio Virtual Cable)`
- 学生听到的就是 CABLE 里的**混音结果**（Windows 共享模式自动混音，
  同 `soundboard.py:9` 既有注释所述）

## 三、关键技术约束（★ 全部已实测）

### 3.1 必须用 `OutputStream`，不能用 `sd.play`

**实测数据**（`tools/_probe/passthrough_probe.py`）：

| 位置 | 峰值 |
|---|---|
| 真麦说话 | 0.2469（−12.2 dBFS） |
| CABLE Output 里 | 0.2329（−12.7 dBFS） |
| **传递比** | **0.94（几乎零衰减）** |

但 `sd.play()` / `sd.stop()` 是 sounddevice 的**全局单例**：
起第二路会 **stop 掉第一路**。而现有 `board_worker.py` 用的正是 `sd.play`
—— 它**接不了这个需求**：一按热键就会把老师的真声**掐断**。

→ 直通 worker 必须自持 `OutputStream`，与插话流**各一条流**（已实测可并发）。

### 3.2 设备解析：必须排除 `CABLE In 16 Ch`

照抄 `rvc_live._is_16ch_variant` 的既定规则（2026-09-19 事故）：
`CABLE In 16 Ch (...)` 是同一块 VB-Audio 声卡的**另一端点**，**不在变声链路里**
—— 选中它 = 声音灌进**没人听的端点**，表现为"一切正常但对面听不到"。

### 3.3 与 `rvc_live` / `cascade` 互斥

三者都要占 CABLE 出口。照既有口径（`cascade.py:145`）：
**启动时检查，冲突则 409**，提示"两者都占 CABLE，请先停止"。

### 3.4 后台常驻进程**不要依赖 stdin 判活**

**实测踩坑**：agent 后台跑时 `sys.stdin.readline()` **立刻 EOF**
→ 早期版本在此 `break` → **开流不到 1 秒就自己退出**，
现象是"启动了但用户毫无感觉"。

→ 交互触发一律走**文件触发**（监听触发文件 mtime）或显式 keep-alive 标志。

## 四、模块划分

### 4.1 新增 worker：`m2_server/passthrough_worker.py`

常驻子进程（与 `board_worker.py` 同构，用 RVC venv 的 sounddevice）：

- 启动：解析 CABLE 渲染端（含 16-Ch 否决）、真麦
- 开两条流：`InputStream(真麦)` → 队列 → `OutputStream(CABLE)`
- 行协议（stdin JSON / stdout JSON，**一命令一响应**，照抄 board_worker）：
  - `{"wav": ..., "id": ..., "gain": 0.9}` → 把 wav 叠加到直通流上（**不掐断真声**）
  - `{"stop_clip": true}` → 停掉正在叠加的插话（直通继续）
  - EOF → 退出
- 事件：`{"type":"ready"}` / `{"type":"playing",...}` / `{"type":"error","msg":...}`

### 4.2 新增后端模块：`m2_server/passthrough.py`

- `_spawn/_ensure/_command/_stop` 生命周期，**照抄 `soundboard.py:153-240`**
  （那套已经处理了"死掉的残留重开""管道关闭 ≠ 响应不对"两个坑）
- 环境开关 `VM_PASSTHROUGH=0` → 拒启（测试隔离惯例，conftest 会设）
- 路由（挂在 `sound.tts` 下，与 `voice_phrases` 同域）：
  - `POST /api/passthrough/start` → 启直通；与 rvc_live/cascade 冲突则 409
  - `POST /api/passthrough/stop` → 停直通
  - `GET  /api/passthrough/status` → `{running, device, input_device, pid}`

### 4.3 热键混音路径（★ 关键改动）

`voice_phrases.play_phrase` 目前的出口是 `soundboard._command`（→ `sd.play`）。

改为**按直通状态分流**：

```
直通开着 → passthrough._command({"wav":..., "id":...})   # 叠加，真声不断
直通没开 → soundboard._command({...})                    # 保持现状，零行为变化
```

**这样对现有功能零破坏**：不开直通时，热键行为与今天完全一致。

## 六、验证记录（2026-10-04 真机，用户确认）

**环境**：QQ 视频通话，QQ 麦克风选 `CABLE Output (VB-Audio Virtual Cable)`。

**用户原话**：「可以，可以，快捷键按了，我发现之后可以有声音，确实有声音。」

**结论**：「真声直讲 + 偶发插 AI 音、两路混音」**可行性成立**，
且传输链路**零衰减**（传递比 0.94）。

**探针**：`tools/_probe/passthrough_probe.py`（临时验证用，非产品代码）。

## 七、正式实现（2026-10-04 落地）

按上文设计实现完毕，落点与设计一致：

| 文件 | 角色 |
|---|---|
| `m2_server/passthrough_worker.py` | 常驻 worker：自持两条流，插话在回调里**叠加** |
| `m2_server/passthrough.py` | 生命周期 + `/api/passthrough/{start,stop,status}` |
| `m2_server/voice_phrases.py` | `play_phrase` 按直通状态**分流** |
| `m2_server/plugins/sound.tts/plugin.json` | `routers` 加 `"passthrough"` |
| `web/src/pages/Tts/{usePassthrough.ts,PassthroughCard.tsx}` | 开关 + 运行态 + 外部软件提示 |
| `web/src/pages/Tts/TtsPage.tsx` | 卡片挂在短语板**上方**（两者配套） |

### 三条不变量（守护测试均已变异验证）

1. **插话叠加，不是替换** —— `buf[:take] += cd[p:p+take]`。
   改成替换 = 老师讲到一半按热键**被静音**。这是整个模块存在的理由。
2. **`stop_clip` 只清插话，绝不碰流** —— 命令名刻意区别于 `board_worker` 的 `stop`。
3. **16-Ch 端点否决** —— 三条判据照抄 `rvc_live._device_matches`。

另外两条：**削波保护**（两路相加超 ±1.0 硬限幅，不夹会回绕成爆响）、
**抢占语义**（连按两次热键 = 后一条接管，不排队）。

### 使用须知（给老师）

1. 在 **QQ/微信通话界面**把**麦克风**选成 `CABLE Output (VB-Audio Virtual Cable)`
   —— 这是唯一要在**外部软件**里做的一步，界面卡片上有提示。
2. 打开「真声直讲」开关 → 正常用真声讲课。
3. 讲累了按 `Ctrl+Alt+1~5` → 那一句 AI 音**叠加**在真声上，不打断。
4. 与「实时变声」「级联变声」**互斥**（都要占虚拟声卡）。
