# 二、A2 · 市场自动试听

> 对应《功能完善建议-2026-09-05》A 档第 2 条。

## 解决什么问题

实测 chaye741 / hudddd 等市场仓库**都没有演示音频**（只有 weights/indices），市场页「试听」长期不可用，用户必须装完才知道像不像。现在：**安装收尾自动合成一句固定中文试听**，市场卡片与音色库共用播放器，把「装了才知道翻车」变成「装了先听再留」。

## 链路

安装完成（`market_install.py` 收尾）→ `market_preview.try_auto_preview(voice_id)`（fire-and-forget，失败不阻塞安装）

后台线程里走完整链路：

```
固定一句中文
  └─ 用本机任一 voicebank 参考音色 → Qwen3-TTS 合成源句（缓存 outputs/market/_preview_src.wav，只做一次）
       └─ 走 RVC 离线推理（offline_vc_infer.py 子进程，与离线变声同一条链路）
            └─ outputs/market/<id>_preview.wav（市场卡片 / 音色库共用播放）
```

**源句缓存**：`_preview_src.wav` 首次生成后复用，不会每个音色都烧一次 TTS；无任何 voicebank 时报可读原因（failed），提示先去建一个音色。

## 状态模型

每个音色一个 sidecar（`outputs/market/<id>_preview.json`）：

| 状态 | 含义 | 前端表现 |
|---|---|---|
| `ready` | 试听已生成（wav 存在，sidecar 可脏） | 播放器 |
| `generating` | 生成中 | 转圈 +「试听生成中…」 |
| `failed` | 生成失败，error 带原因 | 「重新生成试听」按钮（hover 显示原因） |
| `skipped` | GPU 被实时/级联/离线变声占用（不静默排队） | 同上，可稍后重试 |
| `missing` | 从未生成 | 有安装就触发，否则无 |

# 三、A3 · 语料体检

> 对应《功能完善建议-2026-09-05》A 档第 3 条。commit `b0960e6`。

## 解决什么问题

clip_qc 打分早就接进了切片流水线（每条切片都有 A/B/C/D 等级徽章），但 **`/ft/train` 训练入口从来没消费这个分数**——D 级废片（近静音、爆音、错人声）照样进训练集，直接污染音色。袋鼠音色"鬼叫"的根因之一就是脏切片进训。

现在：切片处理完自动体检 → 检出废片给出原因 → 一键剔除（可恢复）→ 再开训。

## 功能入口

**前端**：微调页「处理完成」卡片内新增「语料体检」面板。

- 等级分布徽章：A/B/C/D 各级条数 + 均分 + 净时长
- D 级 > 0 时红字提示废片原因（如「响度过低 ×4」）
- 剔除粒度切换：**只剔 D 级**（默认）/ **C 级也剔**
- 「一键剔除并重选锚点」「恢复全部」
- 切片数变化时自动重新体检（带指纹缓存，不会反复重算）

**后端 API**：

| 端点 | 方法 | 说明 |
|---|---|---|
| `/api/ft/corpus_qc?voice_id=&force=` | GET | 体检报告（按 clips 指纹缓存，force 强制重算） |
| `/api/ft/corpus_prune?voice_id=&keep_grades=A,B` | POST | 剔除非保留级切片 |
| `/api/ft/corpus_restore?voice_id=` | POST | 恢复全部已剔切片 |

**训练闸门**：`/api/ft/train` 启动前自动体检，检出 D 级切片时响应带 `qc_warning` 字段（**不阻断训练**，是否剔除由用户决定——避免自动删数据）。

## 剔除的行为语义（重要）

1. **只移文件不销毁**：被剔切片从 `ft/<id>/clips/` 移入 `ft/<id>/rejected/`，wav + 转写一并保留。
2. **train.jsonl 同步重写**：只保留存留切片的行，转写文本不丢。
3. **锚点重选**：锚点参考音如果被剔除，自动从存留切片里重新挑（时长最长、B 级以上）；剔除后所有行的 `ref_audio` 指向有效文件。
4. **下限告警**：剔除后净时长 < 120s 时返回 `warning`（音色库现有音色不受影响，仅提示）。

## 文件清单

| 文件 | 改动 |
|---|---|
| `m2_server/ft_corpus_qc.py` | 新增：体检三件套（报告/剔除/恢复） |
| `m2_server/finetune.py` | 挂 3 个路由 + `/ft/train` 前置体检 |
| `m2_server/tests/test_ft_corpus_qc.py` | 新增：15 项测试 |
| `web/src/api/client.ts` | FtCorpusQc 等类型 + 3 个 API 函数 |

# 四、A4 · 多链路对比

> 对应本文 **一、来源清单** 的 A4。
> 解决"同一段输入到底走 RVC / Seed-VC / Qwen3 哪条链路更像"，把靠人耳挑变成可量化决策。

## 做了什么

| 层 | 文件 | 内容 |
|---|---|---|
| 后端 | `m2_server/ab_chain.py` | `POST /api/ab/chain`：上传一段源声 + 选一个目标音色，串行跑三条链路并打分 |
| 前端 | `web/src/components/voice-studio/AbChainCard.tsx` | 三栏并排试听 + 客观分 + 主观投票同屏 |
| 前端 | `web/src/pages/Voices/VoicesPage.tsx` | 音色库页在 A/B 盲听卡下方挂载（≥1 个音色即可用） |
| 测试 | `m2_server/tests/test_ab_chain.py` | 8 条：三链路成功 / 无文本跳过 / 单链路失败隔离 / 互斥 / GPU 占用 / 参数校验 / 权重缺失 |

## 接口

```
POST /api/ab/chain   multipart: file(音频) + voice_id + text(选填)
→ { ok, target_voice_id, text,
    chains: { rvc|seed_vc|qwen3: { status, url, error, metrics:{secs,nats,duration_s} } } }
```

- **任一条链路失败不拖垮整体**：该链路 `status=failed` + 可读原因，其余照常返回。
- **无 text → Qwen3 `skipped`**（TTS 链路必须有文本，不硬造）。
- **GPU 互斥**：实时变声 / 级联 / 离线变声在跑，或已有对比任务在跑 → 409。
- 同步端点（FastAPI 放线程池），整轮 RVC+Seed-VC+打分约 1–3 分钟。

## 两把客观尺子

| 指标 | 含义 | 来源 |
|---|---|---|
| `secs` | 输出 vs 目标音色参考音的 **CAM++ 声纹余弦相似度**，0~1，越高越像 | `speaker_sep._sv_embed`（与主链路同一套） |
| `nats` | **自然度**评分，越高越自然，可为负 | NatScore 本地权重 `models/natscore/final.pt`（whisper-small 编码器 + 偏好头） |

前端分档：secs ≥0.85 很像 / ≥0.75 比较像 / ≥0.62 一般 / ≥0.5 偏弱 / else 不像；
nats ≥3.4 自然 / ≥3.0 尚可 / ≥2.6 略生硬 / else 生硬。

## 主观与客观同屏

卡片底部可投"听感最好"的一票，投完直接给出结论：

- 一致 → 提示"可以定为默认链路"；
- 不一致 → 提示**以听感为准**，并说明 secs 只衡量声纹接近度，抓不住咬字和节奏。

这是刻意的：袋鼠音色 A/B 试了 8 轮的教训就是客观分高不等于听着像，工具只负责把两方摆在一起。

## 已知边界

- RVC 链路要求目标音色**已训练**（有可推理 pth），否则该链路 failed 并提示；Seed-VC 是零样本，无需训练。
- NatScore 权重缺失时打分环节报"NatScore 权重缺失"，不阻塞对比（该链路 metrics=null）。
- 三条链路串行共用 GPU，不做并行——8GB 显存下并行必 OOM。

| API | `m2_server/history_api.py` | `GET /history`（+`starred`/`tag` 过滤）、`GET /history/tags`、`PATCH /history/{id}`、`POST /history/bulk_delete`、`POST /history/export`（zip 流） |
| 前端 | `web/src/components/voice-studio/WorksLibrary.tsx` | 音色库页新增「作品库」卡片：音色筛选 / 只看收藏 / 标签 chips / 星标 / 标签编辑 / 勾选批量打包 zip 与删除 / 分页加载 |

设计取舍：

- **入口塞进音色库页**，不开新导航项（原建议"避免入口碎片化"）。作品天然按音色组织，放在音色库语义也顺。
- **导出走 POST + blob 下载**而不是 GET 链接：id 列表可能很长，且能顺带透出 `X-Missing-Files`（文件已被清掉的条数）。
- **删除联动**：批量删除或存储看板清 `outputs_wav` 后，指向不存在文件的历史记录同步摘掉，不留空链接。
- 标签清洗：去空白/去重/超 16 字拒收/最多 8 个——防止把标签当自由文本滥用。

## B2 存储占用看板 + 一键清理

| 层 | 文件 | 内容 |
|---|---|---|
| 统计/清理 | `m2_server/storage.py` | 9 个目标共用一套定义（统计与清理看到的永远是同一批文件）；`scan()` / `disk_usage()` / `clean()` |
| API | `m2_server/system_api.py` | `GET /api/system/storage`、`POST /api/system/storage/clean` |
| 前端 | `web/src/components/StoragePanel.tsx` | 设置菜单 →「维护 → 存储占用与清理」弹窗：磁盘水位条 + 各目录占用 + 勾选清理 |

目标清单（`cleanable=false` 的两项**受保护，永不清理**）：

| key | 内容 | 可清理 |
|---|---|---|
| market_downloads | 市场下载的 .pth/.index/.part（不动 downloads.json） | ✅ |
| market_previews | 市场自动试听音频 | ✅ |
| outputs_wav | outputs 顶层 wav（历史产物） | ✅ |
| qc_cache | 质检中间产物 | ✅ |
| clips | 解析切片 | ✅ |
| ft_corpus | 微调语料 | ✅ |
| logs | outputs 与 m2_server 的 .log | ✅ |
| rvc_weights | RVC 实时权重副本 | ❌ 只读 |
| voicebank | 音色档案 | ❌ 只读 |

设计取舍：

- **`rvc_weights` 故意设为只读**：它是 logs/<id>/<id>.pth 的硬链接副本（见 A1 改动），删了不省空间反而让实时变声失效——面板上会写明这一点。
- **voicebank / RVC logs 永不出现在可清理列表**（原建议明确排除），这两项是不可重建的用户资产。
- 清理只删文件、不删目录结构；被占用的文件跳过并计入 errors，不中断。
- 磁盘水位 ≥90% 红条 / ≥75% 黄条（对 C 盘 96% 满的场景直接可见）。
