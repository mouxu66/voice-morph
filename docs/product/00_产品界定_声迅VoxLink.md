# 产品界定：声迅 VoxLink — 移动端实时 AI 变声引擎

> 本文档是《功能规格书》《竞品分析》《产品路线图》三份交付物的共同前置界定。三者均围绕同一款产品展开，避免口径漂移。

## 1. 产品名称与一句话定位

- **产品名称**：声迅 VoxLink
- **英文代号**：VoxLink
- **一句话定位**：面向低端安卓机与社交聊天场景的 AI 变声语音工坊——录音/TTS → 变声 → 一键发进微信/QQ；端侧离线免费保底，PC（RTX 5060 8GB）高清克隆与自动化增强。

## 2. 产品背景

### 2.1 市场缺口
当前移动端实时变声市场呈两极化：
- **国际标杆（Voicemod）**：以 PC 为绝对主力，虚拟麦克风方案体验成熟，但**原生移动端能力弱**、对低端设备/弱算力不友好，且最佳 AI 音色锁在付费墙后。
- **国内移动 App（叮咚、声侠客、变声器管家等）**：主打游戏悬浮窗实时变声，但**仅提供预设音色、无真声克隆、普遍带广告、优质声线需会员解锁、iOS 适配弱**。

两者都缺少一个组合：**「低端机原生可用 + 真声克隆 + 无广告 + 可选高清」**。

### 2.2 我们的资产（来自本项目）
- 已积累 **RVC 音色克隆能力**（如「袋鼠骑士」语音库 `media/voicebank/kangaroo/`），实测比 Qwen3-TTS 零样本/微调克隆更稳（TTS 路线在本项目被 A/B 试听推翻）。
- 已验证 **8GB 显存（RTX 5060）可承载 RVC 实时推理**；移动端 RVC 经 INT8 量化 + 流式分块后，行业基准显示端到端延迟可压到 <100ms（骁龙 888）、连续 1 小时耗电 <15%、可离线运行。
- 目标硬件已明确：荣耀 Play 50 Plus（天玑 6020，约 52 万 AnTuTu，8/12GB RAM，6000mAh，3.5mm 耳机口）；PC 推理端 RTX 5060 8GB。

### 2.3 产品理念
不做"又一个预设音色玩具"，而做**低端机用户也用得起的真声级实时变声**：端侧轻量模式保底（免费、离线、任何手机能跑），PC 串流高清模式进阶（真声克隆 + 高保真），用端云协同覆盖"能不能用"和"好不好听"两件事。

## 3. 目标用户

| 细分 | 特征 | 核心需求 | 痛点 |
|------|------|---------|------|
| **微信/QQ 语音社交用户（核心）** | 低端安卓机、群里玩梗整活、发语音包 | 录音/文字→变声语音条随手发、音色丰富、无广告免费 | 竞品回录操作繁琐、广告多、优质声线收费 |
| **手游玩家（次核心）** | 低端安卓机、常开黑/角色扮演 | 游戏中变声（PC 游戏为主，或用注入线） | 手机游戏注入无解（安卓限制），竞品宣传过度 |
| **移动主播/短视频创作者** | 边玩边播、需稳定声线与音效 | 高保真变声 + 声音克隆（专属人设） | 预设音色千篇一律、无专属声线 |
| **语音社交用户** | 语聊房、微信语音、玩梗 | 趣味声线、随手切换、低功耗 | 合成感重、iOS 适配差、收费 |

## 4. 核心应用场景

> **方向调整（2026-09-03）**：经技术评估，**Android 无 root 时无法把合成音频注入第三方 App 的麦克风采集**（详见 `04_传输方案评估` §3），"手机游戏内实时变声"不具备纯软件可达性。主场景调整为**社交语音消息变声**——"录完再发"不依赖实时注入，100% 可交付；游戏实时降级为条件场景。

1. **微信/QQ 语音消息变声（主场景，P0）**
   - **语音包**：录音→变声→一键发送微信/QQ；**文字转语音**：输入文字→用音色（含真声克隆）合成→发语音条。
   - 发送路径三选一（**①③已建成，代码实测**）：①**音频文件分享**（App TTS/离线变声结果页 ShareButton：下载到手机→expo-sharing 系统分享面板→微信/QQ，已实现）；②**悬浮窗回录助手**（竞品同款，未做，①③已覆盖后降为可选）；③**PC 虚拟声卡自动灌入微信**（`m2_server/wechat_voice.py` 已完整实现：声卡切 CABLE→前台化微信按 Alt 触发 4.1.9+ 官方「发送语音消息」→TTS wav 播进 CABLE Input→松键发送（≤60s），含手动引导降级与发送历史）。
   - **手机微信语音条 → ④线缆回灌（③的物理版，半自动）**：虚拟声卡/按键自动化属 Windows 机制，且安卓无 root 时微信录音只认真实麦克风（注入墙，见 `04_传输方案评估` §3），软件法**无法**直达手机微信。物理替代：PC 播变声音频 → TRS 公对公线 → TRRS 二合一转接器 → 手机耳机口麦克风触点，手机将其识别为有线麦克风，微信正常按住录音即录到变声（无外放漏音、无需掐秒）。流程半自动：微信按住说话 → App 遥控 PC 播放（复用 m2_server 播放能力）→ 松手发送。延迟不敏感（非实时对话场景）。
   - 收到的微信语音→转文字：微信自带，不在我们范围。
2. **移动直播 / 录屏配音（P1）**
   - 边玩边变声直播，支持真声克隆形成专属主播声线；**PC 端走虚拟麦克风**（PC 游戏/Discord/OBS 直接收虚拟麦，无注入问题）。
3. **游戏内实时变声（降级 P2 / 条件场景）**
   - PC 游戏：手机作 PC 无线麦克风（纯软件闭环，随 1.0 串流提供）。
   - 手机游戏：仅 3.5mm TRRS 注入线一条路（¥20 线缆，B 计划，不作默认承诺）。

## 5. 关键约束（来自本项目实测与行业基准）

- **算力上限**：PC 推理端仅 8GB 显存（RTX 5060），RVC 实时推理可承载，但并发/模型尺寸受限；**RVC 路线稳定性优于 Qwen3-TTS 克隆路线**，本产品变声核心采用 RVC 而非 TTS-LM。
- **低端机算力**：天玑 6020 级别需 INT8 量化 + 流式分块（200ms 块 + 滑动窗口），否则延迟/发热不可控。
- **音频回路**：3.5mm 有线/蓝牙回环存在回路延迟与回声风险，需 AEC 与延迟补偿。
- **网络依赖**：PC 串流高清模式依赖手机↔PC 连接（含本机 Clash/代理等复杂网络环境），必须有**弱网/断连自动降级到端侧**的兜底。
- **隐私与离线**：低端用户与社交场景对隐私敏感，端侧轻量模式须**完全离线可运行**。
- **无广告定位**：作为差异化卖点，免费端侧模式不含广告（收入来自 PC 高清订阅/音色市场抽成）。

## 6. 设备角色与范围边界（口径修正 2026-09-03）

> 澄清一个易误读点：**不是"只做低端手机"**。低端是切入阵地与信任状，不是天花板。

| 设备 | 在产品中的角色 | 态度 |
|------|--------------|------|
| **手机（安卓）** | 主使用端（变声语音包生产与发送） | ✅ 覆盖低端→旗舰全体；以"低端机也能流畅"作差异化信任状 |
| **PC（RTX 5060 8GB）** | 高清推理后端 + **微信 PC 语音条自动发送**（虚拟声卡） | ✅ 角色是"手机的高清外挂与自动化后端"，不做独立 PC 变声软件 |
| **主机 / 主机 Key** | 远期扩展 | 🚧 路线图远期，手机作桥接（对标 Voicemod Key） |
| **iOS** | 待定 | 🚧 视首版数据决策 |

- **三档服务形态**：①端侧轻量（免费/离线，任何安卓机）→ ②端侧标准（旗舰机高音质，零网络依赖）→ ③PC 串流高清（高保真 + 真声克隆，付费点）。
- **"别刚 PC/主机"的准确含义**：不与 Voicemod 拼独立桌面变声软件（❌），但手机调用 PC 算力的端云协同（✅）恰是本产品特色。
- **一句话**：手机是入口，低端是信任状，PC 是增强，克隆是卖点，未来扩主机/iOS。

## 7. 现有资产盘点与差距映射（2026-09-03 代码实测）

> 本项目并非从零开始。以下为仓库实存资产，规格书/路线图的基线据此修正。

### 7.1 已建成资产

| 资产 | 位置 | 实测能力 |
|------|------|---------|
| **PC 后端** | `m2_server/`（FastAPI :8000） | 级联变声（ASR→TTS 文字中转，p95 延迟统计）、RVC 实时变声、RVC 训练（阶段/进度/自动质检 QC）、离线变声、TTS 克隆合成（含 fast_tts）、**微信语音全自动发送**（wechat_voice.py：虚拟声卡+Alt 快捷键+降级+历史）、**DSP 效果链**（effects.py：混响/回声/EQ/变调）、**产出历史**（history.py：tts/offlinevc/audiobook/fx/mine）、有声书（audiobook.py）、**Seed-VC 引擎**（seed_vc.py）、实时 ASR 字幕（--asr-only 子进程）、素材流水线（切片/打标/说话人分离/质检/音调建议）、loopback 采集、PC 声卡一键最优/恢复、API Key 鉴权 |
| **移动端 App** | `mobile/`（Expo 54 + RN 0.81 + expo-router + zustand，约 1200 行业务代码） | 四 Tab：**主控台**（后端连接、级联/RVC 实时遥控启停、PC 训练与流水线状态镜像）、**离线变声**（手机录音→上传 PC RVC→回传播放/分享，pitch/index_rate/denoise 可调，与实时互斥保护显卡）、**TTS**、**音色库**（RVC 状态/QC 徽标）；设置页配对 host + API Key |
| **桌面控制端** | `voice-morph-desktop/`（变声工坊.exe，Electron 已打包） | PC 侧图形控制台 |
| **音色资产** | `media/voicebank/`（RVC voicebank，含袋鼠骑士） | 已验证的克隆训练与推理链路 |

### 7.2 关键差距（对照规格书 M1–M6，2026-09-03 二次核对）

> ⚠️ 第一版盘点漏掉了 `wechat_voice.py`/`effects.py`/`history.py` 等已建成模块，本节为修正版。**结论：新主场景（微信/QQ 语音包 + TTS）的后端链路已全部建成，缺口集中在 App 端入口与端侧引擎。**

1. **App 端微信遥控入口未接**：后端 `/api/wechat/send_voice`（全自动发语音条）与 `/api/history` 已在，但手机 App 四个 Tab 均未接——用户在手机上无法"选音色打字→遥控 PC 微信自动发语音条"。这是**当前性价比最高的一步**：API 全在，纯 App 端接线。
2. **M1 手机采集回环未打通**：当前"实时变声"是 **PC 采集→PC 播放、手机当遥控器**；手机实时采集→PC→回手机的低延迟链路仍未通（主场景调整后此缺口降为 P1，服务直播/PC 无线麦场景）。
3. **M5 串流仅有雏形**：REST + 轮询够遥控与离线任务，不够实时音频流。
4. **端侧离线 RVC 未做**：App 完全依赖 PC 后端，离线轻量模式（差异化三件套之一）尚未开始。
5. **克隆采集引导未做**：RVC 训练在 PC 端完成，移动端"录 30s→自动克隆"入口缺失（M3.2）。
6. **悬浮窗回录助手未做**：发送路径②；在①文件分享与③PC 自动发送已建成的前提下，优先级最低。

**结论**：主场景"录音/打字→变声/TTS→发微信/QQ"的**生产与自动发送链路已全部建成**（文件分享 + PC 全自动两条路都通）。MVP 剩余重心收敛为：**①App 端接微信遥控入口 + 语音包历史页（纯接线，最快见效）②端侧轻量 RVC 引擎**。
