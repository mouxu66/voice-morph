# 翻唱 checkpoint 扫描：权重 / 素材时长（2026-10-14）

> **类型**：快照（数字只代表 2026-10-14 这次实测）
> **触发**：`docs/product/research/m1g_RVC翻唱混杂-调研_2026-10-14.md` 的待办 ——
> 「未测：checkpoint e10–e40 扫描、多首歌」。checkpoint 这条做掉了（多首歌见 §7）。
> **一句话结论**：★ **e30 在两个 seed 上、8/8 个细分频段都同号地改变了频谱形状** ——
> 它把能量从 **800–4000 Hz 搬到了 200–400 Hz**。**这不解决"闷"**：
> 4–8 kHz 只高 0.7 dB，而 800–4000 Hz（清晰度/临场感所在的频段）**一致地更低 2.4–2.9 dB**。
> ⇒ **现役 e40 保持不变**，换 e30 是"更浑厚"，不是"更亮更纯"。
> **素材时长**：4min ≈ 8min ≈ 12min（唯一跨 seed 一致的是"对原唱相似度"随素材增多而降）。
> **原始数据**：`media/covers/ckpt{,  _s4321}/`（`ckpt_sweep.json` / `metrics.json` /
> `fine_bands.json` / `f0_bands.json`；gitignore，产物不入库）
> + 试听页 `media/covers/ckpt/listen.html`（8 条，音频内嵌）

## 0. 先给可操作的三句话

| 问题 | 本机实测答案 |
|---|---|
| 翻唱该换 checkpoint 吗？ | **不换**。现役 `myvoice_ppt12_full`（= e40）保留 |

## 1. 为什么要重扫：域内结论不能搬到跨域

2026-10-13 已扫过一次 epoch，结论是**「加 epoch 无收益」**（TTS→RVC 的 CAM++ 只涨
+0.0036，小于 seed 噪声 0.004~0.011）。但那次用的是**说话句**；翻唱是**跨域**输入
（歌声 → 说话模型），而 `m1g` 已证明"模型在域内忠实、跨域才掉高频"。
**域内分辨不出的差异，跨域未必分辨不出** —— 所以重扫。
★ 这本身是一条方法论：**"某个维度没用"的结论带着它的域。**

## 2. 做法（单变量）

`experiments/cover_ckpt_sweep.py`：同一段歌声（78–98s）、同一变调（−12）、同一 seed，
**只换权重**。★ 刻意 `index_rate=0` —— 索引来自不同数据集，带上它就成了
"权重 × 检索库"两个变量同时动（脚本 docstring 与守卫 `test_cover_ckpt_sweep.py` 都钉住）。

| 组 | 唯一变量 | 成员 |
|---|---|---|
| `epochs_12min` | 训练轮数 | `ppt12_full` 的 e10/e20/e30/e40 |
| `dur_4_8_12min` | 素材时长 | `probe_4min_e40` / `probe_8min_e40` / `ppt12_full_e40` |

客观分用 `experiments/cover_metrics.py`（分频段 + 谱质心 + CAM++），口径与 `m1g` 同一套。
**两个 seed 都跑**（1234 / 4321）—— 2026-10-13 的教训是「固定 seed ≠ 结论稳健」。

## 3. ★ 本轮最值钱的一步：两个"亮度"判据打架了

先跑出来的表里有一对矛盾，差点让我写反结论：

| 判据 | e30 vs e40 | 读作 |
|---|---|---|
| 4–8 kHz 相对能量 | e30 **高 0.7 dB** | "e30 更亮" |
| 谱质心 | e30 **低 94 Hz**（482 vs 576） | "e30 更闷" |

两个都是"亮度"指标却指向相反。**在查清之前不能写推荐** —— 于是把 0–4 kHz
（装了约 99% 的能量，质心差异只可能来自这里）切成细段重量
（`experiments/cover_ckpt_fine_bands.py`）：

| 频段 | e30−e40（seed 1234） | e30−e40（seed 4321） | 同号 |
|---|---|---|---|
| 0–200 | +0.05 | +0.04 | ✅ |
| **200–400** | **+1.71** | **+1.71** | ✅ |
| 400–800 | +0.18 | +0.20 | ✅ |
| **800–1200** | **−2.63** | **−2.83** | ✅ |
| **1200–2000** | **−2.42** | **−2.55** | ✅ |
| 2000–3000 | −0.15 | −0.25 | ✅ |
| **3000–4000** | **−2.89** | **−2.79** | ✅ |
| 4–8 kHz | +0.70 | +0.66 | ✅ |

（dB，相对整段总能量；**8/8 段两 seed 全部同号** ⇒ 真效应，不是噪声。）

⇒ **矛盾解开了**：e30 把能量从 800–4000 Hz **搬到了 200–400 Hz**。质心因此下降
（能量重心往低频走），而 4–8 kHz 那点尾巴确实略高 —— 但**主战场（清晰度所在的
800–4000 Hz）一致地低了 2.4–2.9 dB**。

★ 这正是 `m1g` 里"闷"的频段。所以：**e30 = 更浑厚/更沉，e40 = 更清楚**。
这**不是**"e30 更亮"，而是完全相反。

### 3.1 顺带纠正我自己：谱质心不是基频

我第一版草稿把 `centroid_hz` 读成"中位基频"，据此写下"e30 的 482 Hz 更贴你的音域"。
实测中位基频（产品同款 `_median_f0`，`experiments/cover_ckpt_f0.py`）：

| | e10 | e20 | e30 | e40 |
|---|---|---|---|---|
| 中位基频 | 123.1 | 123.5 | **124.0** | 123.8 Hz |

⇒ **换权重根本不改音高**（四档差 0.9 Hz）。`centroid_hz` 是**谱质心**
= Σf·P(f)/ΣP(f)，是能量的频率重心，**越高越亮、越低越闷** —— 与"音域"无关。
★ 教训：**指标名字里带"centroid"不等于质心之外的东西**；写结论前先确认这个数
是怎么算出来的（同族：#168「8-10k 不可用作判据」、`m1f`「尺子先验证再用」）。

## 4. epoch 组的完整结果

| 权重 | 谱质心 Hz | 4–8k dB | CAM++ 对你 | CAM++ 对原唱 |
|---|---|---|---|---|
| e10 | 501 / 496 | −36.2 / −36.7 | 0.6189 / 0.6335 | 0.2370 / 0.2515 |
| e20 | 510 / 508 | −36.5 / −36.8 | 0.6000 / 0.6042 | 0.1612 / 0.1686 |
| e30 | 482 / 478 | −34.3 / −34.5 | 0.6330 / 0.6530 | 0.1138 / 0.1301 |
| e40（现役） | 576 / 576 | −35.0 / −35.2 | 0.6061 / 0.6235 | **0.0863 / 0.1139** |

（seed 1234 / seed 4321）

跨 seed 一致的：
1. **谱质心排序**：e30 < e10 < e20 < e40（同档两 seed 差 ≤6 Hz，档间差 70–95 Hz）⇒ **真效应**。
2. **"对原唱"随 epoch 单调下降**（0.237 → 0.161 → 0.114 → 0.086）⇒ 训练越久，原唱泄漏越少，
   **e40 最好**。
3. **"对你"那一轴分辨不出**（e30 0.6330/0.6530 vs e40 0.6061/0.6235，两 seed 区间重叠）。

## 5. 素材时长组

| 素材量 | 谱质心 Hz | 4–8k dB | CAM++ 对你 | CAM++ 对原唱 |
|---|---|---|---|---|
| 4min | 499 / 494 | −32.5 / −32.6 | 0.5935 / 0.6252 | 0.1298 / 0.1242 |
| 8min | 435 / 433 | −34.8 / −35.7 | 0.5912 / 0.6055 | 0.1522 / 0.1512 |
| 12min | 576 / 576 | −35.0 / −35.2 | 0.6061 / 0.6235 | **0.0863 / 0.1139** |

⇒ **时长不是杠杆**：4min 与 12min 在"像你"上分辨不出（两 seed 方向相反）；
8min 质心反而最低。唯一跨 seed 单调的是**"对原唱"**（4→8→12min 逐档下降）。
与 `m1g` §4 一致：**关键不是素材"多"，是那份素材本身的频谱倾斜**（也独立支持 #168/#173）。

## 6. 结论与动作

**不换 checkpoint。** 理由：现役 e40 在"对原唱泄漏"这一轴最好（跨 seed 一致），
而 e30 的频谱改动方向（把 800–4000 Hz 压低 2.4–2.9 dB）**恰好加重"闷"这条抱怨**。

`m1g` 的主结论不变：**"闷"的杠杆在素材，不在旋钮、也不在 checkpoint。**
本轮把 checkpoint 这一轴也排除掉了 —— 这是它作为"待办"的价值：
**排除一个候选解释，和找到一个真因同样值钱。**

如果想换风格（更浑厚/更沉），e30 是可用的一档，但那是**审美选择**，
应先用试听页听过再定：`media/covers/ckpt/listen.html`（同 20 秒、同 seed 直接 A/B）。

## 7. 边界（引用时必须一起说）

- **CAM++ 是语音声纹尺子**，用在歌声上只能做"同一输入、同一 seed 下的相对比较"，
  不是绝对像度；本表 CAM++ 列都只是**排序证据**。
- **单段 20 秒、单首歌**（Lorezo - Feed the One 78–98s）。**"多首歌"没做掉**：
  本机 `media/songs/` 只有这一首（`media/` 被 gitignore），需要新素材（用户提供或
  `/api/cover/fetch` 扒歌）—— 如实记为未做，而不是用"看起来验过了"的说法盖过去。
- 扫的是本机已有的 5 个实验，不是全部组合；`myvoice_ppt12`（3.4min 旧版）与
  `last4min` 变体**没扫**。
- `index_rate` 固定 0 ⇒ 本表绝对值**不等于**产品现役配置（产品走 0.5 + 索引）。
- 全部是单次前向 + 客观量测，**未做听测**（MOS/ABX）。§6 的"更浑厚"是从频谱推的听感词，
  真正的判断要人耳。
