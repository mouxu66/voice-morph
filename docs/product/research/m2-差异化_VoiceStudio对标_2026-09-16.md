### 1.1 关键负面事实（决定差异化空间）

1. **没有实时变声**：功能表里无 virtual microphone / voice changer / low-latency streaming。它的"听写"是**麦克风→文字**（单向入），不是**麦克风→改造后声音送出去**。
2. **没有虚拟声卡集成**：全库无 VB-CABLE / 虚拟麦克风 / 音频设备切换相关内容。
3. **不做用自己的声音训练模型**：只有**零样本**克隆；无 RVC / 微调训练链路。
4. **没有 IM 集成**：不接微信/QQ，不涉及"把变声语音条发出去"。
5. **引擎偏"宽度"而非"中文社交场景深度"**：16 引擎覆盖多语言配音，但社交语音场景（游戏开黑、微信语音条）零覆盖。

## 2 象限定位（为什么不是正面竞品）

```
                    自建音色
                       │
   VoiceStudio ────────┼──────── 变声工坊
   视频配音/有声书      │        自训练音色/实时变声
   听写转录/声音设计    │        微信语音条/音色市场
                       │
        内容生产 ──────┼────── 实时使用
                       │
                  零样本克隆
                  （双方都有）
                       │
                    预设音色
```

- **VoiceStudio = 左上**：预设为主 + 内容生产。交付物是**音频文件**（配音、有声书、转录稿），时间尺度是**秒到分钟**。
- **变声工坊 = 右下**：自建为主 + 实时使用。交付物是**改造后的语音流**，时间尺度是**毫秒到一句**。

**结论：表面高度重叠（都在"本地+离线+语音克隆"），实际底座不同。** 唯一真重叠是零样本克隆这个**技术点**——而它既不是 VoiceStudio 的壁垒（它靠引擎宽度取胜），也不是我方的壁垒（我方靠链路整合取胜）。

## 3 四个真差异点（护城河候选）

### D1 实时性：毫秒交付 vs 分钟交付 —— **能力缺口，非取舍**

VoiceStudio 完全不做实时。这不是它懒，而是架构决定的：16 引擎编排 + 长文渲染 + 视频 remux 流水线的形态，天然与低延迟流式冲突。

我方：`m2_server/rvc_live.py`（1308 行）RVC 实时 + VB-CABLE 虚拟麦克风，实测 game 档 start 12.2s / 推理 p50 50ms / 显存峰值 4667MB（RTX 5060 Laptop 8GB）。

> **护城河强度：中高。** 对方要补需重写流式架构，不是加个功能。

### D2 发送闭环：发进微信 vs 导出文件 —— **渠道锁定，且是独占**

VoiceStudio 的终点是"导出一个文件"。我方终点是"消息已经在微信里发出去了"。

`m2_server/wechat_voice.py`（1769 行）8 个端点：`send_text` / `send_voice` / `precheck` / `manual_send` / `play_to_cable` / `stop_play` / `history` / `send_voice/last`。
链路 = 必要时重启微信 → 默认麦切 CABLE Output → 微信前台 → 单击话筒 → wav 播进 CABLE Input → 点发送 → 还原声卡。

> **护城河强度：高。** 这是**工程苦活**（UIA 优先+像素降级、启动绑定采集设备必须"杀→切卡→拉起→录音"），不是模型能力；对方没有中文 IM 场景动机，且 AGPL 生态里的贡献者不会为微信做这类 workaround。

### D3 自建音色：训练 vs 零样本 —— **深度分层**

VoiceStudio 上限 = 3 秒零样本（快但音色是"像"，不是"是"）。
我方 = 零样本（TTS）**+ RVC 训练**（`m2_server/rvc_live.py` 训练链路 + `clip_qc.py` 切片质检 + `speaker_sep.py` 说话人分离 + `pitch_advice.py`）。

> **护城河强度：中。** 技术上非独占（RVC 是开源生态），但**"脏素材→可用音色"的成功率工程**（质检打分、自动优选、失败诊断）是攒出来的，不是抄得到的。

### D4 中文社交语境：热梗/角色音色 vs 通用多语言 —— **内容壁垒**

VoiceStudio 的 646 语言是**配音语境**（纪录片旁白、有声书腔）。我方音色市场 30 款精选（`m2_server/market_manifest.py`）走的是**社交语境**（卡通·懒羊羊、卡通·曼波这类热梗角色音）。

> **护城河强度：中低（易被抄，但需中文运营能力）。** 属运营壁垒非技术壁垒，靠周更节奏维持。

## 4 对方的真优势（必须承认，不许自欺）

| 优势 | 说明 | 我方态度 |
|---|---|---|
| **引擎宽度** | 16 TTS + 11 ASR，无单一模型绑死；模型圈三月一换代时这是正确架构 | ⚠️ **值得学**：我方 `seed_vc.py` / `cascade.py` / `offline_vc.py` 已是多引擎雏形，但未做成"目录+热切换" |

| **传播势能** | 20K stars、TechCrunch 报道、221K 下载 | 🔻 无法对标，也不该对标（不同量级） |

## 5 战略选择：三个「不」

### 不跟（明确放弃）
- **视频配音 / 多语言翻译**：对方已经做到 646 语言 + 说话人保留 + remux 导出。跟进去 = 在别人主场打消耗战，且**与实时这个真护城河无关**。
- **有声书深化**：同理。`audiobook.py` 维持现状，不再投。
- **引擎数量军备竞赛**：堆到 16 个没有意义——对方是"通用语音工作站"，我是"社交实时变声器"，引擎够用即可。

### 不碰（合规红线）
- **对方默认引擎是 CC-BY-NC**，且 tokenizer 继承 Meta Llama 社区许可。**不得以任何形式引入 VoiceStudio 的代码（AGPL-3.0 传染）或其模型权重**。此条与根 `THIRD_PARTY_NOTICES.md` 既有纪律一致。
- 严禁把 VoiceStudio 当作组件嵌入「变声工坊」——AGPL 的传染性会波及整个发行物。

### 要打（资源集中）
1. **实时链路的"零门槛"**：把 D1 从"能跑"推到"任何人装完 3 分钟能开麦"。这是对方**不可能跟**的地方（架构级）。
2. **发送闭环的"一句话到底"**：打字 → 选音色 → 微信里出现语音条。这是 D2 的产品化。
3. **自建音色的"零炼丹"**：`clip_qc.py` 已有的打分/优选能力**显性化**成"你只管丢素材，剩下的我们挑"。

## 6 定位口径修正建议

现口径（《00_产品界定》§1）：

> 面向低端安卓机与社交聊天场景的 AI 变声语音工坊

**建议改为**（因 09-09 已聚焦 PC 端，且需与 VoiceStudio 划清）：

> **变声工坊 —— 把变好的声音直接送进微信和游戏的本地实时变声器。**
> 不打字生成音频文件，而是改造你正在说的话；不上云，全程本机。

一句话差异（可直接用于 README / 官网）：

| | VoiceStudio | 变声工坊 |
|---|---|---|
| 一句话 | 本地语音**生产**工作站 | 本地实时**变声**器 |
| 你给它 | 一段文字 / 一个视频 | 你的麦克风 |
| 它给你 | 一个音频/视频文件 | 你**已经发出去**的语音条 |
| 等待 | 秒到分钟 | 50ms |
