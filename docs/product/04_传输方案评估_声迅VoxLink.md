# 传输方案评估：手机 ↔ PC 音频链路（声迅 VoxLink）

**日期：** 2026-09-03 ｜ **关联：** `00_产品界定` §6/§7、`03_产品路线图` MVP
**要解决的问题：** 能否用现成工具拼出「手机麦克风 → PC（RVC 推理）→ 回手机」全双工链路，端到端 ≤200ms。

---

## 1. 结论速览

| 方案 | 核实方向 | 延迟（标称） | 能否进我们链路 | 定位 |
|------|---------|------------|--------------|------|
| **QuicMic** | 手机麦 → PC 虚拟声卡（上行） | LAN 低延迟（QUIC/UDP 数据报 + 无锁环形缓冲） | ✅ 上行首选 | Rust 单二进制，浏览器免安装，WebTransport+WS 兜底，PIN/QR 配对 |
| **ToMic** | 手机麦 → PC 虚拟声卡（上行） | 低（未给数字，MediaRecorder 分块估 100ms+） | ✅ 上行备选 | Node+Socket.io+Opus，FFmpeg/SoX→VB-CABLE，Win/Mac |
| **WO Mic** | 手机麦 → PC（上行） | Wi-Fi ~120ms | ⚠️ 延迟超标，仅兜底 | 成熟但慢 |
| **AudioRelay** | 单次单模式：PC→手机（Speaker）**或**手机麦→PC（Mic） | 可低至 ~40ms；USB tethering 官方推荐"最佳体验" | ✅ **下行首选**（Speaker 模式） | 双向同时需虚拟设备拼接（官方论坛确认可行、配置繁琐） |
| **AudioSync** (alilosoft) | ⚠️ **手机系统音频 → PC**（Android 10+ 内录），不是麦克风 | Wi-Fi 20-60ms / USB 0-20ms | ❌ 方向不对 | 作者自述 4 天 AI 写成、不会编程，工程质量存疑 |
| **sndcpy** | 手机播放音频 → PC（scrcpy 系），非麦克风 | ≤50ms | ❌ 方向和内容都不对 | 不适用 |
| **蓝牙 A2DP sink** | PC 当蓝牙音箱（下行） | >100ms | ❌ 出局 | 已排除 |
| **USB 网络共享** | 不是音频工具，是**网络承载层** | 每边 0-20ms | ✅ 强烈推荐 | 所有 IP 工具跑其上，绕开 Wi-Fi 抖动 |

**核心结论：没有单一工具能做全双工，必须"上行 + 下行"两个工具拼组合。**

---

## 2. 可行组合与延迟预算

**组合 POC（今天就能测，零开发）：**

```
手机麦 ──QuicMic(WebTransport)──▶ PC: VB-CABLE Input
                                        │
                                   RVC 推理（RTX 5060）
                                        │
PC: AudioRelay 虚拟扬声器 ──▶ 手机耳机/扬声器播放
（承载层：USB 网络共享，或 5GHz Wi-Fi）
```

| 环节 | Wi-Fi | USB tethering |
|------|-------|---------------|
| 上行（QuicMic→VB-CABLE） | ~20-50ms | ~0-20ms |
| RVC 推理（流式分块） | ~100-200ms | ~100-200ms |
| 下行（AudioRelay Speaker） | ~40-100ms | ~20-50ms |
| **合计** | **~160-350ms** | **~120-270ms** |

- 压进 200ms **有机会但不稳**：推理分块大小和缓冲是最大变量，需实测调参。
- QuicMic 音质占优（原始 PCM 直传）；ToMic 的 MediaRecorder 自带缓冲，延迟更高。
- 互斥冲突已排除：AudioRelay 单次只能跑一种模式，上行恰好交给 QuicMic/ToMic，互补不抢。

**POC 的工程杂音（为什么只能用于验证、不能当产品）：**
- PC 端需 VB-CABLE（+ 建议 Voicemeeter 做路由），RVC 输出设备要手动指到 AudioRelay 的虚拟设备；
- 两套工具无统一控制面，手机端全手动；USB tethering 下 AudioRelay 需手动切地址；
- 无重连/降级逻辑，断线即哑。

## 3. ⚠️ 比传输更大的墙：注入（必须先知道）

**Android 无 root 时，任何 App 都无法把软件合成的音频注入第三方游戏的麦克风采集。** 游戏开黑语音只认真实输入设备——就算传输做到 0ms，变声后的音频到达手机也只是"播放出来"，队友从游戏语音里听到的仍是你的原声。

这意味着 `00_产品界定` §4 的主场景「游戏内实时变声」在纯软件路线下**走不通**，三条出路：

1. **场景改道：手机作 PC 的无线麦克风（纯软件即可闭环，最快落地）**
   PC 端游戏/PC 直播/PC 语聊吃"虚拟麦克风"——这条链路**不需要注入**，QuicMic/AudioRelay 单方向就够，我们的 App + m2_server 也能原生实现。建议升格为 MVP 首个可发布场景。
2. **3.5mm TRRS 注入线（¥10 线缆，严格说不是"硬件设备"）**
   PC 音频经 TRRS 线进手机耳机口的 **mic 通道**，游戏把这条线当麦克风。代价：内置麦克风被占用（上行需改蓝牙 HFP 麦或 PC 麦）、上行延迟叠加。这是无 root 唯一的手机游戏内注入路径——你说先不考虑硬件，但这条线缆是软件路线死穴的唯一便宜解，建议保留为 B 计划。
3. **Root/Xposed 虚拟麦克风：不做**（目标用户不可达）。

---

## 4. 建议动作（按顺序）

1. **本周 POC**：USB 网络共享 + QuicMic（上行）+ AudioRelay（下行）+ VB-CABLE，用录像帧数法实测全链路延迟（人开口 → 手机出声）。
2. **同场验证"手机作 PC 无线麦克风"场景**：QuicMic 单工具即可跑通 PC 端游戏/Discord 实时变声（PC 虚拟麦 → RVC → 虚拟麦）——这是最快变成产品功能的闭环，也是现有竞品没做好的位。
3. **POC 数据回来后**：给 m2_server 加 WebSocket/WebTransport 双工音频通道 + App 端低延迟采集/播放（react-native-live-audio-stream + 原生播放），把第三方工具全部替换掉——这才是规格书 M1+M5 的产品正道，第三方工具只留作延迟对照基准。
4. **文档修正**：M1 场景拆成「PC 端场景（软件闭环，MVP）」与「手机游戏注入（依赖 TRRS 线，另立里程碑）」，避免路线图对主场景做不可达的承诺。

## 5. 3.5mm 注入线购买清单（2026-09-03 决定采用）

**⚠️ 不能只买"3.5mm 公对公"一根线。** 手机耳机口是 4 节 TRRS（L/R/GND/Mic，CTIA 标准），普通 3 节 TRS 公头直插会把 Mic 节短接到 GND，手机判定为"无麦耳机"——游戏里不会出现耳机麦克风，链路断在第一步。

**正确买法（两件套，共约 ¥20-35）：**

| 物品 | 规格 | 参考价 | 作用 |
|------|------|--------|------|
| ① 二合一转接线 | **3.5mm TRRS 公 → 双 TRS 母**（搜"3.5mm 耳机麦克风二合一转接线"） | ¥10-20 | 把手机耳机口拆成"麦克风输入 + 耳机输出"两个口；手机端才能识别出麦克风 |
| ② 公对公音频线 | **3.5mm TRS 公对公，2 米**，选带屏蔽层的基本款（别买 3 元裸线） | ¥5-15 | 连 PC 音频口 → 转接器的"麦克风"母口 |

**⚠️ 买错预警（2026-09-03 购物确认）：别买"四级（4 节）公对公"直播声卡线！**
电商上常见 ¥2-5 的"3.5mm 公对公**四级**声卡直播线"（接手机/接声卡/接麦克风那种）是给**直播声卡**用的——两端都是 4 节，和直播声卡的四极"手机口"触点一一对应。它进不了我们的链路：
- 插 PC 的 3 节输出口（绿孔）：4 节头的第 4 节（Mic 芯）在 PC 侧悬空 → 手机仍判定"无麦耳机"，链路断在第一步；
- 插笔记本单孔复合口（两头都 CTIA）：变成"输出对输出、麦克风对麦克风"，双向都过不去，两路输出还互相对顶。
**买公对公线时认准"3 节 / 三级 / TRS"，商品标题带"四级""声卡直播"字样的直接排除。**

**接线拓扑：**
```
PC 主板后置音频口(绿) ──公对公线──▶ 转接器"麦克风"母口 ──TRRS──▶ 手机耳机口
                                    转接器"耳机"母口 ◀── 可再接耳机（监听游戏声+变声后自己的声音）
```

**关键参数与注意事项：**
- **线长选 2 米**：手游时手机放桌面，PC 后置口出来刚好且有余量；别超 3 米（无屏蔽长线底噪明显增大）。转接器本体约 15-20cm，已含在总长里。
- PC 端**插主板后置**音频口，别用机箱前面板（接地差、底噪大）。
- PC 输出音量先设 **50-70%**：直灌麦克风通道过载会爆音削波，增益后续在 RVC 链里调。
- 荣耀手机是 CTIA 标准，市售二合一转接线基本都是 CTIA，无需纠结；若出现"左右声道反+麦克风不认"才是买到了 OMTP 老标准，退货即可。
- 插上后验证方法：手机设置里出现"耳机麦克风"，开个录音 App 能录到 PC 放的歌 = 链路通。
