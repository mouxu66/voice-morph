# 功能规格书：声迅 VoxLink 移动端实时 AI 变声引擎

**状态：** 草稿 ｜ **作者：** 产品 ｜ **日期：** 2026-09-03 ｜ **关联界定：** `00_产品界定_声迅VoxLink.md`

---

## 1. 范围

### 目标（本规格覆盖）
- 在低端安卓机型上提供**可用、低延迟、不卡顿**的实时变声。
- 提供三种运行模式：**端侧轻量（离线免费）/ 端侧标准 / PC 串流高清（订阅）**。
- 支持**真声克隆**（基于 RVC voicebank）作为差异化能力。
- 游戏场景优先：悬浮窗、一键切换、低功耗、不掉线。

### 非目标（v1 不做）
- 不做 TTS 文本转语音播报（与变声解耦，避免重蹈 Qwen3-TTS 克隆失败覆辙）。
- v1 不做主机（Xbox/PS/Switch）支持（远期对标 Voicemod Key）。
- v1 不做云端音色市场/社区 UGC（远期）。
- 不做专业录音棚级后期（仅娱乐级微调）。

## 3. 逐模块详述

### M1 音频采集与回环（P0）

**目标**：稳定采集用户声音并低延迟回放变声结果，保证游戏/通话可用。

| 功能点 | 优先级 | 说明 |
|--------|--------|------|
| 1.1 麦克风采集 | P0 | AudioRecord 采集 16kHz/24kHz PCM，可配采样率 |
| 1.2 耳机/扬声器回放 | P0 | AudioTrack 回放，支持 3.5mm 有线与蓝牙 |
| 1.3 实时降噪 | P1 | RNNoise 类轻量降噪，抑制环境噪声 |
| 1.4 回声消除 AEC | P1 | 消除扬声器回路回声，保障通话清晰 |
| 1.5 回路延迟补偿 | P1 | 针对蓝牙/有线回路的延迟测算与对齐 |
| 1.6 输入增益自动调节 | P2 | 自动电平归一，防爆音/过小 |

**用户故事**
- 作为开黑玩家，我希望说话能被清晰采集、变声后从耳机听到，以便队友听不出破绽。
- 作为地铁通勤用户，我希望环境噪声被压住，以便嘈杂环境也能用。

**验收标准**
- Given 插入 3.5mm 耳机 → When 开启变声 → Then 变声后音频从耳机播出且回路回声不可闻（AEC 开启时）。
- Given 安静室内 → When 采集并回放 → Then 端到端采集-回放链路无额外 >30ms 人为延迟（不含推理）。

**关键约束**：蓝牙回路延迟波动大，须有补偿与fallback到有线提示；AEC 在低算力机可降级关闭。

---

### M2 实时变声引擎（P0）

**目标**：核心变声，支持端侧与 PC 串流双路，流式低延迟。

| 功能点 | 优先级 | 说明 |
|--------|--------|------|
| 2.1 端侧轻量模式 | P0 | INT8 RVC，离线运行，任何手机可跑 |
| 2.2 PC 串流高清模式 | P0 | RTX 5060 推理，实时回传高保真变声 |
| 2.3 音色实时切换 | P0 | 不重启流水线切换声线，无爆音 |
| 2.4 音高/音色/混响微调 | P1 | 类 Voicelab 的参数调节 |
| 2.5 流式分块处理 | P0 | 200ms 块 + 滑动窗口重叠，端到端 <200ms |
| 2.6 端到端延迟监控 | P1 | 实时显示延迟/掉帧，便于排查 |

**用户故事**
- 作为低端机用户，我希望不联网也能变声，以便地铁/无网环境可用。
- 作为主播，我希望连上 PC 后音质明显更真，以便打造专属声线。

**验收标准**
- Given 端侧模式 → When 天玑 6020 设备运行 → Then 端到端延迟 ≤150ms、连续 1h 耗电 ≤15%、不 OOM。
- Given PC 串流模式 → When 手机-PC 连接正常 → Then 端到端延迟 ≤200ms，断开后 1s 内自动降级端侧且不掉线。

**关键约束**：RVC 推理须 INT8 + 流式（参考行业基准 72ms 推理/端到端<100ms@888）；PC 端 8GB 显存限制并发与模型尺寸。

---

### M3 音色库与声音克隆（P0 预设 / P1 克隆）

**目标**：提供即开即用的音色，并支持用户真声克隆形成专属声线。

| 功能点 | 优先级 | 说明 |
|--------|--------|------|
| 3.1 内置预设音色库 | P0 | 百种：男女/卡通/影视/游戏角色，定期更新 |
| 3.2 用户声音克隆 | P1 | 基于 RVC 训练/导入（复用 voicebank） |
| 3.3 音色导入/导出/分享 | P2 | 模型文件管理、社区分享（远期） |
| 3.4 音色管理与切换 | P1 | 收藏/分类/一键切换 |
| 3.5 云端音色市场 | P2 | UGC 市场/抽成（远期） |

**用户故事**
- 作为新手，我希望打开就有百种声线，以便立刻玩起来。
- 作为主播，我希望用自己的声音训练专属音色，以便形成人设。

**验收标准**
- Given 首次启动 → When 进入音色库 → Then 至少 50 种可用预设（MVP 下限），无广告。
- Given 用户提供 ≥30s 清晰真声参考 → When 触发克隆 → Then 生成可用 RVC 音色，主观可辨识为同一人（远期量化 MOS≥4.0）。

**关键约束**：克隆涉及版权/隐私，须明确"仅限本人声音或已授权"；克隆模型体积须可控（目标 <100MB 便于分发）。

### M4 交互与控制（P0）

**目标**：游戏不打断前提下的极简控制。

| 功能点 | 优先级 | 说明 |
|--------|--------|------|
| 4.1 游戏悬浮窗 | P0 | 一键开关/切换声线，不切后台 |
| 4.2 物理/屏幕快捷键 | P1 | 映射按键触发音效/切换 |
| 4.3 新手引导与权限流 | P0 | 麦克风/悬浮窗权限分步申请 |
| 4.4 状态指示 | P1 | 当前音色/模式/延迟/电量可视化 |

**用户故事**
- 作为玩家，我希望游戏里点一下悬浮窗就换声线，以便开黑时随时整活。
- 作为小白，我希望有引导告诉我开哪些权限，以便一次配好。

**验收标准**
- Given 游戏中 → When 点击悬浮窗切换声线 → Then 切换 <0.5s 完成且游戏不中断、不掉线。
- Given 首次安装 → When 进入引导 → Then 权限申请成功率（用户授权后功能可用）≥95%。

**关键约束**：悬浮窗在部分 ROM（尤其 iOS/国内定制）受限，须有降级方案（通知栏/小组件）。

### M5 连接与传输（P0，高清模式依赖）

**目标**：手机与 PC 稳定低延迟串流，断连兜底。

| 功能点 | 优先级 | 说明 |
|--------|--------|------|
| 5.1 自动发现与配对 | P0 | 同网/WiFi/USB 发现 PC，一次性配对 |
| 5.2 低延迟音频串流 | P0 | 自研轻协议，音频块实时上/下行 |
| 5.3 弱网/断连降级 | P0 | 自动切端侧，无感过渡 |
| 5.4 传输加密与隐私 | P2 | 串流加密，防窃听 |

**用户故事**
- 作为用户，我希望手机自动连上我的 PC，以便一键用高清变声。
- 作为弱网用户，我希望 PC 断了也能继续变声，以便不掉链子。

**验收标准**
- Given 手机 PC 同网 → When 启动 → Then 30s 内完成发现配对。
- Given 串流中拔掉网络 → When 断连 → Then ≤1s 切换端侧模式，正在进行的通话不中断。

**关键约束**：本机存在 Clash/代理/TUN 等复杂路由，须支持指定网卡/直连，避免流量被劫持导致串流失败。

### M6 性能与功耗管理（P1）

**目标**：低端机长时间运行的稳定性与续航。

| 功能点 | 优先级 | 说明 |
|--------|--------|------|
| 6.1 动态精度/模型选择 | P1 | 按设备性能选 FP16/INT8/基础模式 |
| 6.2 低功耗模式 | P1 | 游戏场景降频保续航 |
| 6.3 发热监控与限频 | P1 | 超温自动降档保护 |
| 6.4 后台保活与会话管理 | P0 | 防系统杀进程导致掉线 |

**用户故事**
- 作为长局玩家，我希望变声 1 小时手机不烫不卡，以便正常游戏。
- 作为用户，我希望切到其他 App 再回来变声还在，以便不重连。

**验收标准**
- Given 低端机连续变声 1h → When 监测 → Then 机身温度 ≤42℃、不掉线、耗电 ≤15%（端侧）。
- Given 切换 App → When 返回 → Then 变声会话保持，无需重新配对/授权。

**关键约束**：后台保活与系统省电策略冲突，须引导用户加白名单/电池优化豁免。

## 4. 全局技术约束与依赖

- 变声核心：**RVC（非 TTS-LM）**，端侧 INT8 + 流式分块（200ms 块 + 滑动窗口）。
- PC 推理端：**RTX 5060 8GB**；同机复杂网络（Clash/TUN）需串流指定直连网卡。
- 目标硬件下限：天玑 6020 级别；更低机型自动降级基础模式。
- 声码器/特征提取须轻量（参考 TFLite + 轻量声码器方案），控制内存峰值 <500MB。
