# 实时变声链路延迟基准

- 档位：`balanced`（block_time = 250.0ms）
- 测量时间：2026-10-05 00:46:52

## ★ 口径声明（先读这一段）

端到端延迟是**三段之和**，不是单段：

```
端到端 = 分块缓冲 + 单块推理 + 驱动缓冲
```

| 段 | 值 | 来源 | 可靠性 |
|---|---|---|---|
| 分块缓冲 | 250.0ms | 档位配置 `block_time` 推算 | 高（配置值） |
| 单块推理 | 70.0ms | 实时日志实测（200 个样本，取中位数） | 高（真实日志） |
| 驱动缓冲 | 20.0ms | **标称值**（未探测真实驱动） | 低（纸面参数） |

**合计 p50 = 340.0ms**，p95 = 390.0ms。

单块推理本身：p50 70.0ms / p95 120.0ms / p99 1210.0ms。

## 与材料里的声称对账

- 声称值：`50ms`（申报书 / README）
- 结论：**inflated** —— 实测端到端 340ms 是声称 50ms 的 6.8× —— 声称的口径几乎肯定是「单块推理耗时」而非端到端，建议在材料里改写口径

## 怎么复核

```bash
# ① 只看配置可推算的部分（零依赖）
python tools/bench_latency.py --profile balanced

# ② 带上你机器上的实时日志，得到推理段的实测值
python tools/bench_latency.py --profile balanced \
    --log <logs/<exp>/realtime_gui.log>
```

★ 换机器测出来的数**必然不同**（GPU、CPU、驱动、后台负载都会变）。
本报告的价值不在那个数字本身，而在**口径被拆开、每一段都能追溯**。
