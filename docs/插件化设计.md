# 变声工坊 · 「一切皆插件」改造设计

> 2026-09-19 立项。灵感来自 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)
> 的 "everything is a plugin"（Cordis 内核：模型、工具、技能、会话、沙箱、存储、UI 全是插件）。
> 本文只写**这个仓库**怎么落地，以及**哪些收益是真的、哪些是幻觉**。
>
> 本轮已拍板：插件**内置但可关**，不做远程下载（见 §8）。

---

## 一、先把收益说清楚（否则会为一个假目标重构）

先纠正一个几乎所有人都会有的直觉：**插件化救不了安装包体积。**

2026-09-19 实测拆解 `VoiceMorph-Setup-0.2.3.exe`（101.5MB）：

| 组成 | 未压缩 | 说明 |
|---|---|---|
| `变声工坊.exe`（Electron 运行时） | 178MB | **安装包的主体**，压完仍占大头 |
| `locales/` + `icudtl.dat` + chromium dll | ~68MB | Electron 自带，砍不掉 |
| `resources/app.asar` | 47.1MB → **6.74MB** | 已修：见 §2 |
| `resources/backend/` | 16MB | 后端源码 + 前端 dist + tools |

结论：**把 `resources/backend/` 整个删掉，安装包也只小 10MB 量级。**
真正几个 GB 的东西（`tts_models` 4.9G / `models` 958M / RVC 整合包）**本来就不在安装包里** ——
它们是 `tools/setup_env.ps1` 在目标机器上现装的。

所以插件化的真实收益排序是：

1. **让 `setup_env.ps1` 从"一刀全装"变成"只装启用集"** ← 省的是 **几个 GB 的 Python 依赖与模型**，不是那 93MB 的 exe
2. **让没装/不用的能力不再污染界面与诊断**：关掉的插件不注册路由、不拉起 torch 上下文、`/api/diagnose` 不再对它报红
3. **失败隔离**：现在任意一个 router 模块 import 失败，整个后端起不来（§5.1），插件化顺手治掉
4. 前端按插件懒加载，主 chunk 从 778KB 降下来（当前构建警告已点名这个）

## 二、本轮已顺手修掉的打包事故

这两条**与插件化无关**，是查安装包体积时挖出来的真 bug，都已修 + 都有机器门禁
（`m2_server/tests/test_desktop_packaging.py`）：

| 事故 | 症状 | 根因 |
|---|---|---|
| **多塞 37.4MB** | app.asar 5305 个条目里 5236 个是 `node_modules` | electron-builder 会把 `dependencies` 整棵树拷进 asar，而 `files` 的**正向白名单管不住它**；vite 早已把前端库打进 `dist/`。主进程对第三方包的 require 数是 **0**。修法是 `build.files` 加 `"!node_modules/**/*"` |
| **漏发 4KB，静默退化** | 安装版缺 `m2_server/data/rvc_texts.txt` | m2_server 的 `extraResources.filter` 带 `"!**/data/**"`。该文件是**生产文件**（RVC 训练语料模板），`config.load_rvc_texts()` 有内置 20 句兜底 → **不报错**，只是把语料从 100+ 句场景句悄悄退回 20 句通用句 |
| **差点多塞 95MB** | `tools/desktop-control/out/`（87 张调试截图）会整体进包 | `tools/` 那条 `extraResources` **一条 filter 都没有** |

修完实测：app.asar **47.1MB → 6.74MB**（-85.7%），安装包 **101.5MB → 93.4MB**（-8.0%）。
`tools/` 的 filter 现在与 `tools/verify_backend_sync.py` 的 `_IGNORE_RULES` 对齐 —— **那边是唯一权威口径**，改一处要同步另一处。

## 三、现状清点：其实只差"注册"这一步

这个仓库已经是高度模块化的，缺的不是拆分，是**声明式注册**：

| 资产 | 数量 | 状态 |
|---|---|---|
| 后端路由注册 | **26 个模块** | 边界干净（按域拆好了）；`server.py` 的 `include_router` 仍是**硬编码**（2026-09-19 起改为 `_register()` 表驱动，步 1 已落地，见 §6.1）<br>（2026-09-20 复核：实际 **26** 个，README/本文早先写的 24 是旧数） |
| 前端页面 | **15 个页面目录** | `web/src/pages/<Name>/index.tsx`；`App.tsx` 里 **19 处 `<Route>`**（含 catch-all 与几处 `<Navigate>` 重定向）硬编码，且全在同一个 778KB chunk 里 |
| 能力可用性知识 | — | 只存在于 **README 的一张散文表**（"缺了会怎样"），机器读不到 |
| 下载/安装/续传/回滚 | — | **已有**：`market_download` + `market_install` |
| 健康探针 | — | **已有**：`/api/diagnose` + `tools/doctor.py` |

**关键判断：插件系统要造的不是"模块化"，是"清单 + 加载器 + 目录接口"。**

### 三.1 可直接复用的底座（别重造）

| 插件系统需要 | 仓库里已有的 | 复用方式 |
|---|---|---|
| 下载（域名白名单/断点续传/进度/互斥） | `market_download.DownloadManager` | 未来做远程插件时直接用 |
| 安装（落位/状态落盘/重启续装/失败回滚） | `market_install.InstallManager` | 同上；语义与"装音色"完全同构 |
| 能力体检 | `/api/diagnose`、`tools/doctor.py` | 逐项检查改为**由 manifest 驱动**，而不是硬编码清单 |
| 源→安装目录镜像 | `m2_server/backend_autosync.py` | 插件目录纳入镜像范围 |

## 四、插件边界怎么划：按「重可选依赖」而不是按代码目录

划分依据只有一条：**这个能力缺了会不会让用户装几个 GB 的东西 / 拉起一个重量级运行时。**
按代码目录划会切出 24 个碎插件（没意义），按依赖划才切出用户真正想选的东西。

### 4.1 内核（必装、随包、不可关）

| id | 覆盖的 router | 理由 |
|---|---|---|

## 五、Manifest：唯一真相源

`m2_server/plugins/<id>/plugin.json`（内置插件随包发；用户可关不可删）。

### 5.0 ✅ 已落地（2026-09-20）：19 份清单 + 只读 `GET /api/plugins`

实际落地的形状（与下面草案的差异都写在「落地时的四处修正」里）：
**19 个插件**（7 核心 + 12 可选）覆盖 **26 个 router** 与 **4 个启动钩子**，
加载/校验在 `m2_server/plugin_manifest.py`，门禁在 `m2_server/tests/test_plugin_manifest.py`（23 条）。

**落地时的四处修正**（都因为核了实际代码，而不是照草案抄）：

1. **状态文件不在 `%APPDATA%`，而在 `outputs/plugins.json`。**
   后端必须能脱离 Electron 独立跑（局域网/手机访问没有 appConfig），
   且 `cascade_state.json` / `live_asr_state.json` / `pet-skin-state.json` 本来就在 `outputs/`。
   键名用 **`disabled` 而不是 `enabled`**：新加的插件默认必须是开的，
   用白名单的话以后每加一个插件老用户都被默认排除。
2. **`disabled` 不算 `broken`**，而且被关掉的插件**仍然把原因算出来**。
   前端 `SetupBanner` 的弹出条件就是「有 broken」——两者混在一起会让
   “用户每关一个插件就吃一条降级告警”；而把 reasons 清空又会让设置页
   说不清“你关的，而且它本来就是坏的”。
3. **`health` 声明了但还没接线**：只有 `sound.tts → warmup.status` 与
   `hook.wechat → wechat_uia.status` 两个真探针（它们本来就存在），其余为 `null`。
   本步**不调用**它们（调用=行为变更），调用方与展示位置是第 6 步的事。
   门禁保证已声明的探针是**可调用的真属性**且返回 dict。
4. **`requires` 只做声明与校验（存在性 + 无环），不做状态传播**。
   所以“依赖的插件坏了”不会把依赖者也标成 broken —— 那是第 6 步关闭守卫的事。

**另一个必须记住的事实：插件内的 router 顺序不是排版**。
今天的真实注册顺序是**交叉的**（`sound.ft` 的 `finetune` 排第 2、而它的 `rvc_dataset_api` 排第 25；
`sound.audition` 与 `core.media` 同样被拆在两处），因为 `include_router` 的先后决定了
重叠路径由谁接。所以第 3 步改按清单挂载时**必须复原这个全序**，
两条门禁盯着它：`test_plugin_loader.py::test_router_registration_order_is_frozen`（全序）
与 `test_plugin_manifest.py::test_router_order_within_a_plugin_...`（插件内相对序）。

> **更正（2026-09-20，第 3 步实测）**：上面这段的**前提成立、结论不成立**。
> 「`include_router` 的先后决定重叠路径由谁接」是对的；但把当前路由表量一遍后发现
> **没有任何重叠路径** —— 26 个 router / 139 条真实路由，**0 条完全相同的
> `(method, path)`、0 条 router 之间的遮蔽**，65 条遮蔽关系**全部**是
> 「router vs SPA 兜底 `/{full_path:path}`」且全部「先注册、无害」，
> 低优先级路由 / websocket / Mount 均为 0。
>
> 也就是说这份「交错全序」**不承载任何信息**：把 26 个 router 按任意顺序挂载，
> 今天的行为完全一致。所以第 3 步**没有**复原全序，改成按清单 `order` 挂载
> （core 10-70 → sound 100-180 → pet 200-210 → hook 220，插件内按 `routers` 声明序），
> 实测迁移前后路由表逐条一致（139 条、0 重叠、0 死路由）。
>
> 上面那两条门禁也随之替换：`test_router_registration_order_is_frozen` →
> `test_plugin_loader.py::test_mount_order_follows_the_manifest`（挂载顺序 = 清单顺序），
> 而原来想守的那件事换成一条**真正的**断言 ——
> `tests/test_route_shadowing.py::test_no_router_route_shadows_another`：
> **不许出现两条互相遮蔽的 router 路由**（含「参数路由吃静态路由」这种字符串不同、
> 但请求会撞车的情况）。它绿 = 顺序对行为没有影响；它红 = 出现了真需要人判断的取舍，
> 由它点名是哪两条路径、属于哪个插件。比冻结一份没人解释得清的历史顺序管用。

**为什么 manifest 值得做**：现在这些知识**散在四处且会漂移** ——
README 的"缺了会怎样"表、`tools/doctor.py` 的检查清单、`/api/diagnose` 的实现、
前端各页自己写的"未就绪"提示。变成 manifest 后，这四处**全部由一份声明驱动**。

| 消费方 | 读 manifest 的哪部分 |
|---|---|
| `server.py` (loader) | `routers`、`requires` |
| `tools/setup_env.ps1` | `extras.python`（按启用集装） |
| `/api/diagnose`、`tools/doctor.py` | `extras.external`、`extras.models`、`health` |
| `App.tsx` / 侧边栏 | `routes`、`order`、`category` |
| 设置页「能力管理」 | 全部（渲染开关 + 依赖提示 + 体积提示） |

## 六、运行时语义

### 6.1 Loader（`m2_server/plugin_loader.py`）—— ✅ 已落地（2026-09-19）

第 1 步做的是**只含失败隔离**的最小版本，不涉及 manifest / 开关：

```python
# 已经能用（m2_server/plugin_loader.py + server.py 的 _register）
router = plugin_loader.load_router("rvc_live")   # 失败 → None，并记入 registry
if router is not None:
    app.include_router(router)

plugin_loader.call_hook("warmup", "start_background")   # 可选启动钩子，失败静默跳过
print(plugin_loader.report(_ROUTER_ORDER))              # 启动横幅：26/26 或逐条原因
```

两个设计决定值得记住：

- **记账粒度是 `(模块, 用途)` 而不是模块**：`audio_api` 既提供 `router` 又提供
  启动钩子，共用一个 key 的话 router 成功会把钩子失败静静盖掉。
- **只吞 `Exception`，不吞 `BaseException`**：吞掉后者会让启动期的 Ctrl+C 失灵，
  比导入失败更难查。

待第 2 步（manifest）进来后再叠加 `requires` 拓扑与启用状态，
本轮**没有**动 `plugins.json`。

### 6.2 ✅ 已修：一个 import 失败 = 整个后端起不来（2026-09-19）

`server.py` 原先有 **26 处模块级 `from xxx import router`**。
任一处失败（缺 torch / 缺权重 / 缺可选依赖 / 一个笔误）→ `server.py` 直接
`ImportError` → **整个后端无法启动**，前端只看到一个空界面，
而真原因根本没机会被报出来。

已改为 `_register(...)` 表驱动 + `plugin_loader` 容错加载。
实测对照（用一个假装是 `seed_vc` 的坏模块抢占 `sys.path`，在子进程里 `import server`）：

| | returncode | 输出 |
|---|---|---|
| 改写前 | **1** | `RuntimeError: 模拟：这台机器没装 Seed-VC 的依赖`（直接抛出） |
| 改写后 | **0** | `路由模块 25/26 个已加载` + `不可用: seed_vc —— RuntimeError: …` |

两个约束被写进了门禁（`m2_server/tests/test_plugin_loader.py`）：

1. **注册顺序被冻结** —— FastAPI 按注册顺序匹配路由，重排是**行为变更**，不是排版；
2. **容错不能变成静默** —— 坏掉的模块必须在启动横幅里点名 + 给原因，
   否则这次容错只是把“崩溃”换成了“静默”，反而更难查。

> 一个**新引入的风险**要盯住：钩子从 `from x import y` 变成了字符串 `("x", "y")`，
> **拼错不再报错，只会静默不生效**。所以每个钩子都有一条把名字钉在真属性上的用例。

### 6.3 状态与接口

**✅ 已落地的过渡形态（2026-09-19）：`GET /api/capabilities`**

插件系统还没到，但「哪个能力没挂上」这件事不能等 —— 步 1 的容错只把结果写进了 `backend.log`，
而**用户不读日志**。所以先加一个只读端点作为过渡，不依赖 manifest：

```json
{ "ok": true, "loaded": 25, "total": 26,
  "broken": [{ "module": "seed_vc", "use": "router", "error": "RuntimeError: 缺少依赖" }] }
```

两个刻意的选择：

1. **不塞进 `/api/health`**。`health` 的实现里有模块级 `import torch`，重依赖崩掉时它自己就返回不了 ——
   而那正是最需要这条提示的时刻。**状态端点不能依赖它要报告的那个东西。**
2. **前端复用已有的 `SetupBanner`**，不新造组件。缺模型与「能力没挂上」对用户是同一类信号
   （界面里某块功能是哑的），两类原因共用一条横幅、一个 dismiss；叠两条横幅反而让人以为出了两个问题。

正式形态（步 2 之后）：

- 状态文件：`%APPDATA%/变声工坊/plugins.json`（与 `appConfig` 同一处，避免两套配置）
- `GET /api/plugins` → 目录：每个插件的 manifest + `state`（`ok`/`broken`/`disabled`）+ 健康探针结果 + 依赖关系
- `POST /api/plugins/{id}/enable|disable` → 校验依赖守卫后写状态；**重启生效**（不做热插拔，见 §9）
- 关闭守卫：若仍有启用的插件 `requires` 目标 → 409，并在 `detail` 里列出依赖者

### 6.4 与 `m2_server` 是平铺模块的兼容性

`m2_server/` 不是 Python 包（没有 `__init__.py`，靠 `cwd=m2_server` + `sys.path` 平铺 import）。
所以 loader 用 `importlib.import_module("rvc_live")` 即可，**但前提是 `m2_server` 在 `sys.path` 里**
（`server.py` 以 `cwd=m2_server` 启动，成立）。这条前提要写进 loader 的注释 —— 换个启动方式就会全体 ImportError。

## 七、前端：路由与侧边栏改由 `/api/plugins` 驱动

现状：`App.tsx` 里 **18 条** `<Route>` 硬编码（8 条真页面 + 8 条仅重定向 + 2 条兜底），
全部打进同一个 **778KB** 主 chunk（构建已警告）。

目标：

```tsx
// 1) vite 的 glob 给出"路径 → 懒加载组件"的静态映射
//    （Vite 不能动态 import 任意路径，glob 是官方推荐姿势）
const PAGES = import.meta.glob("./pages/*/index.tsx");

// 2) 路由与侧边栏都由 /api/plugins 渲染
const { data: plugins } = usePlugins();
const routes = plugins.flatMap((p) => p.routes).filter((r) => p.state !== "disabled");
```

> ⚠️ **2026-09-20 复核发现这套写法不能直接用**，两处：
>
> **① 现有页面全是具名导出，零 default export。** 实测 8 个真页面一律是 `<目录名>Route`
> （`Home/index.tsx` → `HomeRoute`、`Tts/index.tsx` → `TtsRoute`…，`grep -l "export default"` = **0**）。
> 而 `import.meta.glob` 拿到的模块对象**没有默认导出可取**。两条路：manifest 里显式写
> `{ "path": "/live", "module": "Live", "export": "LiveRoute" }`，或靠 `<目录名>Route` 这个
> 既定约定推算。**建议显式写** —— 约定会漂，而代价只是 manifest 多一个字段
> （统一改成 default export 也行，但那要动全部 8 个页面文件）。
>
> **② 页面目录 ≠ 路由；`glob` 匹配数 ≠ 路由数。**
>
> > **更正（2026-09-20 二次复核）**：本框原先写「`pages/` 15 个目录，只有 **14 个是路由**，
> > glob 恰好只匹配那 14 个」—— **两个数都错**，按下面这份账为准（`ls` + `grep '<Route'` 可复现）。
>
> 精确账：
>
> - `web/src/pages/` **15 个目录**，其中 **14 个有 `index.tsx`**（`SeedVc` 没有）。
> - `App.tsx` **18 条 `<Route>`**，分三类：
>   - **8 条渲染真页面**：`/home` `/workshop` `/voices` `/live` `/audition` `/tts` `/offlinevc` `/pet-market`
>   - **8 条仅重定向**（旧路由，指向合并页的 tab）：`/discover` `/ft` `/market` `/qwen` `/cascade` `/audiobook` `/wechat` `/effects`
>   - **2 条兜底**：`/` 与 `*` → `/home`
> - 那 8 条真页面路由，**与 19 份清单里 8 个插件声明的 `routes` 逐条一致** ——
>   `core.system` `/home`、`core.voices` `/voices`、`pet.market` `/pet-market`、`sound.audition` `/audition`、
>   `sound.offline-vc` `/offlinevc`、`sound.rvc-live` `/live`、`sound.tts` `/tts`、`sound.workshop` `/workshop`。
>   **清单是对的**，错的是本框的说明。
> - **14 个 `index.tsx` 里有 6 个根本不是路由**，它们是被别的页当 tab 消费的（`grep -rl "pages/<目录>"` 实测）：
>   `Audiobook`→`Tts`、`Cascade`→`Live`、`Discover`→`Workshop`、`Effects`→`OfflineVc`、
>   `Ft`→`Workshop`、`VoiceMarket`→`Voices`；再加 `SeedVc`→`OfflineVc` 的子标签（`SeedVcPage` + `useSeedVc`，无 `index.tsx`）。
> - ⚠️ **所以 `import.meta.glob("./pages/*/index.tsx")` 会多匹配 6 个非路由页面（14 匹配 vs 8 真路由）** ——
>   它**不是**「恰好只匹配路由」。必须**由 manifest 的 `routes` 白名单去筛**，不能拿 glob 的结果直接生成路由，
>   否则会凭空多出 `/audiobook`、`/cascade`、`/discover`… 这些早已改成 tab 的页面（它们各自还有一条重定向路由，
>   一旦被注册成真页面，重定向就会被顶掉）。
> - 结论不变且更强：manifest 的 `routes` **必须由路由生成**，一个目录 ≠ 一个插件页。

收益：
- 主 chunk 只含内核页面，每个插件页单独成 chunk（**关掉的插件连 chunk 都不加载**）
- 侧边栏不再需要在每个页面里手写"未就绪"提示 —— 不可用的插件直接不出现/置灰，原因由 `state` 给出
- 新增一个能力 = 加一份 manifest + 一个页面文件，**不用动 `App.tsx`**

### 7.1 ★ 先清点「有哪些面在调后端」，别只改主应用（2026-09-20 的教训）

## 十、明确不做（本轮）

- ❌ **远程下载插件**：已拍板内置；且要先解决签名/版本兼容/离线安装/失败回滚，不是本轮的量级
- ❌ **第三方插件 SDK / 插件市场**：先内部用满半年，边界稳了再开放
- ❌ **热插拔**：关一个插件会改变后端路由表与前端 chunk，热切换是状态一致性的泥潭；**重启生效**
- ❌ **拆 `m2_server` 成真正的 Python 包**：目录布局动了会牵动 `backend_autosync` / `sync_backend.ps1` /
  `verify_backend_sync.py` / 打包 filter 四条链路，收益不抵风险。loader 用平铺 import 即可（§6.4）
- ❌ **把插件系统做成"能装任意 Python 代码"**：那是安全红线的反面（本项目 `0.0.0.0 + 无 token` 的默认就够危险了）
