# A4 多链路对比评测 · 落地说明

> 对应 `docs/功能完善建议-2026-09-05.md` 的 A4。
> 解决"同一段输入到底走 RVC / Seed-VC / Qwen3 哪条链路更像"，把靠人耳挑变成可量化决策。

## 做了什么

| 层 | 文件 | 内容 |
|---|---|---|
| 后端 | `m2_server/ab_chain.py` | `POST /api/ab/chain`：上传一段源声 + 选一个目标音色，串行跑三条链路并打分 |
| 前端 | `web/src/components/voice-studio/AbChainCard.tsx` | 三栏并排试听 + 客观分 + 主观投票同屏 |
| 前端 | `web/src/pages/Voices/VoicesPage.tsx` | 音色库页在 A/B 盲听卡下方挂载（≥1 个音色即可用） |
| 测试 | `m2_server/tests/test_ab_chain.py` | 8 条：三链路成功 / 无文本跳过 / 单链路失败隔离 / 互斥 / GPU 占用 / 参数校验 / 权重缺失 |

## 接口

```
POST /api/ab/chain   multipart: file(音频) + voice_id + text(选填)
→ { ok, target_voice_id, text,
    chains: { rvc|seed_vc|qwen3: { status, url, error, metrics:{secs,nats,duration_s} } } }
```

- **任一条链路失败不拖垮整体**：该链路 `status=failed` + 可读原因，其余照常返回。
- **无 text → Qwen3 `skipped`**（TTS 链路必须有文本，不硬造）。
- **GPU 互斥**：实时变声 / 级联 / 离线变声在跑，或已有对比任务在跑 → 409。
- 同步端点（FastAPI 放线程池），整轮 RVC+Seed-VC+打分约 1–3 分钟。

## 两把客观尺子

| 指标 | 含义 | 来源 |
|---|---|---|
| `secs` | 输出 vs 目标音色参考音的 **CAM++ 声纹余弦相似度**，0~1，越高越像 | `speaker_sep._sv_embed`（与主链路同一套） |
| `nats` | **自然度**评分，越高越自然，可为负 | NatScore 本地权重 `models/natscore/final.pt`（whisper-small 编码器 + 偏好头） |

前端分档：secs ≥0.85 很像 / ≥0.75 比较像 / ≥0.62 一般 / ≥0.5 偏弱 / else 不像；
nats ≥3.4 自然 / ≥3.0 尚可 / ≥2.6 略生硬 / else 生硬。

## 主观与客观同屏

卡片底部可投"听感最好"的一票，投完直接给出结论：

- 一致 → 提示"可以定为默认链路"；
- 不一致 → 提示**以听感为准**，并说明 secs 只衡量声纹接近度，抓不住咬字和节奏。

这是刻意的：袋鼠音色 A/B 试了 8 轮的教训就是客观分高不等于听着像，工具只负责把两方摆在一起。

## 已知边界

- RVC 链路要求目标音色**已训练**（有可推理 pth），否则该链路 failed 并提示；Seed-VC 是零样本，无需训练。
- NatScore 权重缺失时打分环节报"NatScore 权重缺失"，不阻塞对比（该链路 metrics=null）。
- 三条链路串行共用 GPU，不做并行——8GB 显存下并行必 OOM。
