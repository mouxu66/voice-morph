# 方案 · 微信全局托管（`/autopilot`）

> 用户拍板（2026-10-24）：「增加全局管理功能，即用户把所有权限交给他，让他自己滑动微信，
> 寻找聊天记录并自动回复。」
> AskUserQuestion 四项决策：**文本消息** / **指定会话白名单** / **只回提问和 @我** /
> **每次启动重新开启**。

## 1. 与旧约束的关系（先读这段）

项目里此前有两条硬口径：`assistant_api` 的「一切发送先出提案再等确认」与
`chat_radar` / `chat_read` 的「只看屏幕不发消息」。本功能**不是推翻它们，而是划出例外**：

- 例外只在 `hook.wechat` 的托管页、且用户**每次启动都要重新勾选授权**后成立；
- 例外只覆盖**文字消息**，且只发给**用户亲手挑进白名单**的会话；
- 其余一切（语音、文件、图片、红包、转账、链接、提案流、雷达只读）**不受影响**；
- `chat_read` 仍然只读；托管读消息复用它的 UIA 快照，但发送走独立的 `wechat_text`。

## 2. 能力边界

做：

- 轮询左侧会话列表 → 找出白名单里有未读的会话；
- 后台切过去（`SelectionItemPattern.Select()`）读最近消息；
- 判断该不该回（见下方 8 条硬校验）；
- 用本机 Qwen3-VL-4B（llama-server）写**一条** ≤30 字短句；
- 写进输入框并点「发送」，然后把会话切回用户原来那个。

不做：

- 不发语音 / 文件 / 图片 / 红包 / 转账 / 链接；
- 不点「+」面板、不改用户已打的草稿（草稿非空直接拒绝发送）；
- 不翻聊天历史（`history_pages=0`；翻页要抢前台滚轮，默认关）；
- 不碰 `wechat_voice` 的语音发送链路；
- 模型写不出合格短句就**不发**，绝不退回模板复读。

## 3. 技术路线（全部 2026-10-24 实测）

| 环节 | 手段 | 关键事实 |
|---|---|---|
| 切会话 | `wechat_text.select_session` | 会话列表 `ListControl Name="会话"` 的 ListItem 支持后台 `Select()`；用输入框 `Name` 反查确认切成功了 |
| 写文字 | `ValuePattern.SetValue` → 等按钮 enabled → `InvokePattern.Invoke` | 发送按钮 `ButtonControl Name="发送"`，输入为空时 `IsEnabled=False`，正好当「SetValue 生效了吗」的判据 |
| 回退路径 | `_foreground_wechat()` + `SendInput` 逐字 Unicode → Invoke | Qt 不吃 SetValue 时用；**不用剪贴板**（不污染用户剪贴板） |
| 谁发的 | `radar_api.peek_side()` | 消息 ListItem 没有发送方信息；左右只能由像素雷达的 `layout.last_chat.side` 判定 |
| 写回复 | `reply_advisor.suggest_one()` | 复用已接好的本地 4B；严格 JSON 校验，失败返回 None |
| 显存 | `_free_vram_mb()` 预检 | 余量 < 2048MB（`VM_AUTOPILOT_MIN_FREE_VRAM_MB` 可覆盖）→ 本跳过生成，不跳过整轮 |

## 4. 硬校验清单（缺一条都不发）

1. 会话在**白名单**里；
2. 有未读（`unread > 0`）；
3. 免打扰会话跳过（`skip_muted`，默认开）；
4. 不在静默时段（默认 `[23, 7)`，支持跨零点；两值相同 = 不启用）；
5. 距上次回复 ≥ `min_gap_s`（默认 45s），每小时每会话 ≤ 3 条；
6. 最后一条必须 `kind=="text"` **且** `side=="left"`（对方发的文字）；
7. 提问或 @我（`question_only`）；群聊额外要求**必须 @我**；
8. 指纹（会话 + 未读条数 + 最后一条原文）30 分钟内不重复处理。

熔断：连续 3 次失败（微信被关 / UIA 挂 / 模型崩）自动停机；
单轮最多发 `max_per_run=20` 条；日志 `outputs/autopilot_log.jsonl` 超 512KB 轮转。

## 5. 接口与页面

`autopilot_api.py`（`prefix=/api/autopilot`，**整份 router 级 loopback-only**）：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/state` | 状态 + 配置 + 最近日志 + 微信/模型健康 |
| GET | `/sessions` | 会话列表（含 `muted` / `pinned` / 是否白名单/群聊） |
| PUT | `/config` | 保存配置；**运行中 409** |
| POST | `/start` | 必须 `consent=true`，否则 403；白名单空 → 400 |
| POST | `/pause` `/resume` `/stop` | 暂停 / 继续 / 急停 |
| POST | `/test-send` | 只发「文件传输助手」，验证整条链路 |

启动必须显式 `consent`（后端 403 兜底，前端勾选框只是先手）；
配置只能在停止状态改，避免「跑到一半规则被换掉」。

前端：`web/src/pages/Autopilot/`（`AutopilotPage.tsx` + `useAutopilot.ts`），
挂到 `hook.wechat` 的 `routes`（`/autopilot`，桌面组，图标 `Bot`）。
**不新建插件**：新建插件在 `outputs/plugins.json` 里默认启用，会复活用户已关掉的
微信能力；托管本来就属于微信链路。

### 5.1 入口：桌宠建议区第 4 条（2026-10-24 增，当天的报障直接产物）

侧栏入口**不够**：极简模式下 `StudioNav` 只常显「开始 / 变声」两组，其余组折叠成
一行标题 —— 「桌面」组里的「全局托管」在默认状态下根本不可见。首版交付后用户的
原话是「重启之后仍然没有做按钮啊，全部功能都开了」。

所以桌宠面板（`web/electron/pet/pet.html`）的建议区加了**固定第 4 条**「托管」：

- 它**不进** `rankActions()` 的兜底池。那个池子只有 3 格、按「此刻该做什么」排序，
  「该回了 / 正在放歌 / 有提案」任一信号都能把入口挤掉 —— 而它恰恰是「第一次用，
  不知道去哪开」时唯一的入口。它由 `refreshRecs()` 无条件追加，位置永远不变；
- 输入框有字时（搜索态）不追加：那时用户要的是「哪个功能对得上」，固定项会白占一格；
- 点了走 `window.pet.openPage("/autopilot")` → 主进程 `pet:open-page` → show/focus
  主窗口 + 改 `location.hash`（前端是 hash 路由）。主进程只放行 `^/[A-Za-z0-9/_-]*$`，
  因为该串会被拼进 `executeJavaScript`；
- 搜索「托管 / 自动回复 / 全局 / 挂机」也能直接搜到它（`ACT_META` 的 `kw`）。

⚠️ 高度是真的紧：面板 `max-height: 300px`，最挤的 `picked` 形态原来只剩 28px。
为了放下第 4 条，建议条从 26px/gap4 压到 24px/gap3（4 条=105px，+19px），
`tools/pet-panel-layout-budget.json` 已按门禁流程重算基线（最紧 `picked` 余量 9px）。
以后往这个面板加东西，先跑 `node tools/test-pet-panel-layout.cjs --fast`。

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| 发错人 / 发错会话 | 只认白名单；切完用输入框 `Name` 反查；发送前后 `expect_chat` 校验 |
| 冲掉用户草稿 | 发送前读输入框，非空即拒（用户可能正在打字） |
| 半夜替用户回话 | 静默时段 + 每小时上限 + 最小间隔，三重叠加 |
| 群里乱接话 | 群聊必须 @我；昵称留空则群聊永不触发 |
| 模型胡言乱语 | 严格 JSON + ≤30 字 + 拦截「建议你 / 你可以回」旁白；不合格宁可不发 |
| 与实时变声抢显存 | 生成前预检余量，<2GB 跳过生成 |
| 同网段他人开启 | router 级 loopback 依赖（`_require_loopback`） |
| 关了微信还在跑 | 连续 3 次失败熔断停机 |
| 用户忘了它在跑 | 页面常驻状态条 + 日志；急停按钮一键 `stop` |

## 7. 验证步骤

1. `pytest m2_server/tests/test_chat_autopilot.py test_wechat_text.py test_autopilot_api.py test_radar_peek.py`
   —— 策略矩阵 / 发送守卫 / loopback / consent 全覆盖（已进 `check.py --fast`）；
2. `npx vitest run src/pages/Autopilot` —— 白名单增删、群聊标记、开始门控；
3. 真机：微信打开 → 页面「发送测试」→ 去「文件传输助手」看是否收到；
   若 Qt 不吃 `SetValue`，日志里 `method` 会显示 `typing`（回退路径生效）；
4. 部署：`sync_backend.ps1 -TargetRoot <安装目录>` + `cd web && npm run ship`，
   再 `python tools/verify_backend_sync.py`。**入口改到了桌宠**，所以 `pet.html` /
   `preload.cjs` 要单独拷进安装目录的 `resources/backend/web/electron/pet/`，
   `main.cjs`（`pet:open-page`）必须**重打 app.asar**（见 AGENTS.md 定向重打流程）；
   最后 `node tools/audit_asar_freshness.cjs` + `node tools/test-pet-panel-layout.cjs --fast`。

## 8. 已知限制

- 消息列表没有发送方信息，**左右判定依赖像素雷达**（雷达没跑或窗口被挡 → 不发，
  偏保守）；
- 只能读到**当前可见**的消息（不滚动），上下文可能只有最近几条；
- 不识别语音内容（语音消息一律跳过，不猜）；
- 微信更新可能改控件类名（`mmui::ChatInputField` / `mmui::XOutlineButton`），
  `wechat_text` 里两处常量是唯一定义点。
