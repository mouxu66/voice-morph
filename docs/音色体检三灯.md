# 音色体检「三灯」

> **现役**。与当前实现一致，看到不对就该改它。
> 代码：`tools/voice_metrics.py`（测量）、`tools/voice_report.py`（分档合成）、
> `tools/voice_qc.py`（CLI 与落盘）、`m2_server/clips_api.py`（`GET /voice/lamps`、`POST /voice/lamps/scan`）、
> `web/src/components/voice-studio/VoiceLamps.tsx`（UI）。
> 门禁：`m2_server/tests/test_voice_report.py`、`web/src/components/voice-studio/VoiceLamps.test.tsx`。

一句话：把已经攒着的内部质检件（CAM++ 声纹 / 切片打分 / 变声验收）合成**三个灯**，
让「这份音色的质量」第一次在界面上可见 —— **而且训练前就能给预期**。

---

## 1. 为什么做

用户最痛的一句话是「训练完才知道音色不行」。现有的质检件问题不在能力，在**可见性**：
它们全是内部工具（`tools/clip_qc.py`、`tools/voice_qc.py`、A-B 盲听页），用户看不到。

所以三灯解决的**不是**「测得准不准」，而是「**训练前**就能知道这份素材行不行」。

## 2. 三个灯与数据来源

| 灯 | 指标 | 阈值口径 | 训练前可用？ |
|---|---|---|---|
| **相似度** | CAM++ 声纹余弦（变声输出 vs 目标音色参考） | ≥0.95（沿用 `voice_qc.py` 现役判据） | ❌ 要等变声验收 |
| **自然度** | HNR（谐噪比，**浊音帧中位数**） | 中位数分布 P25/P5 | ✅ 只需音频 |
| **夹嗓子风险** | H1-H2（主判）+ 谱倾斜（印证） | 中位数分布 P25/P5 | ✅ 只需音频 |

「训练前可用」是**刻意支持**的用法 —— 这正是这个功能最值钱的地方（见 §5）。

夹嗓子灯**取两者中更危险的那个档位**，不做平均：两个量测的是同一现象的不同侧面
（谱包络陡度），平均会把危险抹平。任一缺失则只用另一个；两个都缺 = 未测。

### 2.1 与 `voice_qc.py` 的分工（别合并）

| | `tools/voice_qc.py` | 本功能 |
|---|---|---|
| 定位 | **入库验收** | **用户可见的体检** |
| 输出 | 4 指标 ×25 分 = 100 分制 PASS/FAIL | 三个灯 + 一句话结论 |
| 落盘 | `outputs/qc/<exp>.json` | 同左（**不改 score/pass 语义**） |

`rvc_live` 回调依赖 `voice_qc.py` 的 score/pass。三灯的数据挂在同一份 JSON 的
**新增键**（`voice.lamps` / `vocal_preview`）上，**不进 items、不进 score** ——
所以 100 分制口径没被动过。两个东西服务不同目的，硬合并会让验收口径被 UI 需求带偏。

## 3. 阈值来自实测分布，不是文献数字

2026-09-29 在**干净训练集全部 73 条自录切片**（`video_260828_110637_*` +
`video_260828_105338_*`，即 `AGENTS.md` 袋鼠音色铁律里唯一认可的素材）上跑出真实指标。

★ **关键：灯的输入是「20 条采样的中位数」，不是单条值。**
所以阈值必须锚在**中位数的分布**上，否则会犯一个很隐蔽的错：

> 拿**单条**分布（h1_h2 P75=5.16）去判**中位数**（实测 4.8）→ 误亮红灯。

### 3.1 Bootstrap 标定（每次抽 20 条取中位数 ×2000 次）

```
HNR      P5=11.09  P25=11.39  P50=11.68  P75=11.91  P95=12.11
H1-H2    P5= 2.99  P25= 3.44  P50= 3.78  P75= 4.33  P95= 4.92
tilt     P5=-7.66  P25=-7.39  P50=-7.25  P75=-7.11  P95=-6.88
```

分档规则：**黄档 = 越过 P25（好的一侧），红档 = 越过 P5。**

即「这份素材与你自己其余素材比，是否明显偏差」—— **不是与某个绝对标准比**。

### 3.2 谱倾斜的方向坑（踩过一次，别再踩）

tilt 的「好」一侧是**数值更大**（更接近 0，谱滚降更缓），所以：

```python
"tilt": {"green": -7.39, "yellow": -7.66, "higher_better": True},   # ✅
"tilt": {"green": -7.39, "yellow": -7.66, "higher_better": False},  # ❌ 灯整个反掉
```

写错时 `-7.0`（更健康）判成红、`-8.0`（更挤压）判成绿。
**与上面三个指标的 green/yellow 语义不同向**，改之前先读 `voice_report.py` 该行注释。

### 3.3 H1-H2 的方向与调研文档相反（以实测为准）

- 调研文档 `调研-SVC路线与嗓音客观指标-2026-09-28.md` §4.2 的通用表述：**越挤压 → H1-H2 越低**。
- **本机合成信号实测**：按谐波斜率做标定，`-2dB→2.31`、`-6dB→6.31`、`-12dB→12.31`、`-18dB→18.31`
  —— 完全线性，且**越大 = 滚降越陡 = 越挤压**。

**结论以实测为准**（更大的值 = 更危险）。文档字符串里已标注这处冲突，
不要因为"文档那么写"就把它改回去。

## 4. 没测到 ≠ 不合格（最重要的一条不变量）

`parselmouth` 缺失、音频没有足够浊音段、还没跑变声验收 —— 这些都产出
`lamp = None`（**未测**），**不是红灯**。

理由：把它们显示成红灯，用户会去修一个不存在的问题。

UI 侧对应 `VoiceLamps.tsx` 的三态：`green` / `yellow` / `red` / **`untested`（灰）**；
`data == null` → 整块显示「未体检」。判词侧 `verdict()` **跳过未测的灯** ——
不能因为测不了就说「没问题」。

## 5. 已实现的用法

```bash
# ① 单一音色体检（轻量：不做转写，只算声学指标）
python tools/voice_qc.py --vocal-preview <音色名>

# ② 训练前样本体检（跑 run_dataset 时自动附带，取 20 条采样）
python tools/voice_qc.py --dataset <目录>
```

后端两个端点（`sound.workshop` 插件路由内）：

- `GET  /voice/lamps?voice=<id>` —— **只读**，从 `outputs/qc/<voice>.json` 取，不触发任何计算。
- `POST /voice/lamps/scan` —— 当场对指定音色/数据集跑一次采样体检（`async`，走 `_VOCAL_SAMPLE_MAX = 20`）。

## 6. 已知偏差（不假装它是通用的）

### 6.1 ★ 基线是「这批素材」的，换人换麦就会偏

这批 73 条自录切片是**同一个人、同一支麦克风**。所以阈值实际表达的是
「与你自己的其余素材比」。

当前阶段可接受（**单用户、单音色主场景**）。要跨用户推广，得改成
**「与该用户自己的历史基线比」**，即：首次体检后把该用户第一批素材的中位数
存成个人基线，之后都相对它判档 —— 而不是套用袋鼠这批数字。

这是**推广前必须做的一件事**，不是优化项。

### 6.2 CPP（倒频谱峰突出度）**被刻意砍掉**

调研文档 §4.2 把 CPP 列为嗓音质量的主流指标之一，本项目**没有实现它**，
理由是实测不过关：

1. **Praat 的 `Get CPPS` 调不通。** `parselmouth.praat.call` 的参数签名探不出来
   （连续 13 次尝试，一直卡在 `right Peak search pitch range` 这类报错上）。
2. **两个自实现版本都不成立。**
   - 版本 A（峰值 − 低分位均值）：正弦 1.68 / 噪声 0.59 —— 量级偏低（正常应 10–16 dB），
     且区分度可疑。
   - 版本 B（峰值 − 自 1ms 起线性回归趋势线）：正弦 0.65 / 噪声 0.59 —— **区分度直接消失**。
3. **根因**：窗函数泄漏在倒频谱 index 0 处造出一个 2.05 的巨大直流尖峰，
   真正的周期峰（6.7ms 处）没被抬起来。

**结论：宁可少一个灯的数据，也不要一个量级错误、跨样本不可比的假指标。**
本文件就是这处决策的现场记录 —— 想加回 CPP，先把上面三条各自解决掉。

### 6.3 HNR 曾经算错（负数），已修

`To Harmonicity (cc)` 返回范围是 **-200 ~ +27 dB**，其中 **-200 是「非浊音帧」哨兵**。
早期版本对整个范围取均值 → HNR = -33 ~ -99 dB（物理上不可能）。

修正：只取浊音帧（F0 mask），**并掉 < -100 的哨兵值**，再取中位数 → 13.28 dB（正确）。
`test_voice_report.py::TestHnrNotFloorAveraged` 钉住这条。
