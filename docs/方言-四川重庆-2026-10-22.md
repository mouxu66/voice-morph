# 方言路线（四川 / 重庆）：2026-10-22 转向

> 前一版是 `docs/潮汕话-起步-2026-10-21.md`。用户不是潮汕母语者，那份方案的死结是
> 「正字没人校、可懂度没人判、素材扒不到」。改做四川/重庆方言后，这三个死结同时消失。
> 本文只写转向后**还需要重新验证**的东西，不重复潮汕那份的通用工程结论。

## 0. 一句话

四川话是**西南官话**，用汉字写，不存在「音频说 A、文本写 B」的错位。所以潮汕那份文档里
最贵的三件事——正字标注、拼音 G2P、翻译层——**整条都不需要**。剩下的只有一个问题：
让 TTS 用你的声音说四川话。

## 1. 为什么难度差一个量级

| 维度 | 潮汕话 | 四川话 |
|---|---|---|
| 文字系统 | 正字不通用，自造字带普通话先验 | **同一套汉字**（巴适/啥子/耍/莫得） |
| 文本↔语音 | 一个字最多 4 读，8 声调，需拼音 | 与普通话对应规则强，直接写汉字 |
| 翻译层 | 必须（普通话→正字） | **不需要** |
| 标注 | 正字 + 拼音人工标 | 说啥写啥，零标注 |
| 评测 | 必须有潮汕母语者 | **你自己就是** |
| 数据量 | 基线 18.9h | VoxCPM2 官方称 **5–10 分钟**可 LoRA 适配 |
| 现成权重 | 检索未见公开 TTS | **至少 3 个模型原生支持** |

## 2. 现成能力盘点（2026-10-22 核过）

| 模型 | 四川话 | 许可 | 规模 | 备注 |
|---|---|---|---|---|
| **Qwen3-TTS-1.7B-CustomVoice** | ✅ 音色 `Eric`（成都男声） | 随仓库 | 1.7B | 项目已在用同系列 Base，切换成本最低 |
| **VoxCPM2**（OpenBMB） | ✅ 9 种方言含四川话 | Apache-2.0 | 2B | 48kHz 输出，官方称 8GB 显存可跑，支持 LoRA |
| **Ming-3.0-tts**（蚂蚁 inclusionAI） | ✅ 四川话 | MIT | 0.5B dense / 7.9B-A1.3B MoE | 100+ 内置音色，14 种副语言标签 |

本机现状（已确认）：

- `tts_models/qwen3-tts-1.7b-base` 是 **Base** 变体，`codec_language_id` 只有 10 种语言、
  `spk_id` 与 `spk_is_dialect` 都是空字典 → **它不会按标签说四川话**，只能靠零样本克隆带口音。
- GPU 为 RTX 5060 8GB：1.7B bf16 约占 3.4GB，够跑；VoxCPM2 2B 官方口径 8GB 可跑但余量小。

**一个必须记的差异**：`Eric` 是**成都**男声。重庆话与成都话同属西南官话但调值与词汇有别
（重庆话无入声归派差异、儿化与语气词不同）。若目标是重庆口音，借 `Eric` 只能当"大方向对不对"
的粗测，不能当验收。VoxCPM2 只标"四川话"，实际覆盖到哪一片未声明，同样要实测。

## 3. 三条路，按成本排

| 路 | 做法 | 成本 | 得到什么 |
|---|---|---|---|
| **A** 借现成方言音色 | 下 `Qwen3-TTS-1.7B-CustomVoice`，`speaker=Eric` | 约 4GB 下载 | 立刻听到成都男声，**但不是你的声音** |
| **B** 零样本克隆你的四川话 | 你录 20–40 秒 + 写下原话，用本地 Base 克隆 | 一次录音 | **你的音色 + 你的口音**，当天可听 |
| **C** LoRA 微调 | 录 10–30 分钟你的四川话 | 半天 | 长句、多音字、语气词最稳 |

**B 是这次转向真正的红利。** 在潮汕方案里，"我的音色"要靠 RVC 从别人的音频转过来，
跨语言失真只能硬扛（§9.3 实测 0.64–0.67）。现在你自己就能说四川话，
**录音同时解决音色和口音两件事，RVC 整条可以从链路里去掉。**

C 不是可选项的对立面：B 若长句飘、腔调不稳，直接拿同一批录音上 LoRA，数据不用重录。

## 4. 怎么判"成不成"（你自己就能判，不用求人）

同一批 8 句固定在 `tts_trial/dialect_probe.py` 的 `TEXTS` 里，方言词密度从低到高。
每条都问三个问题，分开打分，别合并：

1. **是不是四川话**——关掉字幕听，能听出口音就是过；听着像普通话带调就是没过
2. **是不是你**——盲听对比你自己的录音
3. **字对不对**——有没有吞字、多音字念错（"还" hái/hán、"要" yào/yāo 这类）

客观辅助两项：

- `CAM++` 声纹余弦（像不像你），项目里 `m2_server/speaker_sep.py` 现成
- ASR 回环（可懂度粗筛）：合成音频 → whisper 转写 → 比对输入文本；字错率高说明发音糊

## 5. 今天的动作

**只差一样东西：一段你自己的四川话录音。**

- 时长 20–40 秒，安静环境，手机录即可
- 两段更好：① 自然口语（像跟朋友聊天）② 带方言词（巴适 / 啥子 / 耍 / 莫得 / 啷个）
- **必须同时把说的话逐字写下来**——零样本克隆要用 `ref_text`，写错会直接毁掉韵律
- 放哪都行，告诉我路径即可（建议 `media/voicebank/sichuan/`）

拿到后跑：

```bash
python -u tts_trial/dialect_probe.py \
    --ref-audio "media/voicebank/sichuan/ref01.wav" \
    --ref-text "这里放逐字原话" --tag sichuan01
```

同一条命令换普通话参考音、换 `--tag`，就是对照组。

## 6. 预期管理

- 零样本最常见的结果是**音色像、腔调不够**，长句尤其容易滑回普通话。滑了就上 LoRA，不是路线错
- 8GB 显存跑 1.7B 有余量，但同时开 llama-server（Ornith-9B，ngl=99）会抢显存，测前先关
- 四川话 TTS 开源权重虽然多，**"你的音色 + 纯正重庆口音"这个组合没有现成答案**，
  仍要自己训——只是数据量从小时级降到分钟级

## 7. 环境坑：TTS 环境在 8 月之后被升坏了（已修）

跑探针时撞到的，记下来省下次：

**现象**：`venv312/` 里 `transformers==5.16.1`，导入 `qwen_tts` 直接
`TypeError: check_model_inputs() missing 1 required positional argument: 'func'`。
仓库内嵌的 `Qwen3-TTS/pyproject.toml` 锁的是 **`transformers==4.57.3`**，
而 5.x 把 `check_model_inputs` 从「工厂装饰器」改成了「直接装饰器」，
`@check_model_inputs()` 的老写法就炸了。另 `\.venv`（4.46.3）又缺
`ALL_ATTENTION_FUNCTIONS`，两头都不对。

**为什么不直接降级 venv312**：它还被别的脚本用着，全局降级风险大。

**修法**：把 4.57.3 装在**仓库外**，脚本里只给自己加 path。

```bash
PY=tts_trial/venv312/Scripts/python.exe
$PY -m pip install "transformers==4.57.3" --target D:/tts_vendor/tf4573 --no-deps --upgrade
$PY -m pip install "tokenizers==0.22.2"   --target D:/tts_vendor/tf4573 --no-deps --upgrade
$PY -m pip install "huggingface-hub<1.0"  --target D:/tts_vendor/tf4573 --no-deps --upgrade
```

三个都要，缺一个就再报下一个 ImportError（4.57.3 要求 `tokenizers<=0.23.0` 且
`huggingface-hub<1.0`，而 venv312 里分别是 0.23.2 与 1.30.0）。

放在 `D:/tts_vendor/` 而不是仓库内，是为了不把整个 transformers 塞进 git、污染
licenses/ownership 门禁。

**验证**（2026-10-22 08:19 实测通过）：

```
模型就绪 3.7s / 音色向量已建 / s01 3.76s 用时 9.2s
→ media/dialect_probe/smoke_mandarin/
```

注意这次冒烟用的是**普通话**参考音（`tts_models/ref/meituan_rat_002.wav`），
只证明管线通，**不证明口音能迁移**——那要等你的四川话录音。

## 8. 第一轮实测：内置成都话男声跑通了（2026-10-22 08:41）

用户没空录音，所以先做**不需要他参与**的那部分：用 CustomVoice 检查点自带的成都话音色
把"开源模型说四川话到底行不行"验证掉。这样等他的录音到位时，手里已经有一条可对照的基线。

### 8.1 权重与配置

从 ModelScope 直链下载 `Qwen/Qwen3-TTS-12Hz-1.7B-CustomVoice`，3.84GB
（`model.safetensors` 3833MB + 若干小文件）。`speech_tokenizer/` 直接复用 base 的那份，
省掉 682MB 重复下载。

`config.json` 里核到的关键字段（这是"它到底会不会方言"的唯一证据）：

```
spk_is_dialect:  eric = sichuan_dialect      dylan = beijing_dialect      其余 = False
codec_language_id:  sichuan_dialect = 2062   beijing_dialect = 2074      chinese = 2055
```

也就是说 `eric` 不是"带四川口音的普通话音色"，而是走独立语言 id 的方言分支。
对照 base 检查点：`spk_id = {}`、`spk_is_dialect = {}` —— 这就是 base 不能按标签说方言的原因。

### 8.2 生成结果（同一批 8 句，两个音色）

| | eric（成都话） | uncle_fu（普通话） |
|---|---|---|
| 总时长 | **25.04s** | **31.12s** |
| 逐句 | 2.56 2.64 2.72 3.28 3.68 2.96 3.92 3.28 | 4.16 4.48 3.44 3.20 3.12 4.56 4.48 3.68 |
| 单句耗时 | 5.9–8.8s（首句 22.8s 含预热） | 8.8–12.8s |
| whisper-small CER | **21.2%** | **9.6%** |

同一段文字，成都话比普通话**短 19.5%**。两种解释都成立：方言本身更紧凑，
或者吞了字。**这一条必须靠耳朵判，不能靠时长定罪。**

CER 差 2.2 倍，说明模型确实换了一套音系，不是只换音色。逐句看：

- `s01 今天天气巴适得很` → 普通话 0%，成都话 33.3%（ASR 听成"八十的很…耍一下"）
  —— "巴适"被念成 bā shí，这是真方言读音，ASR 按普通话字面还原不了
- `s04 你在爪子哦，啷个半天不回消息` → 两组都是 46.2%，ASR 对这句两边都崩
- `s07 他昨天在屋头耍了一整天` → 成都话把"没做"听成"没煮"，12.5%

### 8.3 两个方法学坑（都踩了，记下来）

**坑一：whisper 在 `language=zh` 下默认吐繁体。** 不转简体，CER 会被虚高十几个点。
`asr_eval.py` 的文件头已经写过这条，我这次还是先踩了一遍：s03 未转换时 27.3%，
用 `zhconv.convert(text, "zh-cn")` 归一后是 **0.0%**。以后所有 CER 必须先转简体。

**坑二：whisper-small 在真实重庆话上完全不能用。** 拿 `BV16h4y1w7Mu`
（乡音计划《重庆话入门100句》）跑了一遍，输出是这样的：

```
一 你好 二 大家好 三 写写 不用写 不存在 开启了
十 多谢 不好意思 五 小时写 不存在 落
```

「谢谢——不用谢，没关系」被转成「写写 不用写 不存在」。也就是说
**"ASR 回环"这条路只能当合成音频的相对粗筛，不能用于真实方言语音的评测**，
更不能用来给方言录音做标注。要真做方言 ASR，得换更大的模型或专门的方言 ASR。

### 8.4 顺带确认：重庆话那份视频也是同一个坑

`BV16h4y1w7Mu` 抽帧看过，是和潮汕那份同一个 UP 主（语言狂魔Mark）的系列：
只有普通话课件页（"1.你好 2.大家好 3.谢谢——不用谢 4.对不起 5.没关系…"），
没有重庆话正字，页脚同样写"版权所有 侵权必究"。
所以它和潮汕那批素材结论一致：**只能当探针音源，不能当语料。**

### 8.5 下一步（等录音，或继续自己跑）

## 9. 用项目已有音色说四川话：能，但有 0.21 的音色代价（2026-10-22 12:35）

用户问「能不能用我项目里的那些音色」。答案是能，但**只有 RVC 一条路**，
而且代价比同语言转换明显。本节把三条候选路都过了一遍，两条被代码否掉。

### 9.1 一条看起来最优、实际被 API 否掉的路

`qwen_tts/core/models/modeling_qwen3_tts.py:2113-2122` 里，`language` 参数是
**直接查 `codec_language_id`** 的：

```python
if language.lower() not in self.config.talker_config.codec_language_id:
    raise NotImplementedError(f"Language {language} not implemented")
else:
    language_id = self.config.talker_config.codec_language_id[language.lower()]
```

而 CustomVoice 检查点里 `sichuan_dialect = 2062` 确实存在
（实测 `可用语言` 含 `beijing_dialect / sichuan_dialect`）。

**推论本该是**：把 `language="sichuan_dialect"` 配上任意参考音做零样本克隆，
就能得到「任意音色 + 四川音系」，一步到位、不需要 RVC。

**实测否掉**：`create_voice_clone_prompt` 在 `tts_model_type: custom_voice`
上直接抛

```
ValueError: model with tokenizer_type: qwen3_tts_tokenizer_12hz
tts_model_size: 1b7 / tts_model_type: custom_voice
does not support create_voice_clone_prompt
```

也就是说**零样本克隆被 API 层锁在 Base 检查点上**，而 Base 的
`codec_language_id` 不含 `sichuan_dialect`（§8.1 已核）。
两者不可兼得 —— 这条「最优路」在现有权重下不成立。
探测脚本留在 `tts_trial/clone_dialect_test.py`，可复现，不生成音频。

### 9.2 RVC 是唯一现成路径

源 = `eric` 生成的 8 句成都话（§8.2），目标 = `myvoice_ppt12_full`
（`/d/RVC/assets/weights/`），`offline_vc_infer.py`，seed 1234，pitch −12。

| 句 | 文本 | CAM++ 像不像我 |
|---|---|---|
| s01 | 今天天气巴适得很，我们出去耍一哈 | 0.6368 |
| s02 | 你吃饭没得？没吃的话我们一起 | 0.6358 |
| s03 | 这个事情我晓得，你放心嘛 | 0.6773 |
| s04 | 你在爪子哦，啷个半天不回消息 | 0.6548 |
| s05 | 莫得事，慢慢来，不着急 | 0.5650 |
| s06 | 这个东西有点贵，但是味道确实安逸 | 0.6841 |
| s07 | 他昨天在屋头耍了一整天，啥子都没做 | 0.6168 |
| s08 | 要得，那就这么说定了，明天见 | 0.5800 |
| **均值** | | **0.6313** |

**参照音必须统一，否则分数不可比。** 第一次用
`media/voicebank/myvoice_supp2026/reference.wav` 当参照得 0.54–0.57，
换成历史基线所用的 `media/ft_work/ppt12/ref_24k.wav` 后同一条音频变 0.6368。
同一批产物、同一个模型，仅因参照音不同差了 0.07。以后所有音色分一律用
`ref_24k.wav`。

对齐参照音后的标尺：

| 条件 | CAM++ |
|---|---|
| 同语言真人音频 → 我的音色（`out_real.wav`） | **0.9197** |
| 同语言普通话 TTS → 我的音色（`out_tts01.wav`） | **0.8460** |
| 成都话 eric → 我的音色（pitch −12） | **0.6313** |
| 源头 eric 未转换（应接近 0） | 0.0673 |

**差 0.21。** 这次变量比潮汕那次干净得多：同一音色包、同一推理脚本、
同为汉语男声、源同为 TTS 合成 —— 唯一变的是**口音 + 基频**。

### 9.3 pitch 不是调参，是硬约束

`eric` 的 f0 中位数 **211.4Hz**（p10 145.2 / p90 275.7），
而我的参照 `ref_24k.wav` 是 **113Hz** —— 差约 11 个半音，接近一个八度。

pitch 扫描（s01 单句，CAM++）：

| pitch | 0 | −2 | −12 | +12 |
|---|---|---|---|---|
| CAM++ | 0.5801 | 0.5815 | **0.6368** | 0.3656 |

降八度后实测 f0 中位数 **106.9Hz**（p10 85.1 / p90 116.6），与参照 113Hz 对齐。
即：**这里必须 −12，且 −12 只是把音高拉回目标区间，不是"更好听的调节"。**

### 9.4 0.21 的差距归因（三条，未拆干净）

1. **降一个八度的音高变换本身有损伤** —— RVC 在 -12 档的相位重建质量低于
   0 / ±2 档，这是架构层面代价，不是参数没调好
2. **源是 TTS 合成**（对比的 `out_tts01` 也是 TTS，此项已对齐，不算差异来源）
3. **口音差异** —— 理论影响最小，因为 RVC 只换音色不改音素；
   但入声/儿化/鼻化韵这些四川话特有音段在目标模型的训练分布里没有，
   HuBERT 特征可能落在他没见过的区域

**结论性判断：主因是第 1 条（降八度），不是「跨方言」本身。**
证据：pitch 0 时 0.5801、−12 时 0.6368，同一段音频仅改 pitch 就动了 0.057；
而整轮方言转换相对同语言只掉 0.21 —— 降调能解释其中相当一部分。

### 9.5 项目内音色基频对照（决定谁适合当 RVC 目标）

| 音色 | f0 中位数 | 与 eric(211Hz) 的半音差 | RVC 需要的 pitch |
|---|---|---|---|
| `myvoice_supp2026` | 113.3Hz | −11 | −12 |
| `kangaroo` | 128.6Hz | −9 | −9 ~ −12 |
| `aishell3_ssb0407` | 175.2Hz | −3 | −3 ~ −4 |
| `eric`（源） | 211.4Hz | 0 | 0 |

**规律：目标基频越接近源，RVC 代价越小。** 现在项目里所有「我自己的音色」
都在 113–129Hz，跟 eric 差 9–11 个半音，落在最不利的一档。
`aishell3_ssb0407` 只差 3 个半音，但它是公开语料音色、且 `/d/RVC/logs/` 下
没有对应训练目录，不能直接当目标。

### 9.6 三条改进方向（按代价排序）

1. **换低音四川话源**：找 130–160Hz 的四川话男声（讲古/评书类基本是低音男声）
   当 RVC 源，把降调幅度从 −12 压到 −4 以内。这是**不改架构、不改模型、
   只换一个输入**的最小改动，最该先做。
2. **VoxCPM2（OpenBMB，Apache-2.0，2B，约 8GB）**：支持 zero-shot 克隆，
   官方方言列表含四川话，但**没有显式 `dialect` 参数**，只能靠
   「括号指令 + 方言文本」隐式引导，且官方自述结果会波动、需 1–3 次重生成。
   它绕开 RVC 的关键在于：能直接用 113Hz 的参考音，不存在降八度问题。
3. **固化路线**：用 eric 生成一批四川话 → RVC 到我的音色 → 拿这批数据
   QLoRA 微调 Base 模型（`tts_trial/sft_8gb.py` 现成）。
   代价是继承 RVC 的失真，好处是推理时不再需要跑 RVC，链路变成单模型。

## 10. 「带电音」诊断：参数全无效，根因在生成阶段（2026-10-22 12:58）

用户听完 §9 的 8 条说「带电音」。把 RVC 侧能调的旋钮全扫了一遍，
结论是**一个都动不了它**，问题不在 RVC。

### 10.1 先量化「电音」

主观词拆成三个可测量：

| 指标 | 含义 | 电音方向 |
|---|---|---|
| `flux` 谱通量 | 帧间频谱跳变量 | 越高越有金属/毛刺感 |
| `flat` 谱平坦度 | 频谱有多「像噪声」 | 越高越沙 |
| `semi` 半音抖动 | f0 相邻帧差（半音） | 越低越像 autotune |
| `floor` 静音段 RMS | 底噪 | 越高越嘶 |

**关键方法论修正**：第一版用 Hz 绝对差算 f0 抖动，得到「降八度把抖动压平 61%」的结论 ——
那是假的，f0 减半则 Hz 差自然减半。改用 `12*log2(f[i+1]/f[i])` 后，
实际只掉 24%。**以后所有音高抖动一律用半音单位。**

对齐后的标尺（同参照音 `ref_24k.wav`）：

| | flux | floor | semi |
|---|---|---|---|
| 方言 → 我的音色（现状） | **61.02** | **0.0134** | 1.224 |
| 同语言 TTS → 我的音色 | 48.49 | 0.0001 | 1.121 |
| 同语言真人 → 我的音色 | 45.30 | 0.0015 | 1.044 |
| 同语言输入源（未转换） | 18.08 | 0.0000 | 0.944 |

**flux 高 26%，floor 高 9–134 倍。** 这两项才是「电音」。

### 10.2 `protect` 在这个管线里是死参数（字节级证据）

`infer/vc/pipeline.py:175` 写的是 `if protect < 0.5 and pitch is not None and pitchf is not None`。
按说 0.33 该生效、0.5 不该生效，两者输出应该不同。实测：

```
e4384f2dc5f0ed552e4ca09f384c2b10  base_p33_ir50_lp11k.wav
e4384f2dc5f0ed552e4ca09f384c2b10  p50.wav
e4384f2dc5f0ed552e4ca09f384c2b10  p70.wav
```

**md5 完全相同。** 三档 protect 产出字节级一致的音频 —— 这个分支在此配置下从未进入。
以后别再拿 protect 当调音旋钮。

### 10.3 其余旋钮全扫，最大变化 0.0007

s01，pitch −12：

| 配置 | flat | hf | semi | flux |
|---|---|---|---|---|
| base（ir0.5 lp11k） | 0.00548 | 0.0097 | 1.224 | 61.02 |
| ir0.30 | 0.00565 | 0.0104 | 1.239 | 61.07 |
| ir0.75 | 0.00557 | 0.0091 | 1.139 | 61.07 |
| lp8k | 0.00519 | 0.0090 | 1.218 | 61.02 |
| lp16k | 0.00543 | 0.0097 | 1.224 | 61.02 |
| pitch 0 | 0.00482 | 0.0123 | **1.668** | **66.61** |
| pitch −6 | 0.00480 | 0.0100 | 1.643 | 65.03 |

- `index_rate` / `lowpass`：flux 全在 61.0–61.1，**改不动**
- `f0_method`（fcpe/pm）：semi 更差（6.12/6.72 相对 rmvpe 7.03 的 Hz 口径），已弃
- **降调越少，semi 越好（1.224 → 1.668），但 flux 反而更高（61 → 66.6）**

也就是说：**flux 是 RVC 声码器的固有产物，与参数、与降调幅度都无关。**

### 10.4 根因：8 句里 3 句生成就有底噪，两极分化

| 句 | 源 floor | 源 SNR | →RVC SNR |
|---|---|---|---|
| s01 | 0.01375 | **12.3dB** | 12.9 |
| s02 | 0.01511 | **16.2dB** | 19.3 |
| s03 | 0.00301 | 31.5dB | 25.7 |
| s04 | 0.00003 | **72.7dB** | 55.2 |
| s05 | 0.00002 | **71.3dB** | 56.2 |
| s06 | 0.01636 | **14.9dB** | 10.2 |
| s07 | 0.00179 | 36.8dB | 32.9 |
| s08 | 0.00003 | **70.0dB** | 55.2 |

**同一模型、同一批、同样参数，SNR 跨 12–73dB。** s01 的底噪是 s05 的 687 倍。

噪声频谱不是低频嗡嗡，而是集中在 **6–11kHz（占 37%）** 的嘶嘶声 ——
而 `POST_LOWPASS_HZ = 11000` 根本没切到这一段。

RVC 只是把底噪放大 3–10 倍，源头在 Qwen3-TTS 的方言分支（`language_id 2062`）。

### 10.5 贪心解码只救一半，还会跑飞

s01 单句扫 seed：seed1–4 的 SNR 17.6/18.3/32.7/20.6dB，
`do_sample=False` 是 **76.2dB** —— 看起来是解药。但 8 句全跑：

| 句 | 采样 SNR | 贪心 SNR | |
|---|---|---|---|
| s01 | 12.3 | 25.0 | 改善 |
| s02 | 16.2 | 26.2 | 改善 |
| s03 | 31.5 | 73.2 | 大幅改善 |
| s04 | 72.7 | 76.1 | 略好 |
| s05 | 71.3 | 76.9 | 略好 |
| s06 | 14.9 | 12.7 | 没救 |
| s07 | 36.8 | 29.4 | 变差 |
| s08 | 70.0 | **0.9（60.00s）** | **跑飞** |

**单句推出来的结论在 8 句上不成立**（这次又是样本量 1 的教训）。
贪心在 s08 上陷入重复循环，生成 60 秒废音频。
`dialect_probe.py` 已加 `--greedy` 开关，但**不能当默认**。

### 10.6 降噪反而加重电音

`highpass=100, afftdn=nf=-25, lowpass=8000` 处理源，SNR 确实升（s01 15.4→25.7dB），
但 RVC 之后：

| 句 | flux 原 / 降噪后 | semi 原 / 降噪后 |
|---|---|---|
| s01 | 61.02 / **61.93** | 1.224 / **0.600** |
| s04 | 50.40 / 47.79 | 1.577 / 1.712 |
| s06 | 58.70 / 58.26 | 1.071 / 1.008 |

flux 没降（s01 反而升），**s01 的 semi 从 1.224 掉到 0.600 —— 音高抖动被谱减削掉一半，更电音。**
降噪不是解药，对 s01/s06 这类脏样本是负收益。

### 10.7 结论

1. **「带电音」不是 RVC 参数问题，也不是降八度问题。** 20 个配置扫下来，flux 稳在 61 附近。
2. **根因是 Qwen3-TTS 方言分支的生成质量不稳**：8 句里 3 句 SNR 12–16dB，噪声在 6–11kHz。
3. **参数级、后处理级的招都用完了，没有一条能把 flux 从 61 压到同语言的 48。**
4. 剩下的路只有换生成模型或自己训：
   - VoxCPM2（Apache-2.0，2B，8GB，官方方言列表含四川话，支持 zero-shot）
   - Ming-3.0-tts（蚂蚁，MIT，0.5B，原生四川话）
   - 或用本人 20–40 秒四川话训 LoRA，彻底不经过 eric
